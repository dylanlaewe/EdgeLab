# M0.3A retained content and reducer contract v1

## Status and boundary

This contract closes the retained event-content vocabulary for runtime format
2 and specifies the pure reducer that may be implemented next. It supplements
`M0.3A_SUCCESSOR_RUNTIME_FORMAT.v1.md` and supersedes that document only where
this contract makes a narrower decision explicit. It does **not** implement a
writer, database open, migration, selector cutover, recovery, external anchor,
R-gate, scheduler release, or authority-bearing action.

M0.3A remains unaccepted. `STOP-M0-001` and `STOP-M0-3A-001` remain open,
H-M0-041 remains blocked, live remains `LOCKED`, the kill switch remains
`ENGAGED`, and deployable capital remains USD 0.

The published verifier result vocabulary remains version 1 with only
`INVALID` and `UNSUPPORTED`. A later verifier may introduce a separately
versioned `LOCALLY_CONSISTENT_DENY_ONLY` result only after the reducer and full
runtime-image contract exist. No local result establishes authenticity or
authorization.

## 1. Exact retained schema bundle

`schemas/m0-3a-schema-registry.v2.json` is the only runtime-format-2 content
registry. Its digest is computed with the `schema_registry` domain. It contains
exactly these nine documents and roles:

| Role | Schema |
| --- | --- |
| `EVENT_ENVELOPE` | `urn:edgelab:m0-3a-event-envelope:2` |
| `PAYLOAD` | `urn:edgelab:m0-3a-event-payload:2` |
| `TASK_STATE` | `urn:edgelab:m0-3a-task-state:2` |
| `REQUEST` | `urn:edgelab:m0-3a-command-request:2` |
| `RESPONSE_PROJECTION` | `urn:edgelab:m0-3a-response-projection:2` |
| `CHECKPOINT_DOCUMENT` | `urn:edgelab:m0-3a-runtime-checkpoint:2` |
| `EXPORT_DOCUMENT` | `urn:edgelab:m0-3a-runtime-export:2` |
| `LEGACY_ROW_ARCHIVE` | `urn:edgelab:m0-3a-legacy-v1-row-archive:1` |
| `LEGACY_PROJECTION` | `urn:edgelab:m0-3a-legacy-v1-projection:1` |

Documents are sorted by `schema_id`; event bindings are sorted by
`event_type`. IDs, roles, document digests, and the 25-event inventory are
exact and unique. Registry generation is reproducible with
`tools/build_runtime_v2_schema_registry.py`; generated output drift denies.

Only the exact compiled-in bundle is supported. The verifier accepts no remote
or file resolution, nested `$id`, anchors, dynamic or recursive references,
vocabulary overrides, unknown documents, dangling references, or reference
cycles. References are local `#/$defs/<name>` references only. Each document is
canonical JSON, at most 262,144 bytes, and the whole registry/document bundle
is at most 2,097,152 bytes. The registry is at most 262,144 bytes. The verifier
emits at most 128 unique findings in sorted order; finding artifacts are at
most 256 characters and coordinates at most 512 characters, with oversized
values replaced by a deterministic SHA-256-suffixed prefix.

## 2. Digest additions

The shared codec additionally defines:

```text
attachment = SHA256("EDGELAB\0ATTACHMENT\0V2\0" || canonical(attachment))
export = SHA256("EDGELAB\0EXPORT\0V2\0" || canonical(export_without_export_sha256))
remediation_link = SHA256("EDGELAB\0REMEDIATION_LINK\0V2\0" || canonical(link_without_link_sha256))
```

Checkpoint documents retain the checkpoint domain and their separately stored
blob retains the blob domain. Export documents do the same with the export and
blob domains. Digest fields are not interchangeable across domains.

## 3. Closed command request and response

Every command request binds the runtime and chain IDs, exact operation key,
repository generation and bundle digest, subject, expected state reference,
and closed operation arguments. The 22 operations are:

`SYSTEM_GENESIS`, `SYSTEM_LEGACY_BRIDGE`, `INITIALIZE`, `CLAIM`, `START`,
`CONTINUE`, `YIELD`, `FAIL`, `COMPLETE`, `RECOVER`, `RETRY`,
`GOVERNANCE_BLOCK`, `REVALIDATE`, `ASSIGN_REVIEW`, `APPROVE`, `REJECT`,
`REMEDIATE`, `ROUTE`, `CREATE_REMEDIATION_TASK`, `IMPORT_REPOSITORY`,
`CHECKPOINT`, and `EXPORT_SNAPSHOT`.

Generated IDs are lowercase UUIDv4 strings. Task IDs and identities are bounded
ASCII strings. All persisted integers are strict signed-64-bit integers;
booleans do not satisfy integer fields. Commands carrying progress, yield,
failure, completion, recovery, retry, governance, review, remediation, or
routing decisions carry an explicit evidence digest. `COMPLETE.close` is an
explicit boolean and is never inferred.

The response projection is closed and contains operation identity, `COMMITTED`,
affected state references, and generated references. It excludes event IDs,
event digests, and the final global head. Those self-derived return fields may
be reconstructed only after the committed event group is known; they are not
part of `response_sha256`. This removes the response/event hash cycle.

System/checkpoint/export responses have zero affected states; ordinary single-
task operations have exactly one after-state; remediation has source then child;
and import has the sorted affected after-states. Claim, review assignment,
remediation, checkpoint, and export have exactly one generated ref of the
matching kind; all other operations have none. Claim/review refs have null
digests; link/checkpoint/export refs carry their domain digest. Identifiers,
state refs, and digests exactly equal the corresponding payload and reduced
effects.

The two system requests do not contain `manifest_sha256`. Their payloads bind
formats 2/2, the attachment, storage descriptor, schema registry, current
verifier dependency closure, and initial repository coordinates directly. A
bridge additionally binds every legacy manifest coordinate and exact-role
archive/projection refs. The manifest is constructed only after the genesis or
bridge event digest exists and therefore cannot be request or payload input to
that event.

Non-system operation keys have the normalized form
`v2:<the 64-hex chain_id>:<1..180 printable non-space ASCII caller key>`; the
entire normalized key is at most 256 characters. Only the two system keys are
outside that namespace. Schema validation checks the form; the reducer checks
that the embedded chain ID equals the request/event runtime chain.

## 4. Transaction grammar and validation order

The pure reducer consumes a complete candidate runtime image. It never reads a
database, filesystem, clock, network, environment, current checkout, or
authority service. It accepts no callbacks. Validation order is:

1. Enforce host types and resource limits before parsing.
2. Parse exact canonical JSON and verify the pinned storage descriptor and
   schema bundle.
3. Verify runtime, chain, repository, attachment, manifest, and genesis/bridge
   identities.
4. Verify global event sequence, predecessor IDs/digests, event digests, task
   sequence and task-attempt predecessor roots.
5. Partition events into contiguous transaction groups and validate the exact
   request, response, payload, and state schema roles.
6. Apply each whole group to a fresh immutable reducer state. A rejected group
   has no effect.
7. Derive all materialized tables, table roots, metadata heads, snapshots, and
   reachable blobs from accepted groups.
8. Compare every supplied materialization byte-for-byte with the derivation.

All events in one transaction have one transaction ID, operation key, request
digest, response digest, repository binding, event count, and identical
canonical UTC-second timestamp. Positions are zero through `event_count-1` and
global sequences are contiguous. Normal commands have one or more semantic
events followed by exactly one `COMMAND_COMMITTED`. Genesis and legacy bridge
are the only single-event exceptions and use the reserved operation keys.

The commit payload lists semantic event IDs in position order and binds the
pre-command head, post-semantic head, operation, operation key, request and
response blob references, and `COMMITTED`. Idempotency `committed_at` equals the
group timestamp. A repeated operation key with the same request resolves to the
same derived response; a different request is invalid. Orphans, partial groups,
extra commit events, reordered events, mixed timestamps, or overlapping groups
are invalid.

The exact semantic-event grammar is:

| Request operation | Semantic events before commit | `event_count` |
| --- | --- | --- |
| `SYSTEM_GENESIS` | `RUNTIME_GENESIS` only; no commit | 1 |
| `SYSTEM_LEGACY_BRIDGE` | `LEGACY_V1_BRIDGE` only; no commit | 1 |
| `INITIALIZE` | `TASK_INITIALIZED` | 2 |
| `CLAIM` | `CLAIM_ISSUED` | 2 |
| `START` | `TASK_STARTED` | 2 |
| `CONTINUE` | `TASK_CONTINUED` | 2 |
| `YIELD` | `TASK_YIELDED` | 2 |
| `FAIL` | `TASK_FAILED` | 2 |
| `COMPLETE` | `TASK_COMPLETED` | 2 |
| `RECOVER` | `CLAIM_RECOVERED` | 2 |
| `RETRY` | `TASK_RETRIED` | 2 |
| `GOVERNANCE_BLOCK` | `GOVERNANCE_BLOCKED` | 2 |
| `REVALIDATE` | `GOVERNANCE_REVALIDATED` | 2 |
| `ASSIGN_REVIEW` | `REVIEW_ASSIGNED` | 2 |
| `APPROVE` | `REVIEW_APPROVED` | 2 |
| `REJECT` | `REVIEW_REJECTED` | 2 |
| `REMEDIATE` | `REVIEW_REMEDIATED` | 2 |
| `ROUTE` | `DIRECTOR_ROUTED` | 2 |
| `CREATE_REMEDIATION_TASK` | source `REMEDIATION_CREATED`, then child `TASK_CREATED_FROM_REMEDIATION` | 3 |
| `IMPORT_REPOSITORY` | zero to 10,000 `REPOSITORY_GENERATION_APPLIED` events in ascending task ID, then `REPOSITORY_GENERATION_ADVANCED` | affected count + 2 |
| `CHECKPOINT` | `RUNTIME_CHECKPOINTED` | 2 |
| `EXPORT_SNAPSHOT` | `RUNTIME_SNAPSHOT_EXPORTED` | 2 |

`event_count` is at most 10,002 and position at most 10,001. Accounted input is
at most 1,073,741,824 bytes and contains at most 100,000 events, 100,000 tasks,
and 300,000 blobs. An envelope is at most
1,048,576 bytes and an individual blob at most 16,777,216 bytes. Limits are
checked before semantic reduction. Changing any limit requires a contract
version; until the reducer exists, nonempty events and blobs remain unsupported.

Accounted input bytes are the exact sum, counting every field occurrence once
even when byte-identical: raw byte lengths of storage descriptor, manifest,
attachment, registry, every schema document body, every blob body, every event,
checkpoint, selector-history document, and legacy-evidence body; UTF-8 byte
lengths of every schema-document/blob ID and digest and every legacy-evidence
key; plus the canonical JSON byte length of each table snapshot encoded as
`{"table":<name>,"rows":<array-of-row-arrays>}`. Empty fields contribute zero.
Container/object overhead is not counted. Non-JSON snapshot values invalidate
the image before accounting.

For every group, envelope `event_type` equals payload `event_type`; request,
response, commit payload, and event group have equal operation and operation
key; request, response, and every envelope have equal runtime ID and chain ID;
repository coordinates are equal as defined below; commit request/response refs
use the exact request/response schema IDs; payload/state refs use the registry
roles; and every digest equals the referenced canonical bytes. Commit semantic
IDs equal the preceding semantic event IDs in position order.

For ordinary single-task commands (`CLAIM`, `START`, `CONTINUE`, `YIELD`,
`FAIL`, `COMPLETE`, `RECOVER`, `GOVERNANCE_BLOCK`, `REVALIDATE`,
`ASSIGN_REVIEW`, `APPROVE`, `REJECT`, `REMEDIATE`, and `ROUTE`), request subject,
before/after states, and semantic-event task context all name the same current
task and attempt; `expected_state_ref` and envelope before ref equal its current
canonical state. `INITIALIZE` names an absent task at attempt 1, has null
expected/before state, and its event context and after state name attempt 1.
`RETRY` subject names source attempt n and expected/before state is F0 at n;
its semantic event context and after state name the same task at n+1.
`CREATE_REMEDIATION_TASK` subject source coordinates and expected/before state
name the current N5/N6 source; its first event names that source and its second
event/after state names the distinct absent child at subject attempt 1.
`IMPORT_REPOSITORY`, `CHECKPOINT`, and `EXPORT_SNAPSHOT` have null subject and
expected state; import task-event contexts equal the listed tasks' current
attempts in list order. Worker command claim/fence arguments equal the current
active claim and task fence; recovery claim equals the active claim; and review-
decision assignment equals the active review.

For all commands except import, request and envelope repository coordinates
equal pre-command metadata; import alone uses the exact next coordinates
specified below. Genesis/bridge coordinates are generation zero and equal their
payload and manifest provenance.

Every task command except `GOVERNANCE_BLOCK` requires the before state's
repository generation to equal current metadata. `GOVERNANCE_BLOCK` may consume
a stale before state, but its after state adopts the current metadata generation.
The request state ref and envelope before ref still identify that exact stale
state. No other transition may consume a stale task.

## 5. Task-state and transition closure

The only reachable task triples are the 13 alternatives in
`m0-3a-task-state.v2.schema.json`: N0, N1, N2, F0, N3 through N8, B0, B1, and
C0 as named by the accepted planning contract. `CANCELLED` and `SUPERSEDED` are
not runtime-format-2 states. Adding either requires a new event vocabulary and
contract version.

The state transitions are:

| Operation | Source → target |
| --- | --- |
| `INITIALIZE` | absent → N0, attempt 1 |
| `CLAIM` | N0 → N1; create claim and advance scheduler, dispatch, fence |
| `START` | N1 → N2 |
| `CONTINUE` | N2 → N2; increment continuation and scheduler generation |
| `YIELD` | N1 or N2 → N0; close claim and advance scheduler, dispatch, fence |
| `FAIL` | N1 or N2 → F0; close claim and advance scheduler, dispatch, fence |
| `COMPLETE(close=false)` | N2 → N3; close claim and advance scheduler, dispatch, fence |
| `COMPLETE(close=true)` | N2 → C0; close claim and advance scheduler, dispatch, fence |
| `RECOVER` | N1 → N0 only; close claim with liveness evidence |
| `RETRY` | F0 at attempt n → N0 at attempt n+1 |
| `GOVERNANCE_BLOCK` | N0/N1/N2 → B0; N3/N4 → B1; close or revoke active work |
| `REVALIDATE` | B0 → N0; B1 → N3; never restore old claim or review assignment |
| `ASSIGN_REVIEW` | N3 → N4; create review assignment |
| `APPROVE` | N4 → N7; close assignment |
| `REJECT` | N4 → N5; close assignment |
| `REMEDIATE` | N4 → N6; close assignment |
| `ROUTE` | N7 → N8 |

Let `S`, `D`, `F`, and `C` mean scheduler generation, dispatch generation,
task fence, and continuation count in the before state. Fields not named by a
transition are byte-identical before and after. Counter overflow invalidates the
whole group.

- `INITIALIZE` sets attempt 1, N0, `S=D=F=C=0`, the request owner, owner role,
  and receipt,
  current repository generation, null claim/assignment/reviewer and null links.
- `CLAIM` sets N1, `S+1,D+1,F+1`, and the payload UUID as active claim. It
  creates `claims(claim_id,task_id,attempt,F+1,"OPEN",actor,event_id,null)`.
- `START` sets N2 and `S+1`; `CONTINUE` keeps N2 and sets `S+1,C+1`.
- `YIELD`, `FAIL`, and either `COMPLETE` target set `S+1,D+1,F+1`, clear the
  claim, and close its row at the semantic event with status `YIELDED`,
  `FAILED`, or `COMPLETED`. `close=false` targets N3; `close=true` targets C0.
- `RECOVER` sets N0, `S+1,D+1,F+1`, clears the claim, and closes it
  `RECOVERED`.
- `RETRY` sets attempt n+1, N0, `S+1,D+1,F+1,C=0`, clears claim/assignment,
  preserves owner, receipt, repository and task links, and creates the new
  attempt row with predecessor n.
- `GOVERNANCE_BLOCK` sets B0 or B1, `S+1,D+1,F+1`, and clears active work. An
  active claim closes `GOVERNANCE_INVALIDATED`; an active review closes
  `GOVERNANCE_REVOKED`. `REVALIDATE` sets N0 or N3, `S+1`, current repository
  and receipt values, and never restores the prior claim or assignment.
- `ASSIGN_REVIEW` sets N4, `S+1`, and the payload UUID as assignment. It creates
  `reviews(assignment_id,task_id,attempt,actor,role,"OPEN",event_id,null)`.
  The request actor must differ from the task's immutable owner fixture ID and
  the request role must differ from its immutable owner role; otherwise the
  group is invalid.
  `APPROVE`, `REJECT`, or `REMEDIATE` sets N7, N5, or N6, `S+1`, clears the
  assignment, and closes it `APPROVED`, `REJECTED`, or `REMEDIATION_REQUIRED`.
- `ROUTE` sets N8 and `S+1`.

`CREATE_REMEDIATION_TASK` is one group: source N5 or N6 receives
`REMEDIATION_CREATED`; the absent child receives
`TASK_CREATED_FROM_REMEDIATION` at attempt 1/task sequence 1; the reciprocal
link and both task references derive atomically. `IMPORT_REPOSITORY` emits task
events in ascending unique affected-task-ID order and then one runtime
`REPOSITORY_GENERATION_ADVANCED`; it is idempotent through the universal command
key. Unlisted source, target, or operation combinations are invalid.

Remediation additionally requires a null source `successor_task`, an absent
child, and distinct source and child task IDs. A source can therefore create at
most one remediation child and its link cannot be overwritten. The request
`decision_sha256` must equal the decision digest in the prior review-decision
request whose semantic event placed the source in N5 or N6.

The remediation source retains its N5/N6 triple, sets `S+1`, and sets
`successor_task=child`; the child is N0 with zero counters, current repository,
request owner/owner-role/receipt, `predecessor_task=source`, and no successor.
For a v1 bridge, the immutable owner role is the literal `owner`, matching the
frozen v1 review predicate. The link row
uses the request relationship UUID, both semantic event IDs, source decision
digest, and the remediation-link digest equation. Its exact preimage is the
canonical object with keys `link_id`, `source_task_id`, `source_attempt`,
`child_task_id`, `child_attempt`, `source_event_id`, `child_event_id`, and
`decision_sha256`, with values equal to the eight same-named row columns;
`link_sha256` is excluded.

For `IMPORT_REPOSITORY`, request top-level generation and bundle are the new
candidate values; `new_generation = old metadata generation + 1`, and all group
envelopes use the new coordinates. The affected list is sorted and unique. It
contains every current F0, N5, N6, N7, N8, B0, or B1 task, may contain any
caller-selected subset of N0, N1, N2, N3, or N4 tasks, and never contains C0.
It equals the task semantic events in the group. N0, F0, N5, N6, N7, N8, B0,
and B1 retain their triple and set `S+1`; N1/N2 become B0 and N3/N4 become B1,
each with `S+1,D+1,F+1` and active work closed/revoked as above. Every affected
state takes the new generation. Unlisted N0-N4 tasks are unchanged and retain
their older generation; they are stale and can only be consumed by
`GOVERNANCE_BLOCK` as specified above. C0 is terminal and remains unchanged.
The affected list may be empty only when no mandatory task exists; the runtime
advancement event still records the new generation. Payload old/new values,
source commit, bundle component digests, reason, and affected list exactly equal
the request-derived candidate and reduced set.

`TASK_RETRIED` is task sequence 1 of the new attempt. Its task predecessor is
the derived new-attempt root, its before-state is F0 from attempt n, and its
after-state is N0 for attempt n+1. Attempt n remains headed by `TASK_FAILED`.

The persisted `tasks.reviewer` column is always null. Active reviewer identity
is represented once, by `reviewer_assignment_id` and the corresponding review
row. Duplicating reviewer identity into the task row is invalid.

## 6. Whole-image derivation

The reducer derives all 15 tables and takes none of them as an input to state
transition decisions:

| Table | Exact derivation |
| --- | --- |
| `events` | every validated canonical envelope in global-sequence order |
| `blobs` | exact reachable request, response, payload, state, snapshot, and legacy blobs |
| `schema_documents` | exact pinned nine-document inventory |
| `schema_registry` | one exact pinned registry row |
| `metadata` | genesis/bridge identity plus reduced runtime heads, repository and selector fields |
| `tasks` | latest after-state for each task, including atomic retry/remediation effects |
| `attempts` | one row per observed attempt with origin and final task-local head |
| `claims` | claim issuance and exact close/recovery/invalidation event |
| `reviews` | assignment and exact approval/rejection/remediation/revocation event |
| `remediation_links` | reciprocal source/child event pair and domain-separated link digest |
| `idempotency` | committed non-system command groups only |
| `seals` | exactly one `RUNTIME_GENESIS_IDENTITY` row |
| `migrations` | exactly zero rows |
| `snapshots` | validated checkpoint and export documents/events in independent sequences |
| `legacy_archive` | zero rows for `NEW`, exactly one bridge-derived row for `V1_MIGRATION` |

Normative row equations supplement the table summary:

- `events` rows are `[global_sequence,event_id,event_sha256,canonical_envelope]`.
- An `attempts` origin is its sequence-1 task event; its head is its maximum
  task sequence. Retry never moves the old attempt head.
- `tasks` is exactly one latest reduced state per task. All 18 columns equal
  that canonical state in descriptor order.
- Claim and review row values and close statuses are the transition equations
  above; opened/closed IDs are their semantic event IDs.
- `idempotency` is one row per non-system commit with group operation key,
  transaction UUID, request/response digests, commit ID/sequence and group time.
- `metadata` is the singleton manifest/genesis identity plus latest reduced
  repository, global head, checkpoint and selector coordinates. Authority is
  always null and `UNANCHORED/UNKNOWN/DENY`.
- `seals` is one row with `seal_id` and `seal_type` both
  `RUNTIME_GENESIS_IDENTITY`, the runtime/chain/attachment/genesis/manifest
  coordinates, source event equal to genesis/bridge, and genesis group time.
- `legacy_archive` columns exactly equal bridge payload/manifest source
  coordinates and exact-role archive/projection blob digests.
- `snapshots` columns exactly equal checkpoint/export request, document,
  payload, cut head, prior digest, semantic event, and group time.
- Every remaining column is fixed by the descriptor projection plus the
  transition, link, selector, and blob equations here; no implementation-
  selected default is allowed.

The literal singleton keys are `metadata.singleton="runtime"`,
`schema_registry.singleton="registry"`, and, when present,
`legacy_archive.singleton="legacy"`. Attachment `created_at`, manifest
`created_at`, metadata `created_at`, seal `created_at`, and the genesis/bridge
group timestamp are byte-identical canonical UTC seconds. No other creation
timestamp can be selected for those rows.

One blob digest maps to exactly one schema ID. The blob table equals the exact
reachable set; missing and extra blobs both invalidate the image. Identical
canonical bytes cannot be relabeled under another schema ID. Before/after state
refs follow the registry: initialization and child remediation creation have a
null before ref; runtime events have null before/after refs; all other task
events bind both state documents.

Reachability is a least fixed point over only these typed edges: every event
adds its envelope payload/state refs; every validated transaction group adds
the exact-role request and response blobs named by its shared transaction
digests, and each non-system commit repeats those refs; a bridge payload adds
its exact-role legacy archive and projection refs; checkpoint/export payloads
add their known-role document
blob digests; and snapshot rows repeat those same document edges. No string or
digest elsewhere is traversed. Response generated refs, evidence/decision/
repository digests, heads, and link digests are not blob edges. The fixed point
must equal the blob inventory exactly.

The `migrations` table exists only to keep the frozen physical layout closed.
It is empty in runtime format 2. Any physical storage or schema change requires
a successor runtime format. The v1-to-v2 bridge is genesis provenance in
`legacy_archive`, not a format-2 migration row or `MIGRATION_RECORDED` event.

## 7. Checkpoints, selector evolution, and exports

Selector generation 0 is format 1. Generation 1 activates format 2 and has a
null `latest_v2_checkpoint_sha256`. Generation 2 and later require a non-null
latest checkpoint digest.

A checkpoint command binds a UUIDv4 snapshot ID, sequence, prior checkpoint,
checkpoint digest, blob digest, and the complete next selector generation,
selector digest, and selector-history digest before the command is committed.
Its checkpoint roots describe the pre-registration cut: the head and
materializations before the checkpoint document, blob, snapshot row, semantic
event, commit event, and metadata advance. After a successful transaction, the
already-bound selector bytes may be durably installed; recovery can use only
those exact bytes. No selector is invented during recovery.

The pre-registration cut excludes every artifact of the registering command:
request, response, payload, states, document, every new blob, snapshot and
idempotency row, semantic event, commit event, and metadata advance. Export uses
the identical exclusion rule. Thus no document root contains itself or an
object whose digest contains that document.

For a checkpoint from current selector generation `g`, request next generation
is exactly `g+1`. The candidate selector has the fixed v2 filenames, same
runtime/manifest, history path for `g+1`, prior path/digest equal the current
selector, latest checkpoint equal the new checkpoint digest,
`V2_ACTIVE/UNKNOWN/DENY`, and `written_at` equal the group time. Its digest is
recomputed; next history digest is the selector-history digest of old
contiguous history plus the candidate. Request and payload values must equal
those results. Generation 1 is the cutover selector; every later generation
corresponds one-to-one with a checkpoint and no generation skips. Metadata
advances to those exact selector/checkpoint values in the command.

Checkpoint and export snapshot IDs are request-bound UUIDv4 values. Their
sequences are separately contiguous from zero and their prior digest is null
only at sequence zero. Exports use the export digest domain and bind an exact
read cut. `source_checkpoint_sha256` equals the latest checkpoint at that cut,
or null exactly when none exists. Checkpoint, export, selector, and table-root assertions remain local
integrity evidence with `UNANCHORED / UNKNOWN / DENY`.

## 8. Implementation gate

This milestone permits only schema-bundle verification. The next coherent
milestone is a pure, in-memory, whole-transaction reducer with adversarial
fixtures and no writer. A database writer, SQLite initialization, migration,
selector cutover, or positive consistency result remains prohibited until that
reducer independently reproduces every derived table and rejects all malformed
transaction/state cases.
