# Runtime-v2 dependency-closure integer-token digit limit

Status: bounded deny-only classification evidence

## Exact subject

This evidence classifies only the lexical decimal-digit ceiling applied by
`runtime_v2_closure._parse_integer_token` before Python integer conversion.
For an input token, one leading ASCII minus sign is removed for counting:

`digits = token[1:] if token.startswith("-") else token`

The accepted condition is `len(digits) <= 19`. A token with more than 19
counted characters raises `CanonicalJsonError("INTEGER_TOKEN_TOO_LONG")`
before `int(token)` is called. The unit is Python string characters. The
leading minus sign is not included in the count. No leading plus behavior is
classified or authorized.

## Bound source shape

The classification binds the exact sign-removal slice, the exact strict
`len(digits) > 19` comparison, `_parse_integer_token`, the
`json.loads(parse_int=_parse_integer_token)` caller in `_parse_closure_json`,
and the complete closure module AST. It binds the one-through-nineteen digit
admission boundary and twenty-digit pre-conversion rejection for both positive
and negative tokens.

Changing the literal, comparator, sign slice, sign test, integer conversion
order, error code, or `parse_int` callback invalidates the evidence. Duplicate,
missing, substituted, attacker-refreshed, predecessor-rewritten, or
ancestor-rewritten sites remain fail-closed.

## Explicit nonclaims

The 19-character lexical ceiling is not signed-int64 validation. Some admitted
19-digit tokens exceed int64. It does not establish field-specific integer
minimums or maximums, leading-zero rules, negative-zero rules, plus-sign
behavior, canonical JSON grammar, float handling, token counts, byte counts,
dependency completeness, closure identity, currentness, public-verifier
acceptance, STOP clearance, execution, wagering, or capital authority.

All other discovery sites remain separately classified or unclassified.
Coverage remains `INCOMPLETE`; generation and every authorizing use remain
`DENY`.
