# M0.3A Checkpoint and Export Replay Slice v1

## Scope

This slice extends the private, pure runtime-format-2 initial-image reducer to
compile `CHECKPOINT` and `EXPORT_SNAPSHOT` transaction groups. It remains
disconnected from the public verifier and returns only `INVALID` or
`UNSUPPORTED / CLOSURE_NOT_COMPILED / DENY`. It adds no database writer,
selector installer, cutover path, currentness claim, execution authority,
capital authority, or STOP-clearing authority.

## Exact cut derivation

Before either registration group, the reducer reconstructs all fifteen
descriptor tables from accepted prior events, reachable typed blobs, task and
attempt history, idempotency rows, snapshot rows, repository coordinates, and
selector history. It computes each table root with the retained
`EDGELAB\0TABLE\0V2\0` domain. The cut excludes the registering request,
response, payloads, document blob, snapshot row, semantic event, commit event,
idempotency row, and metadata advance.

The reducer recomputes the checkpoint/export document domain digest and its
separate blob digest. It cross-binds request, response, semantic payload,
commit payload, event pair, exact cut head, document, and snapshot row. Export
and checkpoint sequences are independently contiguous from zero with separate
prior chains. An export binds the latest checkpoint at its cut, including null
before any checkpoint.

Every checkpoint deterministically derives the next contiguous selector. The
supplied selector must match the fixed v2 paths, runtime and manifest,
checkpoint digest, prior selector, group timestamp, `V2_ACTIVE`, `UNKNOWN`,
and `DENY`; both selector and cumulative history digests are recomputed. Export
does not create a selector. Final metadata is derived from the last accepted
event and selector/checkpoint state.

Snapshot materialization is always sorted by
`(snapshot_kind, snapshot_sequence, snapshot_id)`, independently of event
interleaving. Optional checkpoint copies are comparison-only transport bytes:
they must byte-equal registered checkpoint document blobs, remain unique and
strictly sequence ordered, and never create reachability.

## Bounded work and atomicity

Historical checkpoint/export cuts and the final supplied cut are each charged
for all fifteen tables. The cumulative root-work limit is 1,073,741,824 bytes;
identical logical materializations would still be charged once per cut. A
group advances the replay cursor, selector list, snapshot rows, idempotency
rows, and reachability only after its complete event/document comparison has
succeeded. Hostile types and malformed values fail closed under normal Python
and `python -O`.

## Adversarial evidence

`tests/test_runtime_v2_snapshot.py` covers snapshot-first export with a null
checkpoint, two checkpoints and two exports with independent prior chains,
selector evolution, sorted snapshot rows, checkpoint-copy transport,
repository-import followed by snapshot registration, fully rebound root
forgery, selector and copy attacks, and exact cumulative root-work boundary
plus one-byte-over denial. The existing initial-replay corpus remains green.

Live status remains `LOCKED`, the kill switch remains engaged, deployable
capital remains zero, and every open STOP remains open.
