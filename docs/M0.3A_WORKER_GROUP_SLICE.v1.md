# M0.3A START and YIELD transaction slice v1

## Status

This document records the third private ordinary transaction-group increment
of the runtime-format-2 reducer. It is not a whole-image verifier release.

The slice is pure, deny-only, and disconnected from the public verifier. A
candidate that passes every compiled check remains opaque as
`UNSUPPORTED / CLOSURE_NOT_COMPILED / DENY`.

## Compiled profiles

The reducer now recognizes these bounded NEW-runtime prefixes:

1. `RUNTIME_GENESIS`.
2. Genesis followed by `INITIALIZE`.
3. The initialized task followed by `CLAIM`.
4. The claimed task followed by either `START` or `YIELD`.
5. The started task followed by `YIELD`.

`START` changes the task from `CLAIMED` to `IN_PROGRESS`, increments the
scheduler generation, and preserves the OPEN claim. `YIELD` is valid from
`CLAIMED` or `IN_PROGRESS`; it closes the active claim as `YIELDED`, returns
the task to `CLAIMABLE`, increments scheduler and dispatch generations, and
advances the task fence.

## Reusable worker-group boundary

The shared worker reducer validates before transition:

- complete prefix shape and one two-event semantic/commit group;
- exact global and task-local sequence and predecessor continuity;
- event, digest, transaction, and operation-key uniqueness across the prefix;
- runtime, chain, repository, operation, request, response, and commit
  cross-bindings;
- exact task subject and before-state equality with the prefix-derived state;
- closed operation-specific arguments and empty semantic payloads;
- claim-ID and fence compare-and-swap through the immutable transition kernel;
- exact independently derived after-state, claim history, attempt head,
  idempotency row, task row, and metadata head;
- exact typed blob reachability and all 15 table projections.

The supplied before-state, after-state, claim row, response, and tables remain
comparison-only. No late validation failure can publish a partial patch.

## Explicit exclusions

This version does not compile `CONTINUE`, `FAIL`, `COMPLETE`, `RECOVER`,
`RETRY`, governance, review, route, remediation, repository import,
checkpoint, or export groups. It does not add a writer, database, selector
cutover, currentness claim, positive consistency result, authority, paper
execution, live execution, or capital path.

## Next boundary

Extend the reusable worker reducer across continuation and claim-closing
operations, preserving every historical claim and attempt across retry and
re-claim cycles. Review and governance projections follow only after the task
execution lifecycle is closed. Snapshot cuts remain downstream of complete
ordinary replay.
