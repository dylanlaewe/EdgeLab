# M0.3A portable-path character limit v1

## Status and scope

This additive evidence contract freezes the exact source-level claim required
to classify `_PORTABLE_PATH_MAX`. It does not change runtime behavior,
classify the sibling component-length constraint, complete the resource
census, authorize release generation, establish public-verifier acceptance,
clear a STOP, or authorize execution or capital.

The classification is valid only while the definition, comparison, exact
string-and-pattern precondition, rejection result, enclosing helper and
module, evidence input, predecessor, schema, manifest, and self-digest
bindings remain exact. Missing, stale, aliased, inconsistent, or partially
refreshed evidence fails closed.

## Exact semantic claim

```text
constraint_id: _PORTABLE_PATH_MAX
classification: RESOURCE_MAXIMUM
semantic_subject:
  EXACT_BUILTIN_STR_PORTABLE_RELATIVE_PATH_ARGUMENT_AFTER_PATH_PATTERN_VALIDATION
unit: CHARACTERS
maximum: 4096
```

The accepted resource equation is:

```text
for each exact built-in str path admitted by _PATH:
    len(path) <= 4096
```

`CHARACTERS` means Python built-in `len()` applied to the exact `str` returned
by `_pattern(value, _PATH, coordinate)`. The pinned `_PATH` grammar admits
only ASCII path characters, so this measure is also the number of admitted
ASCII code points. It does not mean encoded bytes, filesystem bytes, path
components, canonicalized paths, resolved paths, host-platform path units, or
the length of the caller-supplied coordinate.

The maximum is inclusive. Satisfying this equation is only admission by the
total-path resource predicate. Component length and later portability checks
remain independent and can still reject a path of at most 4,096 characters.

## Preconditions and enforcement order

The resource check is reached only through this order:

1. `_path` receives `value` and the caller-supplied diagnostic `coordinate`.
2. `_pattern` requires `value` to have exact built-in type `str`.
3. `_PATH.fullmatch(value)` must accept the complete value; otherwise exact
   `PATTERN` rejection occurs before length inspection.
4. The exact admitted string is retained as `path` and split on `/` into
   `components` without rewriting `path`.
5. Built-in `len(path)` applies the inclusive 4,096-character equation.
6. On total-path overflow, the first `or` operand short-circuits and `_fail`
   raises `ClosureValidationError` with exact code `PATH_LENGTH` and the
   unchanged caller coordinate.
7. If the total-path predicate admits, the independent
   `_PORTABLE_COMPONENT_MAX` predicate may still produce the same rejection.
8. If both size predicates admit, trailing-dot and Windows-device portability
   rules may still reject.
9. Only after all independent rules pass does `_path` return the exact
   admitted `str` object without truncation, encoding, normalization,
   resolution, substitution, copying, or reordering.

A `str` subclass is not an exact built-in string. It must be rejected by
`_pattern` before caller-controlled `__len__` or other subclass behavior can
participate. A syntactically invalid string must likewise be rejected as
`PATTERN`, irrespective of its size.

## Exact boundary acceptance matrix

Let `M = 4_096`. Dedicated evidence must use exact built-in ASCII strings
accepted by `_PATH`, with every component at most 255 characters and no
trailing-dot or Windows-device component.

| Case | Exact supplied cardinality | Required result |
| --- | ---: | --- |
| maximum minus one | `M - 1` | `_path` succeeds and returns the exact supplied object |
| maximum | `M` | `_path` succeeds and returns the exact supplied object |
| maximum plus one | `M + 1` | exact `PATH_LENGTH` rejection at the supplied coordinate |

The 4,096-character positive fixture is seventeen components: fifteen
255-character components, one 254-character component, one one-character
component, and sixteen separators. The 4,097-character negative fixture
extends only the final component, so component length cannot explain its
rejection.

Evidence must additionally establish that:

- a valid admitted path is retained by identity and value;
- a `str` subclass with hostile `__len__` is rejected as `PATTERN` without
  executing that method;
- plain non-string values are rejected as `PATTERN`;
- oversized strings outside `_PATH` are rejected as `PATTERN` before the
  resource comparison;
- a path shorter than 4,096 with a 256-character component is rejected as
  `PATH_LENGTH`, demonstrating that the sibling rule remains separate;
- trailing-dot and Windows-device paths remain later `PATH_PORTABILITY`
  rejections rather than part of this maximum;
- total-path overflow rejection is deterministic and preserves the exact
  diagnostic coordinate; and
- normal and optimized (`-O`) Python produce the same results.

## Required adversarial evidence

The classification must fail closed under attacks that alter or bypass any
part of its semantic dependency closure, including:

- changing the maximum, replacing it with a literal or alias, or adding an
  additional load or store of `_PORTABLE_PATH_MAX`;
- substituting `_PORTABLE_COMPONENT_MAX` or a currently equal-valued
  expression such as `2_048 + 2_048`;
- changing `>` to `>=`, reversing or negating the comparison, or measuring
  `value`, `coordinate`, `components`, encoded bytes, or a transformed path;
- deleting, duplicating, relocating, wrapping, or conditionally bypassing
  the enforcement branch;
- weakening, deleting, or moving the exact built-in string and `_PATH`
  precondition after the cardinality inspection;
- changing split behavior so the resource predicate measures or returns a
  rewritten path;
- suppressing, catching, renaming, redirecting, or changing the code or
  coordinate of `ClosureValidationError`;
- truncating, encoding, normalizing, resolving, copying, substituting, or
  reordering an admitted path;
- conflating component length or portability with the total-path maximum;
- shadowing or replacing `len`, `_pattern`, `_PATH`, or `_fail` in the bound
  source closure;
- changing the set of `_path` callers while retaining a stale semantic claim;
- treating successful private shape validation as verifier acceptance or
  operational authority; or
- refreshing ordinary source, census, schema, manifest, predecessor,
  evidence, or self-digests around a semantic mutation.

Attacker-controlled ordinary identities must be refreshable in adversarial
tests so the hard-pinned definition, comparator, precondition, helper, module,
evidence, predecessor, ancestry, and exact-manifest checks remain
independently meaningful.

## Explicit exclusions

- `_PORTABLE_COMPONENT_MAX`, component count, trailing-dot behavior,
  Windows-device aliases, path ownership, path uniqueness, or root coverage;
- filesystem existence, resolution, normalization, case behavior, symlink
  safety, operating-system support, or path authorization;
- serialized bytes, retained storage, aggregate work, database size, or any
  relational maximum;
- the correctness or acceptance of the dependency closure as a whole;
- public-verifier support or acceptance, replay validity, strategy evidence,
  authority, or whole-image reducer semantics;
- release-generation readiness or completeness of the resource census; or
- behavior under an unpinned interpreter or external monkeypatching.

## Safety and authority boundary

This is evidence about one private dependency-closure path-character bound.
Successful `_path` return is not approval and grants no filesystem access,
scheduling, execution, wagering, capital, STOP-clearing, publication,
release-generation, or public-verifier authority. Its eventual cumulative
manifest must remain `INCOMPLETE`, generation and authorizing use must remain
`DENY`, the project-wide resource-inventory blocker must remain
unconditional, live must remain `LOCKED`, deployable capital must remain USD
0, and the kill switch must remain engaged.

If any required identity, boundary result, ordering fact, adversarial result,
or authority invariant cannot be reproduced exactly, `_PORTABLE_PATH_MAX`
must remain unclassified.
