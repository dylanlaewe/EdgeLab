# M0.3A decision-evidence currentness model

A future adapter uses a closed record with `repository`, `runtime`, `attachment`,
`task_id`, `attempt`, `scheduler_state`, `assignment`, `handoff`, `claim`, `fence`,
`project`, `stops`, `dependencies`, `capabilities`, `inventories`, `git`, and
`generations`. `generations` requires repository, runtime, scheduler, dispatch,
fence, assignment, handoff and claim integers. Each identity/head is read from the
current transactional scheduler authority or its bound repository snapshot; Git is
read from the attached repository. No field is inferred from an authentic historical
capture.

A value differing from the captured authorization binding produces `STALE`; an
unavailable or wrong runtime produces `INCOMPATIBLE`; either requires v3 verification
result `DENY`. Historical replay remains VALID when only this record changes.
