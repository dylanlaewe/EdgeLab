# M0.2 Decision Evidence Envelope v1

This is the minimum adapter contract between frozen M0.2 (`bc3a40924ca580ca6eddc4c24e32ff99ddd95330`) and M0.3A. It captures evidence around the frozen function; it does not alter its input acceptance, eligibility, STOP/capability behavior, actions, or output meaning. `decision_id` remains a deterministic local content binding, not a receipt, authentication artifact, external authority, or approval.

## Canonical form and source set

All envelope, input, and output bytes are UTF-8 JSON encoded with recursively lexicographic keys, no whitespace, explicit `null`, `ensure_ascii=true`, integers as JSON integers, booleans as JSON booleans, and no NaN/infinity. SHA-256 values are lowercase hex. A source reference is `{path,sha256}` and binds the exact repository file bytes.

The adapter accepts only `{task_id:string,attempt:integer}`. It resolves the same repository inputs frozen `orchestration.decision(root,intent)` resolves: origin URL and committed-ancestor identity; `orchestration/scheduler-state.json`; its referenced project-state file; every `reports/stops/STOP-*.v*.json`; the named task; current claimed handoff; current task assignment; handoff binding; recursively resolved dependency task records and their completion records; every capability record; and the current source Git commit. The input bundle contains `schema_version`, `freeze_commit`, `engine_identity` (path and source SHA-256), `repository` (expected remote, resolved root marker, HEAD), `intent`, `source_refs` sorted by path, and `resolved` values `{state,project,stops,task,handoff,assignment,handoff_binding,dependencies,completions,capabilities}`. It includes no M0.3 state and no decorative field. Absence is rejected unless frozen M0.2 itself accepts an explicit JSON null.

The output bundle is the exact returned mapping from frozen `decision`, with `schema_version`, `decision`, `decision_id`, `task_id`, `reason`, `execution_adapter`, and `operation` explicitly `null` when the DENY result lacks it. No output field is reinterpreted.

## Envelope schema and generation

The typed schema is `schemas/m0-2-decision-envelope.schema.json`. An envelope includes immutable identity, freeze/engine identity, task/attempt, input/output bundles and digests, repository bundle/generation binding, creation time, and its content digest. Create it only by: resolve the source set; canonicalize/hash input; invoke frozen M0.2 with the same root/intent; canonicalize/hash output; verify the returned `decision_id` by rerunning frozen M0.2 from the captured source set; construct canonical envelope excluding `content_sha256`; hash; persist. A caller-supplied `receipt_digest` is never evidence.

## Verifier and currentness

The verifier returns `VALID_CURRENT`, `VALID_STALE`, or `INVALID`.

1. Validate schema and envelope digest.
2. Require exact freeze commit and engine path/content identity.
3. Resolve every source reference from the authoritative repository and compare raw bytes/digests.
4. Reconstruct canonical input, compare its digest, rerun frozen M0.2, reconstruct output, compare output digest and every output field including `decision_id`.
5. Verify task/attempt/assignment subject. Any mismatch is `INVALID`.
6. Compare the envelope authoritative-bundle digest and repository generation with current M0.3A binding. Exact recomputable evidence with a changed authoritative input is `VALID_STALE`, not valid current.

`VALID_CURRENT` requires `DISPATCH`, matching task/attempt, current authoritative bundle/generation, current assignment/head, project/STOP/dependency/capability records, and a matching runtime binding. Changes to any captured source make it stale. A stale envelope remains historically verifiable and may be replayed but cannot authorize an R-gated transition.

For `CLAIM`, `START`, `CONTINUE`, and `COMPLETE`, require a current DISPATCH envelope bound to the same task/attempt and repository generation. The same envelope may be reused only while all captured inputs and generation remain current; M0.3 tuple-only changes do not alter M0.2 inputs. `REVALIDATE` requires a newly verified current DISPATCH envelope after a governance block. `INITIALIZE`, yield, fail, retry, recovery, cancellation, supersession, review, remediation, and routing are not R-gated. An input/generation change fences work under existing M0.3A governance rules and requires re-evaluation before a new R-gated transition.

## Persistence and limits

SQLite is the runtime authority: store immutable canonical envelope bytes and digest once, reference the digest from task/event/idempotency history, and reject update/delete through normal runtime access. Generate on demand only before use; once used, persist it. Git stores only milestone exports/evidence, never a competing mutable runtime authority. Replay follows event → envelope digest → exact historical bytes, and verifies historical validity separately from present currentness.

The envelope proves deterministic local binding, recomputation, substitution detection and staleness detection within the documented repository/host assumptions. It does not prove external authentication, worker/reviewer identity, hostile-host integrity, external append-only anchoring, STOP clearance, Risk approval, or capital authority.
