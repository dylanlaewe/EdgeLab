# M0.3A v16 — bounded semantic replay closure

V16 supplements v15 without granting M0.3A acceptance or operational authority.
The local synthetic scheduler must reconstruct, from its task-event history, the
exact task tuple transitions, task owner and remediation lineage, attempt chain,
all current and historical claims, all review assignments, and remediation
links. Startup, export, backup, and the locked authority diagnostic fail closed
when any reconstructed row set differs from SQLite materialization.

Normal task events bind an exact-typed request task ID, operation, expected
tuple, repository generation, and stored decision-receipt string. The writer and
replay language are identical for scalar types: booleans are not integers,
identities are nonempty strings, retry is exactly boolean, and liveness,
routing, completion-mode, and review-decision inputs are closed to their declared
types. A task whose repository generation lags the runtime generation cannot
transition until a repository import explicitly advances or fences it.

Repository task events carry both the prior global generation and the prior
task-local generation so a task omitted from an earlier import can be advanced
later without inventing history. `COMPLETE` is allowed only from N2.
Governance block and repository invalidation are allowed only from N0 through
N4. The existing v1 wire names `TASK_YIELDD`, `TASK_FAILD`, and
`REVIEW_REJECTD` remain unchanged pending a versioned storage migration.

A review outcome carries a lowercase SHA-256 decision digest. A remediation
source event, child event, and link must use that exact preceding REJECT or
REMEDIATE digest, share one relationship, be globally consecutive, bind child
owner and receipt, and form a single acyclic parent/successor lineage. A source
cannot acquire a second successor.

This remains a bounded v1 hardening step. Idempotency request/response
reconstruction, runtime metadata and genesis closure, seal reconstruction,
migration-ledger and snapshot-root replay, task-event global predecessor-ID
anchoring, and resistance to a hostile complete-chain rehash require a separately
versioned format milestone. Positive currentness, an R-gate, executor activity,
STOP clearance, paper/live action, and capital authority remain absent.
