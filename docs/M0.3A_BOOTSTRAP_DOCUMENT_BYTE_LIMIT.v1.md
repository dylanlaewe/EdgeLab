# M0.3A bootstrap-document byte limit v1

## Status and scope

This additive evidence contract freezes the exact source-level claim required
to classify `MAX_BOOTSTRAP_DOCUMENT_BYTES`. It does not change runtime
behavior, classify any sibling or aggregate constraint, complete the resource
census, authorize release generation, establish public-verifier acceptance,
clear a STOP, or authorize execution or capital.

The classification is valid only while every definition, branch binding,
shared comparison dependency, enclosing function and module, evidence input,
predecessor, schema, manifest, and self-digest binding remains exact. Missing,
stale, aliased, inconsistent, or only partially refreshed evidence fails
closed.

## Exact semantic claim

```text
constraint_id: MAX_BOOTSTRAP_DOCUMENT_BYTES
classification: RESOURCE_MAXIMUM
semantic_subject:
  EXACT_BUILTIN_BYTES_BOOTSTRAP_FIELDS_OR_COLLECTION_MEMBERS_ADMITTED_BY_HOST_PREFLIGHT
unit: BYTES
maximum: 1,048,576
```

The accepted equations are:

```text
for each exact built-in bytes field value in:
  RuntimeImage.verifier_dependency_closure
  RuntimeImage.manifest
  RuntimeImage.attachment

    len(supplied field bytes) <= 1,048,576

for each exact built-in bytes member reached after tuple and cardinality
validation in:
  RuntimeImage.checkpoint_copies
  RuntimeImage.selector_history

    len(supplied member bytes) <= 1,048,576
```

`BYTES` means Python byte length as measured by `len()` at the bound source
layer. It does not mean decoded characters, parsed JSON size, canonical object
size, collection cardinality, retained database size, estimated memory use,
or the sum of two or more fields or members. The maximum is inclusive and is
applied independently to each of the five branch subjects.

The shared constant has five known branch-specific uses. A classification of
only one use would be a partial description of the named constraint and is
not accepted by this contract.

## Preconditions and enforcement order

### Exact byte fields

Each `verifier_dependency_closure`, `manifest`, or `attachment` comparison is
reached only through this order:

1. Require the candidate to have the exact host `RuntimeImage` type.
2. Read every required slot into the closed `captured` mapping without a
   caller-selected fallback.
3. Require all fields to be present.
4. Select the literal row from the fixed `byte_fields` tuple.
5. Require the selected field to have exact built-in type `bytes`.
6. Add its exact byte length to independent bounded aggregate accounting.
7. Apply the inclusive per-field equation.
8. On overflow, add `IMAGE_ITEM_BYTE_LIMIT` for the exact field artifact at
   coordinate `/`.
9. If any violation exists, withhold the sanitized image. Otherwise, retain
   the exact supplied byte object.

### Exact collection members

Each `checkpoint_copies` or `selector_history` member comparison is reached
only through this order:

1. Perform the same exact host-type and complete field-capture checks.
2. Require the collection to have exact built-in type `tuple`.
3. Apply the separate cardinality rule for that collection.
4. Skip member iteration if cardinality is invalid.
5. Select the literal row from the fixed `byte_collections` tuple.
6. Require each iterated member to have exact built-in type `bytes`.
7. Add its exact byte length to independent bounded aggregate accounting.
8. Apply the inclusive per-member equation.
9. On overflow, add `IMAGE_ITEM_BYTE_LIMIT` for the exact collection artifact
   at coordinate `/<index>`.
10. If any violation exists, withhold the sanitized image. Otherwise, retain
    all supplied members in their original order and identity.

The collection cardinality constants and their shared comparator remain
unclassified. They are preconditions for reaching this byte maximum, not part
of its semantic subject. Aggregate accounting is likewise an ordering
dependency, not part of the classified maximum.

## Exact boundary acceptance matrices

Let `M = 1,048,576`. Dedicated evidence must apply this matrix independently
to each of `verifier_dependency_closure`, `manifest`, `attachment`,
`checkpoint_copies`, and `selector_history` using an otherwise valid host
fixture.

| Case | Exact supplied length | Required result |
| --- | ---: | --- |
| maximum minus one | `M - 1` | no byte-limit finding; retain the exact supplied bytes when no unrelated violation exists |
| maximum | `M` | no byte-limit finding; retain the exact supplied bytes when no unrelated violation exists |
| maximum plus one | `M + 1` | exact `IMAGE_ITEM_BYTE_LIMIT`; withhold the sanitized image |

For the three field branches, the overflow coordinate is `/`. For each
collection branch, it is the exact `/<index>` of the oversized member.
Boundary results remain deny-only and non-Boolean even when size-admitted.

Evidence must additionally establish that:

- accepted values are not truncated, decoded, sampled, replaced, or
  reordered;
- a nonzero collection-member index is reported exactly;
- a non-`bytes` field or member is rejected before its caller-controlled
  `__len__` can execute;
- a non-tuple collection is rejected before collection length inspection;
- invalid collection cardinality skips per-member size inspection and is not
  relabeled as a byte-limit failure;
- all five siblings may independently equal `M` without consuming a shared
  `MAX_BOOTSTRAP_DOCUMENT_BYTES` allowance;
- making exactly one sibling `M + 1` identifies only that subject; and
- normal and optimized (`-O`) Python produce the same result.

## Required adversarial evidence

The classification must fail closed under attacks that alter or bypass any
part of its semantic dependency closure, including:

- changing the maximum, replacing it with a literal or alias, or adding an
  additional load or store of `MAX_BOOTSTRAP_DOCUMENT_BYTES`;
- substituting another currently equal-valued maximum;
- omitting any of the five known branches or adding an unreviewed branch;
- changing, duplicating, deleting, reordering, filtering, slicing, or
  dynamically constructing either bound table;
- changing a branch key, captured subject, maximum symbol, row index,
  assignment, loop target, loop iterable, or shared comparator;
- changing `>` to `>=`, comparing a collection instead of a member, or
  measuring a decoded or copied representation;
- weakening exact field, tuple, member-type, or cardinality preconditions;
- moving the check before required guards or after an attacker-controlled
  parse or transform;
- suppressing, renaming, redirecting, or changing the artifact or coordinate
  of `IMAGE_ITEM_BYTE_LIMIT`;
- retaining, truncating, substituting, or reordering an over-limit subject in
  a sanitized image;
- allowing an image to survive any resulting violation;
- shadowing or replacing `len` in the bound source closure;
- changing the fixed deny-only/non-Boolean result semantics; or
- refreshing ordinary source, census, schema, manifest, predecessor, or
  self-digests around a semantic mutation.

Attacker-controlled ordinary identities must be refreshable in adversarial
tests so the hard-pinned row, table, loop, function, module, evidence,
predecessor, and exact-manifest checks remain independently meaningful.

## Explicit exclusions

This contract does not establish or classify:

- JSON syntax, canonicality, schema validity, digest validity, or semantic
  validity of any bounded bytes;
- whether checkpoint or selector documents are mutually consistent;
- collection cardinality, `MAX_CHECKPOINT_COPIES`, `MIN_SELECTORS`, or
  `MAX_SELECTORS`;
- either shared generic comparator as an independently classified site;
- `MAX_EVENT_BYTES`, `MAX_SCHEMA_REGISTRY_BYTES`, or any other sibling
  branch;
- total accounted input, final root work, retained storage, database size,
  schema-bundle size, or any other aggregate or relational maximum;
- public-verifier support or acceptance, replay validity, authority, or
  reducer semantics;
- successful image construction when any unrelated rule fails;
- release-generation readiness or completeness of the resource census; or
- behavior under an unpinned interpreter or external monkeypatching.

## Safety and authority boundary

This is evidence about five private host-preflight branches sharing one
per-subject byte maximum. It grants no scheduling, execution, wagering,
capital, STOP-clearing, publication, release-generation, or public-verifier
authority. Its cumulative manifest must remain `INCOMPLETE`, generation and
authorizing use must remain `DENY`, the preflight result must remain non-Boolean,
the project-wide resource-inventory blocker must remain unconditional, live
must remain `LOCKED`, deployable capital must remain USD 0, and the kill
switch must remain engaged.

If any required identity, boundary result, ordering fact, adversarial result,
or authority invariant cannot be reproduced exactly,
`MAX_BOOTSTRAP_DOCUMENT_BYTES` must remain unclassified.
