# M0.3A runtime-v2 reducer bootstrap gaps

## Status

This document records a fail-closed engineering review of
`M0.3A_CONTENT_REDUCER_CONTRACT.v1.md`. It does not revise that frozen
contract, accept a runtime image, clear a STOP, or create operational
authority. `STOP-M0-3A-002` prevents a positive whole-image reducer result
until every item below is resolved through a versioned successor contract and
independent engineering review.

The private `runtime_v2_transition` module may be developed under this STOP.
It operates only on immutable in-memory task state, is not imported by the
public verifier, and cannot represent whole-image consistency or authority.

## Blocking gaps

### 1. Verifier dependency closure is unbound

Genesis and bridge payloads contain
`verifier_dependency_closure_sha256`, but the current `RuntimeImage` has no
closure record and the verifier has no compiled supported-closure value. A
syntactically valid digest is not evidence of the dependency closure.

A successor contract must publish one exact canonical closure record and its
digest. The record must close every pure executable module, embedded or
compiled schema, canonicalization rule, and external package/version used by
whole-image reduction. The pure boundary must compile the supported digest and
reject any genesis/bridge mismatch without reading the current checkout.

### 2. Bootstrap schema authority is incomplete

The nine-document retained registry intentionally omits the bootstrap
attachment, manifest, and active-selector schemas. The current verifier pins
only the raw manifest schema hash and does not possess immutable schema bytes
for any of the three documents.

A successor contract and implementation must embed or mechanically generate
the exact bootstrap validators and pin these current raw schema digests:

- attachment: `0623e1706d3a18a2b06043c72f444bd8bad9d798248ff62c83a901a36c1dbb9c`
- manifest: `dcec875b3bb65178fc58e19d84c7fed5d85df97f44f501b3e4aa3c1c44b791de`
- selector: `5398ccf55ce90159d9da34f9a29863a856f1e6e38fdb9ab498b8bd71bb5badf9`

Loading `schemas/` at reduction time is prohibited because mutable ambient
repository files cannot define the meaning of retained evidence.

### 3. Runtime-image transport shape is not closed

The existing `RuntimeImage` contains untyped table cells, separate checkpoint
copies, selector-history byte strings, and optional string-keyed legacy
evidence. The contract does not completely define their ordering,
cardinality, cross-equality, or resource-work limits.

The successor must define all of the following before positive reduction:

- exactly one supplied snapshot for each of the 15 descriptor tables, in
  descriptor order, with exact scalar cell types and no duplicate names;
- selector history beginning with generations 0 and 1, contiguous thereafter,
  with metadata initially derived from generation 1 and generations 2+ in
  one-to-one order with checkpoint groups;
- for a bridge, generation-0 `active_runtime_id` equals the bridge source
  runtime ID; for `NEW`, generation 0 is an explicitly supplied, schema-valid
  pre-cutover selector and conveys no migration or authority claim;
- generation 1 is deterministically derived from the manifest, generation-0
  selector, genesis/bridge timestamp, and fixed v2 paths, with a null latest
  checkpoint;
- checkpoint copies are optional transport duplicates only; every supplied
  copy must byte-equal exactly one registered checkpoint document blob and
  duplicates or unregistered copies are invalid;
- bridge archive and projection documents are reached only through their typed
  blob references. The current `legacy_evidence` field is rejected unless a
  future version publishes a closed typed inventory and digest equations;
- a bounded snapshot/root-work budget that prevents repeated flat-table root
  computation from becoming quadratic, plus cardinality caps for checkpoint
  copies, selector documents, table snapshots, and legacy evidence.

Legacy bridge provenance is archival only. A bridge creates the single
`legacy_archive` row and no active v2 task or attempt rows. Any legacy task that
must become active requires a later, separately specified v2 initialization or
import operation; no task mapping may be inferred from the archive or
projection documents.

### 4. REVALIDATE receipt replacement is unstated

The frozen prose says `REVALIDATE` sets current receipt values, but its request
has only `evidence_sha256`. There is no second receipt source. The successor
contract must state the deterministic equation:

`after.decision_receipt_digest = request.arguments.evidence_sha256`

The private transition kernel uses this equation provisionally. It cannot be
connected to retained-event verification until the successor contract adopts
it and the review suite confirms the request, payload, state, and response
cross-bindings.

## Safe implementation boundary

Work permitted while the STOP is open:

- immutable task/claim/review/remediation transition planning;
- exhaustive transition and rollback tests;
- pure resource accounting, canonical parsing, and transaction partitioning
  that expose no positive public result;
- versioned contract repair and independent engineering review.

Work prohibited while the STOP is open:

- a positive whole-image consistency status;
- importing the private kernel into the public verifier as an acceptance path;
- a writer, SQLite initializer, migration executor, selector installation,
  recovery mutation, currentness assertion, or authority-bearing result;
- any change to live status, kill switch, deployable capital, or strategy
  promotion.

## Remediation evidence required

The STOP may be considered for resolution only after a successor contract,
exact dependency-closure artifact, embedded bootstrap validators, closed image
transport type, and adversarial fixtures are independently reviewed and the
complete pure reducer reproduces all 15 materialized tables for both genesis
kinds. Resolution still would establish local consistency only; it would not
establish authenticity, currentness, execution authority, or capital
authority.
