# M0.3A RECOVER transaction slice v1

## Status

This document records the sixth private ordinary transaction-group increment
of the runtime-format-2 reducer. It adds exactly one bounded `RECOVER` group
after `CLAIM`. It is not a whole-image verifier release.

The slice is pure, deny-only, and disconnected from the public verifier. A
candidate that passes every compiled check remains opaque as
`UNSUPPORTED / CLOSURE_NOT_COMPILED / DENY`.

## Compiled transition

`RECOVER` is valid only from `CLAIMED`, before work has entered `IN_PROGRESS`.
Its closed request arguments are the exact active claim ID and a syntactically
valid liveness-evidence digest. The operation deliberately has no fence
argument.

The immutable transition returns the task to `CLAIMABLE`, increments scheduler
and dispatch generations, advances the task fence, clears the active claim,
and closes that claim as `RECOVERED` at the semantic event. Attempt identity
and continuation count are preserved.

Recovery from `IN_PROGRESS` is rejected because the system cannot infer or
cancel possible external effects. A liveness-evidence digest is a syntactically
bound replay input, not proof that the evidence exists, is true, or is current.

## Replay boundary

The shared group reducer independently derives and validates exact global and
task chains, identity uniqueness, retained content, source state, claim
compare-and-swap, after-state, claim history, task and attempt heads,
idempotency, typed reachability, and all 15 table projections. Supplied state,
claim rows, and tables remain comparison-only.

## Explicit exclusions

This version compiles only `INITIALIZE → CLAIM → RECOVER`. It does not compile
re-claim after recovery, `RETRY`, repeated continuation, repeated attempts, or
any governance, review, remediation, import, checkpoint, or export group. It
adds no writer, database, selector cutover, currentness claim, positive
consistency result, authority, execution, or capital path.

## Next boundary

Implement a distinct `RETRY` reducer and lossless multi-attempt projection.
Then generalize claim replay and the dispatcher for repeated lifecycle cycles
without quadratic rescanning at the retained event bound.
