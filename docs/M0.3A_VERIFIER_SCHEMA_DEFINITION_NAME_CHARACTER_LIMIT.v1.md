# M0.3A verifier schema-definition name character limit

## Scope

Classification V40 records one already-enforced resource maximum: a root
`$defs` member name may contain at most 64 Python string characters. The exact
overlapping definition and enforcement site is the strict
`len(name) > 64` comparison in `_schema_safety_findings`.

## Complete semantic slice

The verifier obtains `definitions` from the root document with
`value.get("$defs", {})`. A non-dictionary value produces
`SCHEMA_DEFS_NOT_OBJECT` and is replaced by an empty dictionary. After the
budget-guarded root walk, the verifier iterates exactly
`definitions.items()`. The character ceiling is one disjunct of the existing
compound name profile: exact string type, nonempty value, maximum length,
alphabetic initial character, and ASCII alphanumeric/underscore/hyphen
characters. Failure adds `SCHEMA_DEF_NAME` at `/$defs` and immediately
continues. Consequently a rejected member neither creates a graph node through
`edges.setdefault` nor recursively walks its definition body.

Lengths 1, 63, and 64 are accepted when the other profile terms hold. Length
65 is rejected. The bound counts Python string characters, not encoded bytes.

## Deliberate nonclaims

This constraint does not classify the other definition-name profile terms,
schema-reference token length, target existence, graph size or cycles,
definition-body validity, generic string limits, or diagnostic multiplicity.
An invalid short name can receive the same diagnostic for a reason unrelated
to length. Diagnostic emission remains subject to the existing finding budget.
