# Runtime V2 blobs-table row limit evidence

## Accepted claim

The host inspector enforces one inclusive resource maximum at the strict-zip
position paired with `_TABLE_SPECS[1]`:

`len(captured['table_snapshots'][1].rows) <= 300000`

This is a positional `ITEMS` bound. The supplied `table` label is a non-blocking
diagnostic and does not select or redirect the maximum. The comparison runs
only after the exact outer table-snapshot cardinality, snapshot type and
field-presence guards, the identity diagnostic regardless of label match, and
the built-in-tuple rows guard. 300001 rows produce `TABLE_ROW_LIMIT`, mark
accounting incomplete, skip row inspection, and keep the image unavailable.
