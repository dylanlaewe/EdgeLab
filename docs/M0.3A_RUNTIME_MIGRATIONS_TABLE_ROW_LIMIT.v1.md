# Runtime-v2 migrations table row limit

Status: **CLASSIFIED RESOURCE MAXIMUM / INCOMPLETE / DENY**

This evidence classifies one previously discovered resource site only: the
Discovery V4 positional `migrations` table-row ceiling in
`src/edgelab/runtime_v2_image.py:inspect_runtime_image_host`.

## Accepted equation

For an exact `RuntimeImage` whose `table_snapshots` field is an exact built-in
tuple with exactly `len(_TABLE_SPECS)` members, the snapshot paired by strict
zip with `_TABLE_SPECS[7]` must have an exact built-in tuple `rows` field and:

```text
len(captured['table_snapshots'][7].rows) <= 0
```

The maximum is inclusive. Zero rows is admitted by this resource check; one or
more rows adds `TABLE_ROW_LIMIT` at `/7/rows`, marks accounting incomplete,
skips row inspection, and prevents a sanitized image from being returned.

## Positional binding

The cap is selected by position 7 in
`enumerate(zip(captured['table_snapshots'], _TABLE_SPECS, strict=True))`, not
by the supplied `snapshot.table` label. A hostile label cannot select another
cap or bypass the zero maximum. The outer exact-cardinality gate must pass
before the strict zip is entered. Exact snapshot type, field presence, table
identity, and exact rows-tuple checks precede `len(rows)`.
