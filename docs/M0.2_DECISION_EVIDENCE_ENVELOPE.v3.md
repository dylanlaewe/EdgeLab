# M0.2 Decision Evidence Envelope v3 — implementation authority

This supersedes v2 for planning. It wraps, without modifying, frozen M0.2 at `bc3a40924ca580ca6eddc4c24e32ff99ddd95330`. It does not authorize a scheduler transition, executor, network, worker, capital, or STOP clearance.

## Closed record and evidence closure

Only the v3 schema is authoritative. Every nested object in it is closed; no authority-bearing JSON object is an untyped map. `subject` is the single authoritative tuple `{task_id,attempt,assignment_head,handoff_head}`. The verifier derives the same tuple from the reconstructed input and from normalized output: all three tuples must be byte-for-byte equal, including task id and attempt. Any mismatch is `INVALID`.

An evidence item is exactly one tagged form: `FILE` (raw immutable bytes), `ABSENT` (the asserted missing path plus the closed directory inventory which establishes absence), or `DIRECTORY` (a closed ordered inventory). `ABSENT` has no blob and is valid evidence only with its named inventory. Every inventory is a complete, UTF-8 repository-relative lexical list of *all* entries in its root, including malformed JSON, unknown names, symlinks and non-files; extra, missing, moved, or reordered entries fail the historical input comparison. A parsed-record inventory is therefore not a convenience list: it covers all `docs/handoffs/*.json` before frozen `_current_handoff` selects one, all dependency/completion records it traverses, and the complete directories read on either branch.

DISPATCH captures intent; scheduler/task/assignment/binding state; all task, assignment, completion, capability, STOP and handoff directories; every handoff JSON (not merely matching IDs); direct referenced schemas; and every file/absence/inventory reached. DENY captures the exact rejection plus the complete denial-context directories. `source_manifest` has one closed entry per source id and `input.source_ids` lists every manifest id exactly once. A source id cannot be both a file and absence assertion.

## Canonical bytes and strict output derivation

`CJ(x)` is UTF-8 JSON with no BOM or whitespace, duplicate-key rejection, codepoint-preserving strings, lexicographic object-member order, preserved array order, explicit null, JSON booleans distinct from integers, integer numbers only, and no floats/nonfinite values. Paths use `/`; timestamps are RFC3339 UTC `Z`. Mapping member order is non-semantic and is represented only by `CJ`; arrays are semantic and never sorted. `SHA256` is of exactly those bytes.

The raw return is stored only as `{encoding:"UTF8_CANONICAL_JSON",bytes_base64,byte_length,sha256}` where the bytes are `CJ(the exact returned mapping)`. It is decoded with duplicate-key rejection and must match length/digest. Thus output bytes and their representation are deterministic. Normalization is not caller assertion: the verifier decodes raw output, checks the exact conditional key set and types, then derives the closed normalized object. Unknown raw keys remain in preserved raw bytes but make normalization fail closed.

For `DENY`, raw keys must be exactly `decision,decision_id,task_id,reason,execution_adapter`; normalized `operation` is null. For `DISPATCH`, raw keys must additionally contain `operation`; it must be a nonempty frozen operation string, and normalized `task_id` and `operation` are copied from raw output. Both branches require `decision_id`, reason and `execution_adapter == MOCK_ONLY`; `DISPATCH` output task id equals `subject.task_id`. Independently supplied normalized values that differ from derivation are `INVALID`.

## Mechanically closed frozen-engine replay

The engine manifest names every executable/imported artifact by path, SHA-256 and byte length: `src/edgelab/orchestration.py`, `validate.py`, `data_integrity.py`, every schema reached by `validate_record`, and the sealed replay launcher, Git shim and clock shim. It also names exact Python implementation/version and jsonschema distribution/version. Its `entries` list is closed and must equal the required dependency closure calculated from the sealed import/validation manifest; an unlisted import, missing entry, different digest, or environment version is `INVALID`.

Replay creates an empty isolated directory, writes only manifest blobs at their captured repository paths, and invokes the sealed launcher in a fresh subprocess with `PYTHONPATH=<replay>/src`, empty inherited module path, fixed locale/UTF-8/hash seed, and a minimal allowlisted environment. The launcher imports only the replay tree. Before import it installs a sealed `FrozenDateTime` at every frozen clock call site; `now(tz)` and `utcnow()` return the captured UTC instant with documented timezone conversion and reject an unlisted clock API. Boundary tests compare direct frozen behavior under the interception with the launcher at equal instants.

The launcher prepends a sealed Git shim to `PATH`. It implements only frozen calls (`remote get-url origin` and `merge-base --is-ancestor HEAD origin/main`) from the captured `git_identity` `{remote_url,head_sha,origin_main_sha,head_is_ancestor}`; all other Git calls deny. The shim, captured refs, launcher and environment are hashed manifest entries. This is historical Git/ref replay: it recreates exactly the observations frozen M0.2 consumes without importing or trusting current checkout state. It is not an assertion that an arbitrary current checkout has the same commit objects.

## Generation, verification and statuses

Generation holds the common repository/runtime lock while it resolves all source blobs/inventories, runs the sealed frozen engine at `evaluation_time`, derives normalized output, builds `SHA256(CJ(envelope without envelope_sha256))`, final-resolves the complete authority set, then atomically persists blobs, envelope, event reference and generation. Any A→B change denies generation.

`verify_historical(envelope)` uses only envelope blobs and the sealed replay environment. It verifies schema, hashes, complete inventories, environment, raw output, derivation, subject equality and a rerun at captured time. It returns `HISTORICALLY_VALID` or `INVALID`.

Only after historical validity, `verify_currentness(envelope,target_runtime)` acquires the common lock and resolves current source closure, task/attempt, assignment/handoff, repository/runtime generation, Git identity, project/STOP, dependency/completion and capabilities. Equal closure is `CURRENT`; changed/deleted/moved authority is `STALE`. Wrong attachment/runtime returns typed `{code:"WRONG_RUNTIME",historical:"HISTORICALLY_VALID",currentness:"INVALID_CURRENT_STATE",expected_runtime_id,actual_runtime_id}` and cannot authorize anything. Overall shape is closed: `VALID_CURRENT`, `VALID_STALE`, or `INVALID`, with typed reasons. Historical validity and currentness are never conflated.

## Retention, gates, and acceptance

SQLite retains immutable envelope bytes, all referenced blobs/manifests/inventories, raw output, normalized output, evaluation time, replay environment identity and append-only event references. Backup/export carries the transitive closure and restore rehashes it. Caller `receipt_digest`, arbitrary envelope ID and `verified` flag are legacy/non-authorizing and every fallback must be removed.

An R-gated transition requires `VALID_CURRENT` bound to the exact current task/attempt/runtime tuple. CLAIM/START/CONTINUE/COMPLETE each recheck it; REVALIDATE creates a new envelope. The exact evidence-only rows are in M0.3A v6. Required acceptance includes every DISPATCH/DENY branch and conditional violation; empty/extra nested objects; subject mismatch; file/absence/inventory mutations; every unrelated handoff mutation; raw-byte/digest/mapping-order/unknown-key cases; engine dependency and version mutations; clock boundaries; Git-ref replay; wrong runtime; historical-valid/current-stale/invalid separation; every evidence-only event; legacy denial; race; backup restore; and byte-identical Stage 1 regression.
