# M0.3A Dependency-Closure Shape Profile v1

## Status and scope

This document records the compiled pre-release validation profile for
`urn:edgelab:m0-3a-verifier-dependency-closure:1`. It is additive to
`M0.3A_RUNTIME_IMAGE_CONTRACT.v1.md` and the pinned closure JSON Schema.

The profile validates canonical transport, closed record shape, limited
published inventory bindings, the deny-only boundary, and the record's
self-digest. It does not
establish the exact supported release identity. No generated closure bytes,
compiled digest, release carrier, writer, selector cutover, positive verifier
result, currentness, execution permission, or capital authority exists.

A shape-valid, self-consistent candidate remains `UNSUPPORTED / DENY` until a
future source-freeze milestone generates one exact closure/carrier and compiles
those exact bytes into the private reducer. The public verifier remains
disconnected.

## Runtime validation boundary

The runtime validator:

- accepts exact `bytes` only and enforces the 1,048,576-byte limit before
  parsing;
- requires duplicate-free canonical JSON, exact built-in JSON types, and a
  deterministic maximum of 19 decimal digits per integer token;
- compiles the v1 schema constants, closed keys, patterns, cardinalities,
  strict integers, exact five bootstrap roles, and exact nine retained roles;
- requires one fixed `ENTRYPOINT`, one fixed `PIN_CARRIER`, and exactly one
  carrier-only pin elision;
- binds each bootstrap and retained schema role to its already-published
  schema ID and repository path;
- enforces ascending unique keyed inventories, case-collision denial, one
  global owner-path namespace, and one global schema-ID namespace;
- conservatively fixes ascending `local_import_roots`, distribution import
  modules, and runtime-assumption names; requires non-overlapping import roots
  and exactly one proper-ancestor root owner per local artifact; rejects
  trailing-dot and Windows-device path aliases; canonicalizes distribution
  names; requires
  distinct begin/end markers and digest-domain literals; and permits no
  exact or ancestor/descendant standard-library/external module namespace
  reuse;
- recomputes the closure self-digest with only its self field omitted; and
- performs no filesystem, Git, package-metadata, clock, environment, network,
  subprocess, or dynamic-import access.

These refinements remove representational aliases before a release exists.
They do not establish a candidate's mutable inventory as the future compiled
inventory or prove that the inventory is complete.

## Generator-only obligations

Symlink/hardlink identity, resolved import ownership, source byte lengths,
exact raw/domain digests, package metadata, and pin-block occurrence can be
established only by the future offline generator over frozen sources. Runtime
validation must not inspect the ambient checkout to recreate those claims.

The following generation semantics remain intentionally unresolved and keep
`STOP-M0-3A-002` open:

1. The v1 schema has no explicit import-edge graph or module mapping. The
   future generator must either define edges as generation-only derivation over
   the retained artifact inventory or introduce a new schema version.
2. The pin-carrier `byte_length` basis must be defined as transformed/elided
   semantic bytes or final generated source bytes.
3. `external_distributions[].metadata_sha256` needs an exact source-byte and
   digest equation.
4. Exact marker literals and the mandatory runtime-assumption inventory must
   be fixed before generation.

No exact closure or carrier may be published until these choices are
versioned, all semantic reducer sources are frozen, deterministic regeneration
is proven, and independent review accepts the complete artifact.

## Assurance limit

Shape validation plus a self-digest detects malformed or internally altered
records. It does not prove transitive dependency completeness, source
authenticity, external anchoring, currentness, selection, STOP resolution, or
authority. A self-consistent attacker-selected record cannot advance beyond
the private opaque `CLOSURE_NOT_COMPILED` result.
