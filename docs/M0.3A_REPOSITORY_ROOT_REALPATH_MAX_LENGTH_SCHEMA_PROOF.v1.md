# Repository-root realpath max-length schema proof V1

## Scope

This evidence supports exactly the Draft 2020-12 `maxLength` keyword at
`schemas/m0-3a-runtime-attachment.v2.schema.json` pointer
`/properties/repository_root_realpath/maxLength`, site
`bd7b0ebc888973d3388c8ab0d67c0fbcf03333fa27b5b86616a924c5ee90b848`.
Its isolated local meaning is:

`UNICODE_CODE_POINT_COUNT <= 4096 UNICODE_CODE_POINTS`

The proof binds the full schema bytes, root identifier, exact pointer ancestry,
addressed V8 site, and containing-subschema digest
`1cb0f2473cb55b110447de322170e5050e56184fc26d1d544cb298ff202d9ac5`.

## Local behavior

Strings of 4095 and 4096 Unicode code points satisfy this isolated keyword;
4097 code points do not. The empty string satisfies `maxLength` in isolation.
Astral characters count as one code point despite wider UTF-8 encodings.
Combining sequences count individual code points, not grapheme clusters.
Non-string instances receive no assertion from this keyword.

## Evidence boundary

The adjacent `type: string` and `minLength: 1` keywords are context only. This
proof does not establish sibling type or minimum-length behavior, property
presence, path or realpath syntax, path canonicalization, path existence,
symlink resolution, repository containment, filesystem or repository identity,

It establishes no root-schema acceptance or rejection, full-schema validity,
deployed-validator conformance, public reachability, independent acceptance,
STOP clearance, release approval, execution or wagering authority, or
capital authority. It changes no runtime behavior.
