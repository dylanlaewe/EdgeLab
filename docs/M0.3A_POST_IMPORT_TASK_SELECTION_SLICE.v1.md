# M0.3A post-import task-selection replay slice — v1

## Scope and safety boundary

This private slice compiles ordinary runtime-v2 groups after one or more
`IMPORT_REPOSITORY` groups, including snapshot-interleaved tails. It does not
connect the public verifier, open or write a database, install a selector,
clear a STOP, accept the closure, authorize execution, or change capital.
Every locally consistent candidate remains `UNSUPPORTED` with
`CLOSURE_NOT_COMPILED` and `authorizing_use=DENY`.

This slice supersedes only the temporary "import is terminal" implementation
limit recorded in `M0.3A_REPOSITORY_IMPORT_SLICE.v1.md`; the frozen retained
content/reducer contract remains the normative authority.

## Exact selection rule

An ordinary group selects its task only from the exact retained command
request named by the semantic event's transaction digest. The request subject
must be the closed `{task_id, attempt}` object and must identify one retained
workspace task and its current attempt. The event context is then checked
independently against that selected identity, its retained task-attempt head,
and its exact next task sequence. This separation is required for `RETRY`: the
request selects failed attempt n while the semantic event opens attempt n+1.

Selection never depends on mapping order, a sole-task shortcut, a task-table
position, global-sequence parity, or caller-provided materialization. Unknown,
wrong-attempt, hostile-host-type, and cross-task request/context selections
fail closed. Stale selections fail closed for every operation except the exact
`GOVERNANCE_BLOCK` exception below. The immutable transition kernel remains
the final state-machine check.

## Repository generations and history

Every ordinary operation except `GOVERNANCE_BLOCK` requires the selected
before-state repository generation to equal current runtime metadata.
`GOVERNANCE_BLOCK` is the sole stale-task consumer and atomically adopts the
current generation while fencing or revoking active work as the retained
contract requires. Mandatory import tasks are therefore available to their
otherwise-valid next transition; unlisted optional tasks remain stale and
cannot regain ordinary eligibility through selection.

The task-local cursor retains every task and attempt head. Committing a
selected ordinary group advances only that task's head and transition records;
unrelated task state, attempts, claims, reviews, decisions, remediation links,
and history remain byte-identical. Global event, transaction, operation-key,
and digest indexes continue cumulatively across remediation, variable-width
imports, snapshots, and ordinary groups. No even/odd global-sequence
assumption remains.

Repository import is no longer treated as terminal. Repeated imports remain
valid when each request satisfies the exact next-generation and mandatory-task
rules. Checkpoints and exports may appear before or after imports and before a
later selected ordinary group; their registration cuts remain immutable and
the later task event follows the current global head. `INITIALIZE` outside its
existing first post-genesis position remains uncompiled and is rejected as an
unsupported follow-up operation, not mischaracterized as an import rule.

## Adversarial coverage

Focused tests cover a mandatory failed task after an odd-width import, exact
request-attempt selection for retry, source/child selection after remediation,
unrelated state and task-head preservation, stale child claim rejection,
stale-child governance blocking, stale active-claim invalidation with its exact
closed auxiliary row, import-to-checkpoint-to-ordinary replay,
repeated empty imports, foreign and wrong attempts, cross-task context and
subject substitution, and hostile subject host types. The focused module runs
under normal and optimized Python so assertion removal cannot widen acceptance.
