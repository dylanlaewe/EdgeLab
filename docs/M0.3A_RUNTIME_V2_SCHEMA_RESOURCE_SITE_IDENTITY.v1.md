# Runtime-v2 stable schema resource-site identity V1

This evidence-only design gives each legacy schema-bound resource record a
stable address without classifying it. The legacy `_schema_bound_inventory`
walk, record shape, order, and V1 list digest remain unchanged.

For each legacy record, `site_id` is the lowercase SHA-256 hex digest of the
ASCII domain
`EDGELAB\0RUNTIME_V2_SCHEMA_RESOURCE_SITE\0V1\0` followed by canonical JSON
containing exactly `json_pointer`, `keyword`, `path`, `schema_id`, and `value`.
Canonical JSON sorts keys, uses compact separators, escapes non-ASCII, rejects
NaN, and preserves integer sign. Classification is deliberately absent from
the identity equation.

The ordered addressed list is hashed with the domain
`EDGELAB\0RUNTIME_V2_SCHEMA_BOUND_SITES\0V2\0`. Its 296-record digest is
`2ca911e85141b79c5ae6be653bf6a8b038ca90873a731764b27ac2bf0cae3fcf`.
The addressing helper is pure and fails closed on record-shape or type drift,
malformed RFC 6901 escapes, noncanonical input order, duplicate five-field
identities, or a site-ID collision. Every `~` in a pointer must be followed by
`0` or `1`. JSON Pointer text is identity data: valid `~0`, `~1`, empty tokens,
Unicode, and array indexes are not decoded or normalized.

Discovery V8 adds no new source binding and changes no V7 evidence. It merely
addresses the existing schema census. Stable identity is not semantic
classification, schema validity, release acceptance, STOP clearance,
execution authority, or capital authority.
