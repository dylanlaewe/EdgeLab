# Runtime-v2 schema declarative-keyword proof V1

Status: executable staged contract; no production classification

This profile defines a closed, location-scoped proof contract for the twelve
Draft 2020-12 integer-valued bound keywords discovered by the resource census.
It does not add a constraint to Classification V44. V44 preserves V43's exact
38 constraints, 71 classified source sites, zero classified schema sites, and
650 unclassified sites.

## Bound identity and context

`SCHEMA_DECLARATIVE_KEYWORD_V1` accepts exactly the ten top-level fields fixed
by its schema. The proof must repeat the complete addressed Discovery V8 record
and its exact five-field site-ID preimage. The checker resolves that record only
from the schema-site namespace; a source site or cross-kind substitution fails.

The schema document is bound by byte length, raw SHA-256, root `$id`, and the
exact Draft 2020-12 dialect. Nested `$id` and `$schema` declarations are denied.
The executable subset is deliberately narrower than general URI-fragment
resolution: every `$ref` must be `#` or a resolving raw local RFC 6901 pointer,
percent-encoded fragments are denied, and `$dynamicRef` and `$recursiveRef` are
unsupported and denied anywhere. The containing
subschema pointer is mechanically the parent of the keyword pointer and its
object is hashed under
`EDGELAB\0RUNTIME_V2_SCHEMA_CONTAINING_SUBSCHEMA\0V1\0`. Ancestors are an
ordered root-to-parent pointer sequence with explicit indices, while the raw
document digest binds the complete ancestor content. These facts establish
only `EXACT_PINNED_SCHEMA_LOCATION_ONLY` applicability.

## Declarative equations

| Keywords | Instance domain | Metric | Operators | Unit |
| --- | --- | --- | --- | --- |
| `minimum`, `maximum`, `exclusiveMinimum`, `exclusiveMaximum` | number or integer | JSON number value | `>=`, `<=`, `>`, `<` | JSON number |
| `minLength`, `maxLength` | string | Unicode code-point count | `>=`, `<=` | Unicode code points |
| `minItems`, `maxItems` | array | array item count | `>=`, `<=` | array items |
| `minProperties`, `maxProperties` | object | object property count | `>=`, `<=` | object properties |
| `minContains`, `maxContains` | array | contains-match count | `>=`, `<=` | contains matches |

Every bound equals the addressed integer site value. Non-numeric counts must be
nonnegative. Numeric bounds may be any JSON integer and are treated with
arbitrary precision; the current census does not claim exhaustive numeric or
floating-point coverage. Length means Unicode code points, not bytes or
graphemes, and this profile makes no claim about lone-surrogate handling.
`minContains` and `maxContains` additionally bind the adjacent `contains`
sibling, which must be a boolean or object schema. The 112 real contains sites
form 56 pairs.

For an instance outside the keyword's domain the keyword makes
`NO_ASSERTION_FROM_THIS_KEYWORD`. A missing local `type` sibling is therefore
not synthesized: 127 real containing subschemas omit it. Reference reachability
and application are distinct from the local declarative equation.

## Evidence and nonclaims

A proof needs at least two pairwise-distinct, byte-pinned evidence inputs. They
may not be the bound schema document or file aliases. Contract fields for
runtime definition/enforcement sites, AST semantics, generic semantic proofs,
or `maximum` are prohibited. A location-specific proof ID prevents different
sites sharing one keyword from collapsing into a single claim.

This contract does not prove runtime-validator behavior, public reachability,
root applicability beyond the pinned local context, full-schema validity,
deployed-validator conformance, independent acceptance, STOP clearance,
release authority, execution authority, or capital authority.
