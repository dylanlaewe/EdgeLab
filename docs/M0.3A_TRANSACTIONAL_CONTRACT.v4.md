# M0.3A Transactional Contract v4 — receipt integration amendment

V4 is implementation-authoritative with v3 scheduler semantics preserved unchanged. This amendment replaces every v3 phrase “exact M0.2 receipt/input bundle” with the sole interface [M0.2 Decision Evidence Envelope v1](M0.2_DECISION_EVIDENCE_ENVELOPE.md). No other v3 state, transition, SQLite, event, attachment, migration, backup, export, lock, replay, or scope rule changes.

`decision_receipt_digest` in the task tuple is renamed semantically to `decision_envelope_digest`; Data must migrate it additively and preserve historical values until a verified envelope replaces them. Caller-supplied receipt digests are invalid for new authorization. A task/event/idempotency record binds the envelope digest and immutable envelope reference.

R-gated `CLAIM`, `START`, `CONTINUE`, and `COMPLETE` require a `VALID_CURRENT` DISPATCH envelope for the exact task/attempt, runtime repository generation and authoritative bundle. `REVALIDATE` requires a newly verified `VALID_CURRENT` DISPATCH envelope after governance block. Other transitions are not R-gated. A `VALID_STALE` envelope is preserved for replay but cannot authorize a new transition; `INVALID` makes runtime unavailable or denies the request. Reuse is allowed only while the envelope verifier establishes all captured M0.2 inputs and generation remain current.

Generation, storage, historical replay, currentness, source-of-truth, verification and security limits are exactly those in the envelope specification. The adapter wraps frozen M0.2, never changes eligibility or treats `decision_id` as stronger than local deterministic content binding. Stage 1 remains frozen at `bc3a40924ca580ca6eddc4c24e32ff99ddd95330`.

Additional required acceptance cases: caller digest denial; valid current DISPATCH authorization; DENY envelope rejection; tampered envelope/input/output/source/engine/freeze rejection; rerun-output and `decision_id` mismatch rejection; task/attempt/assignment substitution rejection; stale-vs-invalid distinction; repository/project/STOP/dependency/capability change staleness; allowed reuse while current; revalidation fresh-envelope requirement; immutable historical replay; and migration from legacy caller digest without silently authorizing it.

All v3 exclusions remain: no M0.3B identity, authenticated worker, model policy, Goal engine, executor/Codex, network, plugin/skill/MCP, external authority, Scout, real sports data, Research/Quant, paper/live, capital mutation, or STOP clearance.
