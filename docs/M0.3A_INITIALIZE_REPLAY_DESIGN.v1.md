# M0.3A Cursor-Relative INITIALIZE Replay Design v1

Status: private implementation design; not an acceptance record, authority
binding, cutover decision, or capital authorization.

This design supersedes only the temporary single-position `INITIALIZE`
implementation limits recorded in `M0.3A_INITIALIZE_GROUP_SLICE.v1.md` and
`M0.3A_POST_IMPORT_TASK_SELECTION_SLICE.v1.md`. Their deny-only,
public-verifier, authority, STOP, and capital boundaries remain unchanged; the
retained content/reducer contract remains normative.

## Contract conclusion

The retained content contract defines `INITIALIZE` as absent task to N0 at
attempt 1. It does not restrict initialization to the first post-genesis group
or to a single task. Runtime-v2 replay therefore accepts the operation at any
complete transaction boundary where its task ID is absent and the group binds
the current runtime, chain, repository generation, repository bundle, and
global head.

## Reducer boundary

`reduce_initialize_group` is cursor-relative. It derives event coordinates and
the pre-command head from the accepted replay cursor, derives repository
coordinates from cursor/workspace equality, validates an absent request task,
opens the task's attempt-1 root, stages the transition, validates exact
response/state/commit materializations, and returns an immutable patch.

The top-level replay loop dispatches `TASK_INITIALIZED` like every other exact
group. Workspace and replay indexes advance only after the whole group and its
attempt opening have validated. Failed groups do not partially add a task,
attempt head, idempotency row, event identity, or reachable blob.

## Preserved boundaries

- Existing task IDs cannot be initialized again.
- An initialization always uses current repository coordinates; stale task
  exceptions remain exclusive to `GOVERNANCE_BLOCK`.
- Global, transaction, operation-key, event-ID, and event-digest identities
  remain unique across snapshots, imports, and task groups.
- Snapshot/import prefixes and odd/even event positions have no semantic role.
- Unrelated task and attempt history remains byte-identical.
- The public verifier remains disconnected. A valid private replay still
  returns only `UNSUPPORTED / CLOSURE_NOT_COMPILED / DENY`.
- This change adds no database writer, migration, cutover, authority binding,
  STOP clearance, live execution, or capital capability.

## Adversarial evidence required

Tests cover distinct tasks after checkpoint and import prefixes, current versus
stale repository coordinates, odd/even positions, duplicate task selection,
reused transaction identity, hostile host scalar types, exact task/attempt
materializations, and failed-tail non-mutation. The same focused tests must pass
under normal Python and `python -O`.
