# M0.3A portable-component character limit v1

## Status and scope

This additive evidence contract freezes the exact source-level claim required
to classify `_PORTABLE_COMPONENT_MAX`. It does not change runtime behavior,
classify component count or total-path size, complete the resource census,
authorize release generation, establish public-verifier acceptance, clear a
STOP, or authorize execution or capital.

The classification is valid only while the definition, generator comparison,
exact string-and-pattern precondition, slash split, preceding total-path arm,
short-circuit structure, rejection result, enclosing helper and module,
evidence input, predecessor, schema, manifest, and self-digest bindings remain
exact. Missing, stale, aliased, inconsistent, or partially refreshed evidence
fails closed.

## Exact semantic claim

```text
constraint_id: _PORTABLE_COMPONENT_MAX
classification: RESOURCE_MAXIMUM
semantic_subject:
  EXACT_SLASH_SEPARATED_COMPONENT_STRINGS_OF_EXACT_BUILTIN_STR_PATH_AFTER_PATH_PATTERN_AND_TOTAL_PATH_ADMISSION
unit: CHARACTERS
maximum: 255
```

The accepted admission equation is:

```text
for each exact built-in str path admitted by _PATH and the total-path maximum:
    all(len(component) <= 255 for component in path.split("/"))
```

`CHARACTERS` means Python built-in `len()` applied to each exact `str`
component produced by `path.split("/")`. The pinned `_PATH` grammar admits
only ASCII path characters. Separators are not members of a component. This
does not mean encoded bytes, filesystem bytes, component count, split work,
canonicalized paths, resolved paths, or host-platform path units.

The maximum is inclusive. The equation describes admission past the complete
component predicate. On rejection, `any(generator)` stops after the first
oversized component; the contract does not claim that later components were
inspected. Component admission alone does not establish total-path admission;
a path inside the equation's stated domain may still fail later portability
rules.

## Preconditions, traversal, and enforcement order

1. `_pattern` first requires an exact built-in `str` admitted by `_PATH`.
2. The admitted object is retained as `path` and split on the literal `/`.
3. The total-path comparison is the first arm of the exact `or` expression.
4. If total path exceeds 4,096 characters, `or` short-circuits before the
   component generator inspects any component.
5. Otherwise built-in `any()` consumes the exact generator over `components`
   in split order, with no filter or transformation.
6. The generator compares built-in `len(component) > 255` and stops at the
   first true result. Later components need not be inspected on rejection.
7. Any resource overflow raises exact `PATH_LENGTH` at the unchanged caller
   coordinate.
8. Only after both size arms admit do trailing-dot and Windows-device checks
   run. Success returns the exact original path object.

A `str` subclass must be rejected before caller-controlled `__len__` can run.
Syntactically invalid input must be rejected as `PATTERN` before resource
inspection.

## Exact boundary and short-circuit evidence

Dedicated evidence must establish:

- 254- and 255-character components are admitted by this predicate;
- a 256-character component rejects as exact `PATH_LENGTH` while total length
  remains below 4,096;
- first, middle, and last overflowing components reject deterministically;
- multiple 255-character components are admitted and separators are excluded;
- total overflow with individually valid components measures only the path and
  never enters the component generator;
- component overflow measures components only through the first failure;
- complete admission measures every component in split order;
- invalid patterns and hostile `str` subclasses fail before resource work;
- later trailing-dot and device-name failures remain `PATH_PORTABILITY`;
- the exact coordinate and original object identity are preserved; and
- normal and optimized (`-O`) Python agree.

## Required adversarial evidence

The classification must fail closed under attacks that change or bypass the
maximum, comparator, exact `any(GeneratorExp)` form, iterable, target, order,
filter-free traversal, literal slash split, preceding total-path arm,
precondition, rejection, return behavior, or enclosing semantic closure.
Attacks include equivalent-expression and alias substitutions, `>=`, `all`,
materialized collections, sliced/reversed/deduplicated components, generator
filters, transformed components, swapped or bypassed `or` arms, alternate
error code or coordinate, extra loads or stores, and source-level shadowing
of `len`, `any`, `_pattern`, `_PATH`, or `_fail`.

Ordinary source, census, schema, manifest, predecessor, evidence, and
self-digest identities must be refreshable around attacks so the hard semantic
pins remain independently meaningful.

## Explicit exclusions and authority boundary

This contract does not establish total-path size, component count, separator
count, split allocation/work, portability, filesystem behavior, path
ownership, uniqueness, authorization, closure correctness, replay validity,
public-verifier acceptance, release readiness, scientific evidence, strategy
approval, execution, or capital authority.

The cumulative manifest must remain `INCOMPLETE`; generation and authorizing
use remain `DENY`; the resource-inventory blocker remains unconditional; live
remains `LOCKED`; deployable capital remains USD 0; the kill switch remains
engaged; and every OPEN STOP remains OPEN. Any unreproduced identity,
boundary, ordering, short-circuit, adversarial, or authority fact leaves
