# M0.3A schema-bundle byte limit v1

## Status and authority boundary

This document records bounded engineering evidence for the shared
`MAX_SCHEMA_BUNDLE_BYTES = 2,097,152` constant in the private runtime-v2 host
preflight and deny-only verifier. It does not connect the public verifier,
establish whole-image consistency, approve a release, clear a STOP, authorize
paper or live activity, or create capital authority.

The constant has two separate semantic subjects. Reuse of one numeric value
does not make them one object:

1. a field-byte aggregate for the supplied schema registry and supplied schema
   document bodies; and
2. the raw byte length of the supplied storage descriptor at the verifier
   boundary.

It is not a bound on serialized Python objects, parsed JSON memory, the full
runtime image, transport traffic, database size, total retained blobs, or
total accounted host input.

## Host aggregate

`inspect_runtime_image_host` initializes `schema_bundle_bytes` to the length of
the captured schema-registry field only when that field is an exact built-in
`bytes` value; otherwise the registry contributes zero and a type violation is
recorded. After exact tuple cardinality succeeds for `schema_documents`, each
exact `SchemaDocumentRecord` whose `canonical_json` field is exact built-in
`bytes` contributes `len(canonical_json)`. A non-record or non-bytes body is
rejected and contributes nothing. Other fields, including schema IDs, document
digests, the manifest, attachment, events, blobs, and table cells, do not enter
this aggregate.

The comparison is inclusive: an aggregate of 2,097,152 bytes is retained by
this guard; 2,097,153 bytes adds `SCHEMA_BUNDLE_BYTE_LIMIT` and the candidate
image is withheld. Independent per-document and registry bounds still apply.
Passing this guard is not verification or authorization.

## Verifier aggregate

`_schema_bundle_findings` reaches aggregate accounting only after it observes
an exact, nonempty built-in-bytes registry, an exact nonempty tuple of schema
documents, a registry within its separate maximum, and the exact pinned
document count. `raw_total` starts at the registry byte length. Each exact
`SchemaDocumentRecord` with an exact built-in-bytes `canonical_json` body is
added. A non-record or non-bytes body produces a finding and is not added.

The comparison is inclusive: 2,097,152 bytes does not produce
`SCHEMA_BUNDLE_TOO_LARGE`; 2,097,153 bytes does. Other schema identity,
canonicalization, digest, reference-safety, and pin checks remain independent.
No aggregate outcome can return an authorizing result: the verifier remains
`INVALID` or `UNSUPPORTED`, `UNANCHORED`, `UNKNOWN`, and `DENY`.

## Storage-descriptor reuse

`verify_runtime_image` separately applies the same maximum to an exact
built-in-bytes `storage_descriptor`. Exact type validation precedes `len`.
At 2,097,152 bytes the descriptor proceeds to canonical parsing; at 2,097,153
bytes it produces `DESCRIPTOR_TOO_LARGE` and parsing is skipped. This is a raw
descriptor-field ceiling, not schema-bundle accounting.

## Boundary and adversarial evidence

`tests/test_runtime_v2_schema_bundle_byte_bound.py` fixes and exercises:

- host field-byte aggregates at maximum minus one, maximum, and maximum plus
  one;
- verifier field-byte aggregates at the same three boundaries;
- storage-descriptor raw bytes at the same three boundaries;
- exact-record and exact-bytes inclusion, with malformed records and bodies
  excluded from aggregate addition;
- exact type guards before hostile `len` or descriptor parsing;
- independence from unrelated manifest bytes;
- deterministic repeated reports, immutable inputs, withheld invalid host
  images, non-boolean result objects, and `DENY` authority throughout.

The test distributes aggregate bytes across the registry and nine document
bodies without exceeding the separate 262,144-byte per-document maximum. This
isolates the aggregate boundary rather than relying on a per-item failure.

## Fail-closed change discipline

Any change to the definitions, inclusive comparator, registry initialization,
document-body addition, exact type or inventory guards, traversal, diagnostic
action, enforcement order, or the distinction between aggregate and
descriptor subjects requires new versioned evidence and a new classification
version. This evidence cannot clear `STOP-M0-3A-002`; incomplete census
coverage and generation denial must remain explicit until independently
satisfied under the project constitution.
