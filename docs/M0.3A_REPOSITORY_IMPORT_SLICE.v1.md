# M0.3A repository-import replay slice — v1

## Scope

This private slice compiles `IMPORT_REPOSITORY` after cumulative runtime-v2
task replay. It does not connect the public verifier, write SQLite, select a
runtime image, clear `STOP-M0-3A-002`, authorize use, or alter capital state.
Every accepted image therefore still ends as `UNSUPPORTED` with
`CLOSURE_NOT_COMPILED`, `authorizing_use=DENY`, and the existing public safety
boundaries intact.

The group contains zero to 10,000 task-semantic
`REPOSITORY_GENERATION_APPLIED` events in ascending affected-task-ID order,
one runtime-semantic `REPOSITORY_GENERATION_ADVANCED` event, and one
`COMMAND_COMMITTED` event. The reducer checks the complete variable-width
transaction before changing the replay cursor or transition workspace. The
workspace replacement updates repository metadata and all affected task,
claim, and review records as one revision.

## Exact derivation

The request has null subject and expected state. Its top-level repository
coordinates, every envelope, the runtime payload, and the derived metadata row
bind `old_generation + 1` and the request's candidate bundle digest. Task
semantics bind the listed current attempts, exact prior task heads, exact
before-state blobs, transition-derived after-state blobs, and empty applied
payloads. The runtime semantic binds old/new generations, source commit,
project/STOP/policy-capability/task-inventory digests, reason, and the exact
affected list. The response contains the derived affected states in list order
and no generated references. Commit payload semantic IDs include all task
semantics plus the final runtime semantic.

The immutable transition kernel enforces mandatory inclusion of every current
F0, N5, N6, N7, N8, B0, and B1 task; permits selected N0–N4 tasks; rejects C0,
absent, duplicate, or out-of-order tasks; fences active claims and reviews; and
updates every affected task to the new repository generation. Empty import is
allowed only when there is no mandatory task. Unlisted optional tasks remain at
their older generation.

## Atomicity and retained boundaries

The replay cursor prevalidates all identities, transaction keys, task heads,
and the final runtime semantic before mutating any index. It retains every
semantic and commit identity, advances task heads only for task semantics, and
advances repository coordinates only with the fully committed workspace.
Materialized metadata, tasks, attempts, claims, reviews, idempotency, events,
and blob reachability must equal replay exactly; partial materialization fails
closed.

Repository import is terminal in this slice. This permits remediation followed
by import, while preventing ordinary single-task reducers from operating on a
multi-task post-import workspace before the explicit post-remediation task
selection contract is compiled.

The frozen content contract accepts the documented reason-code pattern and
does not require the candidate bundle digest to differ from the previous
digest. The later transactional narrative describes a changed bundle and three
named reasons. This slice follows the frozen content/schema boundary without
silently narrowing it; reconciliation requires a separately versioned contract
decision.

## Adversarial coverage

Tests cover zero-affected import, a two-task post-remediation import, exact
runtime-semantic ordering, repository metadata projection, task-head replay,
wrong envelope coordinates, reordered task semantics, incomplete groups,
partial materialization, post-import trailing groups, hostile event-type host
values, normal Python, and optimized Python. Public verification and capital
authority remain outside this slice.
