# M0.3A runtime-v2 release-generation readiness profile v1

## Status and authority boundary

This profile prepares, but does not perform, exact runtime-v2 dependency-
closure generation. The offline checker at
`tools/check_runtime_v2_release_readiness.py` is read-only. It emits a
deterministic machine-readable inventory and blocker report; it cannot emit a
closure candidate, compile a digest, create a pin carrier, install a selector,
or authorize any action.

The current result is necessarily `BLOCKED / DENY`. The public verifier does
not import the private reducer, the private reducer explicitly returns
`V1_MIGRATION_NOT_SUPPORTED` for the legacy bridge, and no exact independently
accepted A-J evidence manifest is bound by this profile. The current resource
inventory also has no reviewed completeness manifest: it binds named limits,
table ceilings, and four explicitly profiled hard-coded comparison sites, but
does not claim that every semantic resource limit has been enumerated. The
additive resource-discovery profile now makes one finite candidate subset
visible by recording every site in its stated syntactic scope as
`UNCLASSIFIED`; it does not turn a syntactic census into semantic acceptance.
These are semantic and acceptance gaps, not values the generator may waive.
Both the acceptance and resource blockers are unconditional, so editing a
source marker cannot turn this profile into permission to generate.
`STOP-M0-3A-002` remains OPEN; `CLOSURE_NOT_COMPILED` remains the only valid
private terminal finding.

## Eventual generation inputs

The future generator's static local-source closure begins at two fixed
generation roots:

1. `edgelab.runtime_v2_verifier`, the sole contract public entrypoint; and
2. `edgelab.runtime_v2_initial`, the temporarily disconnected private reducer.

It follows repository-relative level-one imports transitively under the sole
root `src/edgelab` and also includes the required `src/edgelab/__init__.py`
package initializer. The additional private root is a generation-only closure
input, not a second public entrypoint. The current union contains the nine
`runtime_v2_*` modules reported by the checker. An unreachable extra runtime
module, case alias, local import outside that
namespace, a statically recognizable direct, aliased, or constant-folded
dynamic-execution primitive, a symlink, a hardlink alias, a path escape, or an
unknown absolute import invalidates readiness. The raw digest still binds any
unrecognized source change; this checker is not a general static proof that
arbitrary Python cannot synthesize dynamic execution.

The checker also derives exact byte lengths and raw SHA-256 values for the five
bootstrap schemas, nine retained schemas, storage descriptor, and retained
schema registry. It parses JSON with duplicate-key and noninteger-number
denial, binds every schema `$id`, and independently derives schema-document,
storage, and registry domain digests. It records no Git state, time, host path,
environment selection, or network result.

The same report derives every currently present `EDGELAB` digest-domain literal
from the closed source AST and inventories named resource constants. Four
hard-coded comparisons are derived from exact operand/operator shapes at
explicit function coordinates; all 15 table-row ceilings are derived from
their `_TableSpec` declarations. These records are useful candidate inputs,
not a complete resource manifest. A reviewed successor must close that
inventory before generation. Fixed runtime assumptions are `CPython` and
Python `3.13`; they are recorded profile expectations, never selected from the
ambient interpreter.

The `resource_inventory_discovery` section follows
`M0.3A_RUNTIME_V2_RESOURCE_DISCOVERY.v4.md`. It preserves all 407 V3 source
sites, including the byte-table and cardinality bindings, then fail-closed
derives fifteen positional `_TABLE_SPECS` row-cap bindings. Each binding fixes
the class, aggregate, helper, strict zipped position, reads, guards, comparator,
diagnostic, accounting/continue flow, enclosing function, and module so a
supplied table label cannot select a different cap. Its closed manifest and
schema bind 422 source-bound AST sites plus every numeric bound keyword in the
fifteen fixed schema inputs. All 718
records remain syntactically `UNCLASSIFIED`, so the resource blocker is
unconditional. The closure schema is a discovery input only; it is not
silently added to the bootstrap or retained schema inventories.

The separate `resource_inventory_classification` section checks
`M0.3A_RUNTIME_V2_RESOURCE_CLASSIFICATION.v19.json` with a pinned closed schema
identity and stricter exact semantic checks. Version 19 byte-binds its complete
V18 predecessor and ancestor chain, preserves all fifteen V18 constraints and
forty-two predecessor-classified site IDs exactly, and appends one narrow
positional `migrations` table-row constraint. The fifteenth preserved
constraint binds the scalar definition to the Discovery V3
branch-specific cardinality record, including the captured subject row, table
assignments, both loops, lookup, validity, result, rejection, enclosing
function, and module identities. It does not classify the equal-valued blobs
table-row ceiling, the per-blob byte ceiling, reachability, accounting, the
shared generic comparator, or any sibling cardinality-table row.

The sixteenth constraint classifies only the Discovery V4 composite site for
the exact rows tuple paired by strict zip with `_TABLE_SPECS[7]`, whose inclusive
maximum is zero. The supplied table label is diagnostic-only and does not select
the cap. The same composite site appears in both definition and enforcement
roles and counts once under set-union accounting. Its helper, aggregate,
generic comparator, V3 outer-cardinality site, fourteen sibling row-cap sites,
descriptor/reducer semantics, public verifier, and migration authority remain
unclassified.

The thirteenth constraint continues to bind the inclusive
2,097,152-byte ceiling to three
separate subjects: the host-preflight registry/document-body aggregate, the
verifier registry/document-body aggregate, and the verifier's standalone
storage-descriptor byte field. The descriptor is not part of either schema
bundle merely because it reuses the same numeric constant. The classification
fixes both scalar definitions and all three direct comparisons, including each
aggregate's exact initialization, record/body inclusion rules, addition order,

Version 19 binds all raw runtime-source identities plus the V4 census digests,
every enclosing semantic function AST, the complete closure/image/transition/
verifier source-module ASTs, and exact contract/test evidence bytes. It fails
closed on source drift;
it does not attest an unpinned interpreter or externally monkeypatched runtime
objects. These classifications do not establish schema
canonicality, digest or pin equality, schema safety, parsed validity, storage-
descriptor validity, retained storage, memory use, authorization, a positive

Its forty-three classified source sites do not reclassify the discovery records
in place; 675 census sites remain semantically unclassified, so
coverage remains `INCOMPLETE`, generation remains `DENY`, and the resource

authority.

## Frozen generation semantics

The eventual pin carrier path is exactly
`src/edgelab/_runtime_v2_release.py`. Its generated block starts with the full
line `# BEGIN GENERATED PIN BLOCK` and ends with the full line
`# END GENERATED PIN BLOCK`, each including its trailing line feed. Exactly one
complete, ordered block is replaced by the ASCII bytes
`PIN_BLOCK_ELIDED_V1`. Zero, partial, reversed, nested, or multiple blocks are
invalid.

Both the carrier `sha256` and `byte_length` closure fields are calculated over
the resulting elided semantic bytes. Final generated carrier bytes are still
required to equal the generator's deterministic full rendering; elision is
not a wildcard for the generated block or for bytes outside it. Any
post-freeze source change requires regeneration and review.

Standard-library classification uses the fixed allowlist `dataclasses`,
`hashlib`, `json`, `re`, and `typing`. `__future__` is a compiler directive and
is recorded separately, not as a runtime dependency. This version requires an
empty external-distribution inventory and performs no package-metadata lookup.
Any external import requires a new versioned profile with an exact metadata
digest equation.

## Checker result

The fixed-root CLI accepts no arguments. It prints one canonical JSON object
and exits `1` for the expected blocked state or `2` for an invalid inspected
tree or caller-selected argument. This version can never exit `0`: its
acceptance blocker can be removed only by a reviewed successor profile with an
exact evidence manifest. A test-only function may inspect an isolated copied
tree but does not affect the CLI root.

The report deliberately contains no closure record, closure digest, carrier
candidate, positive verifier result, or authority-bearing boolean. Its
`authorizing_use` is always `DENY`, and `release_artifacts_written` is always
`false`.
