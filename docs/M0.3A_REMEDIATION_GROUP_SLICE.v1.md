# M0.3A remediation group replay slice — v1

## Scope

The private NEW runtime-v2 image reducer now compiles the terminal
`CREATE_REMEDIATION_TASK` transaction group. The group has exactly three
consecutive envelopes: source `REMEDIATION_CREATED`, child
`TASK_CREATED_FROM_REMEDIATION`, and runtime `COMMAND_COMMITTED`. This slice is
pure replay validation. It writes no database, performs no migration, selects
no runtime, and grants no operational or capital authority.

## Atomic reconstruction

The reducer stages the entire source-task update, child-task creation, and
immutable remediation link against one workspace revision. The workspace
commits the replacement state only after request, response, both semantic
events, both task states, both payloads, the commit event, and every referenced
blob agree. A failed comparison leaves the replay workspace and cursor
unchanged.

The source must be the current N5 or N6 task, have no successor, and carry an
exact retained `REJECT` or `REMEDIATE` decision for the same task and attempt.
The frozen remediation subject is exactly `source_task_id`, `source_attempt`,
`child_task_id`, and `child_attempt=1`; the closed remediation arguments contain
only relationship, decision, child receipt, child owner, and child-owner-role
fields. The request decision digest must equal that retained decision digest. The child
must be absent, distinct, attempt 1, N0, and bound to the request owner, owner
role, decision receipt, current repository generation, and source predecessor.
The source retains its decision state, increments only its scheduler generation,
and points to the child.

The relationship UUID identifies one reciprocal link. Its source/child task
coordinates, semantic event IDs, and decision digest are reconstructed, and its
domain-separated link digest must equal the response generated reference and
the materialized `remediation_links` row. The response state order is source
then child. The source task head advances by one; the child task head opens at
sequence one with the synthetic attempt predecessor. The global head advances
only to the third envelope.

## Bounded follow-up rule

This version deliberately requires remediation to be the final group in the
candidate image. Once the child exists, the workspace contains multiple tasks;
ordinary follow-up selection has not yet been generalized to an explicit task
subject. Any post-remediation envelope is rejected with
`GROUP_REMEDIATION_TERMINAL` rather than guessing which task may advance. A
later version must compile explicit multi-task selection and prove both source
and child head continuity before removing this boundary.

## Fail-closed coverage

Focused adversarial tests cover both permitted decision operations, exact
decision-digest ancestry, reciprocal task/link rows, both task heads, source
and child event order, response state order, generated link digest, partial
materialization, unreachable blobs, incomplete groups, and post-remediation
follow-ups. Normal and optimized-Python runs exercise the same assertions.

The public verifier remains disconnected and returns only
`UNSUPPORTED/CLOSURE_NOT_COMPILED` for a valid private replay. The metadata
carrier remains `authorizing_use=DENY`; live status remains LOCKED; the kill
switch and every OPEN STOP remain unchanged.
