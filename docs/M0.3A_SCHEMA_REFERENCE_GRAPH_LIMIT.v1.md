# M0.3A Schema Reference-Graph Node Limit v1

**Status:** Additive, deny-only evidence for the published runtime-v2 verifier.

**Scope:** The local `$defs` reference graph constructed by
`_schema_safety_findings`; this document does not amend an earlier pinned
contract and does not publish a runtime closure or carrier.

## 1. Exact bounded quantity

For a schema document that reaches graph-cardinality evaluation, let
`edges` be the verifier's graph map and let:

```text
schema_reference_graph_nodes = len(edges)
MAX_SCHEMA_REF_NODES = 4096
accepted_by_this_one_guard <=> schema_reference_graph_nodes <= 4096
```

An `edges` key is created exactly once for each valid name in the root
`$defs` object. A valid name is a non-empty string of at most 64 characters,
starts with an ASCII letter, and otherwise contains only ASCII letters,
digits, `_`, or `-`.

The count deliberately excludes:

- invalid root `$defs` names, which instead produce `SCHEMA_DEF_NAME`;
- local `$ref` targets that are not themselves valid root `$defs` names;
- dangling target strings, which instead produce `SCHEMA_REF_DANGLING` and
  do not materialize graph keys;
- schema objects, arrays, keywords, references, and edges as such; and
- any schema document whose earlier diagnostics exhaust the finding budget
  before graph cardinality is evaluated.

The inclusive boundary is therefore 4096 materialized graph-node keys.
Exactly 4097 keys produces:

```text
VerificationFinding(
    code="SCHEMA_REF_GRAPH_TOO_LARGE",
    artifact=<the supplied schema_id>,
    coordinate="/$defs",
)
```

## 2. Evaluation order and short circuits

The verifier performs the relevant work in this order:

1. It checks the top-level schema object, dialect, identifier, and root
   `$defs` type.
2. It walks the non-`$defs` portion of the schema for profile diagnostics.
3. In root `$defs` insertion order, it validates each definition name,
   materializes a graph key for each valid name, and walks that definition to
   collect local reference targets and diagnostics.
4. It evaluates `len(edges) > MAX_SCHEMA_REF_NODES`.
5. When the comparison is true, it adds
   `SCHEMA_REF_GRAPH_TOO_LARGE` and returns immediately.
6. Only when the comparison is false does it sort graph keys and begin the
   iterative depth-first cycle traversal.

The finding budget is an earlier fail-closed diagnostic short circuit. If it
is full during steps 1–3, `_schema_safety_findings` returns the diagnostics
already collected without evaluating this cardinality guard and without
requiring a graph-size finding. Those diagnostics still make the public
verifier result `INVALID`. This profile makes no claim that the schema walk or
graph construction preceding step 4 is bounded by 4096.

## 3. Boundary evidence

The adversarial evidence uses the first pinned schema identifier and otherwise
minimal definitions of the form `"n0000":{"type":"null"}`. The canonical
document and complete pinned-bundle byte counts remain below their separate
published byte limits:

| graph keys | canonical document bytes | complete bundle bytes | graph finding |
|---:|---:|---:|:---|
| 4095 | 98,392 | 150,378 | absent |
| 4096 | 98,416 | 150,402 | absent |
| 4097 | 98,440 | 150,426 | `SCHEMA_REF_GRAPH_TOO_LARGE` |

The public-verifier cases necessarily also report
`SCHEMA_DOCUMENT_DIGEST_MISMATCH`, because an adversarial boundary document is
not the pinned document bytes. The 4097 case adds the graph-size finding. All
three public results are `INVALID`, have `authorizing_use == "DENY"`, and
raise `TypeError` if coerced to a Boolean.

Additional evidence establishes that an invalid definition name and a
dangling target do not inflate the graph-node count, that diagnostic-budget
exhaustion returns its earlier exact finding, and that the 4097-node branch
returns before the DFS sorting operation is reached.

## 4. Explicit exclusions

This limit alone does not establish or imply:

- schema canonicality, digest correctness, profile validity, acyclicity, or
  semantic validity;
- schema-registry identity, document-inventory identity, bundle validity, or
  bundle acceptance;
- a bound on schema bytes, bundle bytes, number of references, number of
  edges, traversal work before cardinality evaluation, or diagnostic count;
- runtime dependency-closure completeness, compiled identity, carrier
  publication, reducer correctness, or independent acceptance; or
- permission to clear a STOP, promote a strategy, unlock capital, or perform
  any live action.

Passing this one inclusive comparison is not a positive verdict. The public
verifier remains closed to `INVALID` or `UNSUPPORTED`, remains DENY-only, and
cannot be used as an authorization Boolean. This evidence neither changes
runtime source nor expands operational authority.

## 5. Falsification conditions

This evidence must be rejected or versioned if any of the following becomes
true:

- 4096 valid root definitions produces the graph-size finding;
- 4097 valid root definitions fails to produce that finding;
- invalid names or dangling targets become additional graph keys;
- the oversized branch reaches DFS before returning;
- an earlier exhausted diagnostic budget is ignored; or
- the public result becomes authorizing, Boolean-coercible, or anything other
  than fail-closed for these adversarial documents.
