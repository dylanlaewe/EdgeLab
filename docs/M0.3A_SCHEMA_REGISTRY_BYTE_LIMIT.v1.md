# M0.3A schema-registry byte limit v1

## Status and scope

This additive evidence contract freezes the exact source-level claim required
to classify `MAX_SCHEMA_REGISTRY_BYTES`. It does not change either runtime
implementation, classify any other constraint, complete the resource census,
authorize release generation, establish public-verifier acceptance, clear a
STOP, or authorize execution or capital.

The classification is valid only while every definition, enforcement site,
branch binding, enclosing function and module, evidence input, predecessor,
schema, manifest, and self-digest binding remains exact. Missing, stale,
aliased, inconsistent, or partially refreshed evidence fails closed.

## Exact semantic claim

```text
constraint_id: MAX_SCHEMA_REGISTRY_BYTES
classification: RESOURCE_MAXIMUM
semantic_subject:
  EXACT_BUILTIN_BYTES_SCHEMA_REGISTRY_FIELDS_SUPPLIED_TO_HOST_PREFLIGHT_OR_VERIFIER_BUNDLE_INSPECTION
unit: BYTES
maximum: 262,144
```

There are two implementation-specific equations:

```text
host preflight, after exact field capture and the exact-bytes guard:

    len(captured["schema_registry"]) <= 262,144

verifier bundle inspection, after registry and document presence guards:

    len(image.schema_registry) <= 262,144
```

The subject in each equation is the exact supplied built-in `bytes` value in
that implementation's `RuntimeImage.schema_registry` field. `BYTES` means
Python byte length as measured by `len()` at the bound source layer. It does
not mean decoded characters, parsed JSON size, canonical object size, schema
count, retained database size, memory footprint, or registry-plus-document
bundle size.

The two modules define distinct immutable `RuntimeImage` host classes and
distinct entry paths. This claim does not invent an identity or mandatory
pipeline between those classes. It states only that both bound source
implementations apply the same inclusive byte maximum to their own exact
supplied schema-registry field.

## Preconditions and enforcement order

### Host preflight

`src/edgelab/runtime_v2_image.py:inspect_runtime_image_host` reaches the
schema-registry comparison only through this order:

1. Require the candidate to have the exact host `RuntimeImage` type.
2. Read every required slot into the closed `captured` mapping without a
   caller-selected fallback.
3. Require all fields to be present.
4. Select the literal `schema_registry` row from the fixed `byte_fields`
   tuple.
5. Require the field to have exact built-in type `bytes`.
6. Add its exact byte length to separate bounded aggregate accounting.
7. Apply the inclusive per-field equation above.
8. On overflow, add `IMAGE_ITEM_BYTE_LIMIT` for artifact
   `schema_registry`, coordinate `/`.
9. If any violation exists, withhold the sanitized image. Otherwise, preserve
   the exact supplied bytes in the sanitized image.

The aggregate-accounting operation is an ordering dependency, not part of the
classified maximum. This contract does not classify the aggregate ceiling.

### Verifier bundle inspection

`src/edgelab/runtime_v2_verifier.py:_schema_bundle_findings` reaches the
comparison only through this order:

1. Determine registry presence using exact built-in `bytes` type and
   nonemptiness.
2. Determine document presence using exact built-in `tuple` type and
   nonemptiness.
3. Reject a missing or incomplete pair before size inspection.
4. Apply the inclusive schema-registry byte equation.
5. On overflow, add `SCHEMA_REGISTRY_TOO_LARGE` for artifact
   `schema_registry`, coordinate `/`, and return an invalid bundle before
   document inventory, bundle accounting, registry parsing, schema safety,
   digest comparison, or pin comparison.
6. Only a size-admitted registry may continue to those independent checks.

`verify_runtime_image` remains the public pure verifier entrypoint. It
propagates bundle findings into a non-authorizing result. Passing this size
guard alone never establishes a valid or supported registry.

## Exact boundary acceptance matrices

Let `M = 262,144`.

### Host-preflight matrix

Use an otherwise valid host-preflight fixture with an exact built-in `bytes`
schema-registry field.

| Case | Exact supplied length | Required size-bound result |
| --- | ---: | --- |
| maximum minus one | `M - 1` | no `IMAGE_ITEM_BYTE_LIMIT` for `schema_registry`; retain the exact supplied bytes when no unrelated violation exists |
| maximum | `M` | no `IMAGE_ITEM_BYTE_LIMIT` for `schema_registry`; retain the exact supplied bytes when no unrelated violation exists |
| maximum plus one | `M + 1` | exact `IMAGE_ITEM_BYTE_LIMIT`, artifact `schema_registry`, coordinate `/`; withhold the sanitized image |

Every result remains `DENY` and non-Boolean. Accepted-by-size bytes must not
be truncated, sampled, copied into a different value, decoded, parsed, or
reordered. A non-`bytes` field must be rejected by the field-type rule without
invoking its caller-controlled `__len__`.

### Verifier matrix

Use an exact verifier `RuntimeImage`, a nonempty exact tuple of fixed schema
documents, and an exact built-in `bytes` schema-registry field. Later registry
validity may deliberately fail; the matrix isolates only the byte guard.

| Case | Exact supplied length | Required size-bound result |
| --- | ---: | --- |
| maximum minus one | `M - 1` | no `SCHEMA_REGISTRY_TOO_LARGE`; execution reaches a later independent bundle check |
| maximum | `M` | no `SCHEMA_REGISTRY_TOO_LARGE`; execution reaches a later independent bundle check |
| maximum plus one | `M + 1` | exact `SCHEMA_REGISTRY_TOO_LARGE`, artifact `schema_registry`, coordinate `/`; bundle result is invalid before document inventory or parsing |

The public result remains non-Boolean and `DENY` in every case. An empty or
wrong-type registry, or an empty or wrong-type document collection, must be
handled by the presence/type boundary before the registry byte comparison.
Normal and optimized (`-O`) execution must reproduce both matrices.

## Explicit exclusions

This contract does not establish or classify:

- registry JSON syntax, canonicality, schema shape, `$id` inventory, reference
  safety, schema safety, registry digest, compiled pin equality, or semantic
  validity;
- whether any registry is the published or supported registry;
- schema-document size, schema-document count, total schema-bundle bytes, or
  any relationship between registry and document byte totals;
- the storage-descriptor byte check, despite its current reuse of
  `MAX_SCHEMA_BUNDLE_BYTES`;
- the `schema_registry` materialized table, its singleton row, or any table
  cardinality;
- total accounted input, root work, retained storage, database size, decoded
  character length, or memory use;
- the shared host comparator, dependency closure, manifest, attachment,
  checkpoint-copy, selector-history, or any sibling row;
- public-verifier acceptance, a positive consistency result, reducer
  implementation, release-generation readiness, or inventory completeness;
  or
- behavior of an unpinned interpreter or externally monkeypatched runtime.

In particular, admission by the byte guard is not support. Later independent
checks are expected to reject boundary-shaped registry bytes that are not the
exact compiled registry.
