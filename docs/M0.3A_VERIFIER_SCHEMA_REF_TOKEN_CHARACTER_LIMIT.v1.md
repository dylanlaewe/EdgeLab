# Runtime-v2 verifier schema-reference token character limit

Status: bounded deny-only classification evidence

## Exact subject

This evidence classifies only the lexical character ceiling for the local
JSON Schema reference token extracted by
`runtime_v2_verifier._schema_safety_findings.walk`.

The verifier first requires the referenced value to be an exact `str` whose
spelling starts with `#/$defs/`, then derives `token = child[8:]`. Within the
existing compound profile check, `len(token) <= 64` is accepted and
`len(token) > 64` adds `SCHEMA_REF_OUTSIDE_PROFILE` at the exact child path.
The unit is Python string characters.

## Bound source shape

The classification binds the exact `#/$defs/` prefix, exact-string type gate,
`startswith` gate, eight-character slice, strict `len(token) > 64`
comparison, enclosing compound condition, diagnostic call, nested `walk`
function, enclosing `_schema_safety_findings` function, and complete verifier
module AST.

The diagnostic budget remains authoritative: if the finding limit is already
full, traversal returns before this token is inspected. Existing valid targets
of one, 63, and 64 characters remain accepted; a 65-character token is outside
the profile.

Changing the prefix, type gate, startswith gate, slice, comparator, literal,
condition order or membership, diagnostic code or coordinate, traversal
shape, function, or module invalidates the evidence. Duplicate, missing,
substituted, census-refreshed, predecessor-rewritten, or ancestor-rewritten
sites remain fail-closed.
