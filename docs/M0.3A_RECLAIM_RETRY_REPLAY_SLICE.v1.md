# M0.3A repeated claim and retry replay slice v1

## Scope

This private slice extends runtime-v2 NEW-image replay through repeated
`CLAIM` groups and exact `RETRY` groups. It compiles no governance, review,
route, remediation, repository-import, checkpoint, or export group, and it
adds no positive public-verifier result. Candidate events, blobs, and
materialized rows remain untrusted comparison inputs.

## Closed dispatch

After `INITIALIZE`, every semantic/commit pair is dispatched only by its exact
semantic event type. `CLAIM_ISSUED` enters the claim reducer. Event types in
the fixed worker profile enter the worker reducer, including `TASK_RETRIED`.
All unknown, non-string, or otherwise uncompiled event types fail closed.
Dispatch does not infer an operation from candidate state or request payloads.

Repeated `CLAIM` is accepted only when the transition workspace's current task
is `N0`. Its semantic task context advances the exact retained head for the
current attempt. Claim identity, scope, fence, and status are derived by the
claim reducer and committed atomically with the task transition.

## Exact retry boundary

`RETRY` consumes a current failed task at attempt `n`. The request subject and
`state_before_ref` therefore bind attempt `n`, and the transition arguments
must contain only a canonical evidence digest plus the literal boolean
`retryable: true`.

The shared transition-workspace planner derives `F0(n) -> N0(n + 1)`. It
increments scheduler generation, dispatch generation, and task fence; resets
continuation count; clears claim and reviewer assignment; and writes no claim
row. The semantic task context and `state_after_ref` bind the newly opened
attempt `n + 1`, whose task sequence is 1 and whose predecessor is the exact
derived attempt-root identity for `n + 1`.

The cursor retains attempt `n` headed by its accepted `TASK_FAILED` event and
opens attempt `n + 1` only after whole-group validation. Opening also requires
the contiguous predecessor attempt and the exact derived root. A skipped,
duplicated, stale, cross-attempt, or forged retry cannot rewrite prior attempt
or claim history.

## Atomicity and assurance

The immutable transition kernel and transition workspace share the same retry
planner. Group validation stages the task delta, validates the new-attempt
semantic context, candidate after-state, response, commit, and historical
tables, and only then commits cursor and workspace mutation. Rejected groups
leave both owners unchanged.

Adversarial coverage includes recovery followed by re-claim, yield followed by
re-claim, repeated fail/retry/claim cycles, wrong attempt contexts, skipped
attempts, wrong roots and predecessors, stale request subjects, non-literal
retry flags, malformed evidence, wrong retry/re-claim source states, and
omitted, reordered, or rewritten cumulative attempt and claim rows. The same
focused suite must pass with assertions enabled and under optimized Python.
