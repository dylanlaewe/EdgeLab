# M0.3A CLAIM transaction slice v1

## Status

This document records the second private ordinary transaction-group slice of
the runtime-format-2 reducer. It is an incremental engineering boundary, not a
whole-image verifier release.

The slice is pure, deny-only, and disconnected from the public verifier. A
candidate that passes every compiled check remains opaque as
`UNSUPPORTED / CLOSURE_NOT_COMPILED / DENY`.

## Compiled profile

The profile now accepts exactly one of these NEW-runtime shapes:

1. The compiled sequence-zero `RUNTIME_GENESIS` image.
2. That genesis followed by one two-event `INITIALIZE` transaction.
3. That initialized image followed by one two-event `CLAIM` transaction:
   `CLAIM_ISSUED`, then `COMMAND_COMMITTED`.

For the third shape, the reducer first replays and validates the complete
genesis and `INITIALIZE` prefix. It then independently checks:

- contiguous global sequence and predecessor links from the prior commit;
- the exact task-attempt sequence-two predecessor link to `TASK_INITIALIZED`;
- event, transaction, and operation-key uniqueness across the retained prefix;
- exact two-event transaction grammar, shared coordinates, UTC-second time,
  semantic-then-commit ordering, and closed event positions;
- closed `CLAIM` request, response, payload, commit payload, and task-state
  content without runtime JSON Schema execution;
- runtime, chain, repository, operation, operation-key, subject, actor,
  request, response, payload, before-state, after-state, claim identity, and
  commit cross-bindings;
- exact equality between the supplied before-state and the state derived from
  the validated prefix;
- independent post-state and claim derivation through `reduce_transition`,
  followed by exact comparisons to supplied state and response documents;
- typed reachability of every genesis, initialization, and claim blob, with no
  extra supplied blob accepted;
- exact events, attempts, claims, idempotency, tasks, metadata, bootstrap,
  schema, and seal rows across all 15 supplied table snapshots.

Candidate state, generated references, and table snapshots remain
comparison-only. They never drive replay. The claim patch is returned only
after all group checks pass, so a late failure cannot publish partial task,
claim, attempt, or idempotency state.

## Explicit exclusions

This version does not support `START`, `YIELD`, review, completion, retry,
recovery, later task operations, remediation, repository imports, checkpoints,
exports, checkpoint copies, legacy bridge reduction, historical root-work
charging, exact release-closure generation, a writer, a database, selector
cutover, a positive consistency result, or any authority or capital path.

The public verifier remains intentionally unaware of the private reducer. No
valid private fixture can be interpreted as permission to execute work, place
a wager, unlock capital, or clear a STOP.

## Next implementation boundary

Extract the common ordinary-group grammar and projection accumulator before
adding the remaining single-semantic task operations. Then implement the
two-event remediation and variable-cardinality import groups. Export and
checkpoint cuts may be added only after their pre-registration state roots can
be derived from complete ordinary replay. Exact closure generation remains
deferred until every semantic source is frozen and independently accepted.
