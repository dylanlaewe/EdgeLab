# Authentic capture format v1

A capture is internally intact only when its inventory, package hashes, result digest, and source graph agree. It is authentic only when it also matches `M0-2-STAGE1-TRUST-ROOT-V1`; captures cannot declare or replace that root. This is repository-authoritative planning trust, not KMS/HSM or external authentication; that limitation remains under `STOP-M0-001`.

Each capture is a closed typed record: metadata/root reference, Git observations, repository inventory, typed intent/result bytes, source records, scheduler/task/assignment/handoff/project/STOP/capability/dependency/completion evidence, module/schema/package records, engine binding, directory inventories, and self digest. FILE becomes an artifact plus SHA-256 blob; DIRECTORY becomes sorted inventory evidence; ABSENT is a tagged absence record. Mapping is deterministic: relative path is the artifact identity, bytes are the blob, and sorted canonical JSON supplies every digest. No consumer may choose another representation.

Verification order: schema; self-integrity; trusted root; frozen module/schema equality; exact unique package name/version/digest closure; structurally valid Git observations; compatible CPython/ABI and checked Git boundary; exact replay. Only all stages produce `HISTORICALLY_VALID`; root mismatch is `INVALID`. Git observations describe historical state, while freeze identity must equal the trusted root. Host Git is resolved once by absolute path; only the documented environment allowlist is passed, and incompatible runtimes return `INCOMPATIBLE`.
