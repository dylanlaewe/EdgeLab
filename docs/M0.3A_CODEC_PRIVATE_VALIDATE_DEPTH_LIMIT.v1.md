# M0.3A private codec validation-depth limit

## Scope

Classification V41 records one already-enforced maximum in the private codec
validator: the internal `depth` argument to `_validate` may be at most 128
levels. The exact overlapping definition and enforcement site is the strict
`depth > 128` comparison.

## Complete semantic slice

At entry to `_validate`, `depth <= 128` passes the guard. `depth > 128` raises
`CanonicalJsonError("MAX_DEPTH_EXCEEDED")` before scalar dispatch, container
cycle handling, or recursive traversal. Direct private calls at 127 and 128
therefore pass for a supported scalar, while 129 rejects. Recursive list values
whose deepest scalar is reached at depth 128 pass; reaching it at depth 129
rejects.

The comparison, enclosing guard, exact error construction, private function,
codec module, two root callers, and recursive list/dictionary value and key
calls are pinned separately. The default `depth = 0` site is context only and
remains unclassified.

## Deliberate nonclaims

This constraint classifies only the private `_validate` internal depth
argument. It does not classify the default-depth site or negative depths and
does not claim a public or canonical-JSON structural-depth contract, parser
rejection semantics, complete recursive traversal, schema/reducer/image
validity, STOP clearance, execution authority, or capital authority.

Classification V41 does not create Discovery V8 or complete the 721-site
census. It remains `INCOMPLETE` / `DENY` with the same four release blockers.

predecessor-prefix difference is a strictly enumerated evidence-only refresh
