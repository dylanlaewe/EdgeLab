# M0.3A transition-argument limit v1

## Status and scope

This additive evidence contract freezes the exact source-level claim required
to classify `MAX_ARGUMENTS`. It does not change runtime behavior, classify a
sibling constraint, complete the resource census, authorize release
generation, establish public-verifier acceptance, clear a STOP, or authorize
execution or capital.

The classification is valid only while the definition, enforcement site,
container-type guard, rejection result, enclosing initializer and module,
evidence input, predecessor, schema, manifest, and self-digest bindings remain
exact. Missing, stale, aliased, inconsistent, or partially refreshed evidence
fails closed.

## Exact semantic claim

```text
constraint_id: MAX_ARGUMENTS
classification: RESOURCE_MAXIMUM
semantic_subject:
  EXACT_BUILTIN_TUPLE_ARGUMENT_ITEMS_SUPPLIED_TO_TRANSITION_INTENT_CONSTRUCTION
unit: ITEMS
maximum: 8
```

The accepted equation is:

```text
for TransitionIntent.arguments having exact built-in type tuple:
    len(arguments) <= 8
```

`ITEMS` means the exact tuple cardinality measured by built-in `len()` at the
private transition-intent construction boundary. It does not mean the number
of operation-specific arguments later consumed, the number of unique keys,
the number of valid `(key, value)` pairs, decoded size, serialized size,
retained table rows, or `semantic_event_ids` cardinality. The maximum is
inclusive. Member shape, key ordering, and key uniqueness are separate
validity rules evaluated after this resource bound.

## Preconditions and enforcement order

The resource check is reached only through this order:

1. Construct the private frozen `TransitionIntent` value.
2. Require `operation` to have exact built-in type `str`.
3. Require both `arguments` and `semantic_event_ids` to have exact built-in
   type `tuple`.
4. Measure the exact supplied `arguments` tuple cardinality.
5. Apply the inclusive eight-item equation.
6. On overflow, raise `TransitionViolation` with exact code
   `TRANSITION_RESOURCE_ARGUMENTS` and exact coordinate `/arguments`.
7. Only after size admission, apply the independent
   `MAX_GROUP_EVENTS` bound, argument-member shape, key ordering, and key
   uniqueness checks.
8. When all independent rules pass, retain the exact supplied arguments tuple
   without truncation, sampling, copying, substitution, or reordering.

A tuple subclass is not an exact built-in tuple. It must be rejected by the
container guard before its caller-controlled `__len__` can run. Conversely,
an oversized exact tuple must be rejected for cardinality before any malformed
member can be inspected or relabeled as an argument-shape failure.

## Exact boundary acceptance matrix

Let `M = 8`. Dedicated evidence must apply this matrix using an otherwise
valid `TransitionIntent` fixture and exact built-in tuples of sorted, unique,
well-shaped `(str, value)` pairs.

| Case | Exact supplied cardinality | Required result |
| --- | ---: | --- |
| maximum minus one | `M - 1` | construction succeeds and retains the exact supplied tuple |
| maximum | `M` | construction succeeds and retains the exact supplied tuple |
| maximum plus one | `M + 1` | exact `TRANSITION_RESOURCE_ARGUMENTS:/arguments` rejection |

Evidence must additionally establish that:

- admitted tuples are retained by identity and value, without truncation,
  sampling, replacement, copying, or reordering;
- a tuple subclass with hostile `__len__` is rejected as
  `TRANSITION_CONTAINER_TYPE:/` without executing that method;
- an exact nine-member tuple containing malformed members is rejected by the
  resource bound before member-shape inspection;
- an exact eight-member tuple containing malformed members is size-admitted
  and then rejected by `TRANSITION_ARGUMENT_SHAPE:/arguments`;
- the rejection code and coordinate are stable across repeated executions;
- the argument allowance is independent of the sibling
  `semantic_event_ids` subject; and
- normal and optimized (`-O`) Python produce the same result.

## Required adversarial evidence

The classification must fail closed under attacks that alter or bypass any
part of its semantic dependency closure, including:

- changing the maximum, replacing it with a literal or alias, or adding an
  additional load or store of `MAX_ARGUMENTS`;
- substituting another maximum or a currently equal-valued expression;
- changing `>` to `>=`, reversing or negating the comparison, measuring a
  transformed value, or comparing a subject other than `self.arguments`;
- deleting, duplicating, relocating, wrapping, or conditionally bypassing the
  enforcement branch;
- weakening, deleting, or moving the exact built-in tuple guard after the
  cardinality inspection;
- suppressing, catching, renaming, redirecting, or changing the code or
  coordinate of the `TransitionViolation`;
- truncating, slicing, copying, substituting, or reordering an admitted tuple;
- conflating member validity, key uniqueness, event cardinality, or an
  operation-specific key set with this resource maximum;
- shadowing or replacing `len` in the bound source closure;
- treating successful private value construction as verifier acceptance or
  operational authority; or
- refreshing ordinary source, census, schema, manifest, predecessor, or
  self-digests around a semantic mutation.

Attacker-controlled ordinary identities must be refreshable in adversarial
tests so the hard-pinned definition, comparator, guard, function, class,
module, evidence, predecessor, and exact-manifest checks remain independently
meaningful.

## Explicit exclusions

  operation validity, or transition validity;
- `MAX_GROUP_EVENTS`, `MAX_EVENTS`, `MAX_TASKS`, or any other sibling
  constraint;

- public-verifier support or acceptance, replay validity, strategy evidence,
  authority, or whole-image reducer semantics;
- release-generation readiness or completeness of the resource census; or
- behavior under an unpinned interpreter or external monkeypatching.
