# M0.3A CONTINUE transaction slice v1

## Status

This document records the fourth private ordinary transaction-group increment
of the runtime-format-2 reducer. It extends the previously compiled
NEW-genesis, `INITIALIZE`, `CLAIM`, and `START` prefix by exactly one
`CONTINUE` group. It is not a whole-image verifier release.

The slice is pure, deny-only, and disconnected from the public verifier. A
candidate that passes every compiled check remains opaque as
`UNSUPPORTED / CLOSURE_NOT_COMPILED / DENY`.

## Compiled transition

`CONTINUE` is valid only for an `IN_PROGRESS` task with the matching active
claim ID and fence. Its closed request arguments are:

- `claim_id`;
- `fence`;
- `progress_evidence_sha256`.

The immutable transition increments the task continuation count and scheduler
generation while preserving the active OPEN claim, attempt, fence, execution
state, dispatch generation, and every unrelated field.

## Replay boundary

The shared worker reducer independently derives and validates:

- exact global and task-local predecessor chains;
- transaction, operation-key, event-ID, and event-digest uniqueness;
- runtime, repository, request, response, and commit cross-bindings;
- prefix-derived before-state and claim/fence compare-and-swap;
- closed operation arguments and an empty semantic payload;
- exact after-state, attempt head, claim history, idempotency row, task row,
  metadata head, typed reachability, and all 15 table projections.

Supplied state and tables are comparison-only. Adversarial changes to the
continuation count in either the retained state or projected task row fail
closed. No partial patch can be published after a late validation failure.

## Explicit exclusions

This version compiles only one bounded `CONTINUE` after `START`. It does not
compile repeated continuations, `FAIL`, `COMPLETE`, `RECOVER`, `RETRY`, later
claim cycles, governance, review, route, remediation, repository import,
checkpoint, or export groups. It adds no writer, database, selector cutover,
currentness claim, positive consistency result, authority, execution, or
capital path.

## Next boundary

Extend the reusable worker reducer through the claim-closing `FAIL` and
`COMPLETE` operations, then `RECOVER`, retry, and repeated claim cycles while
preserving every historical claim and attempt projection.
