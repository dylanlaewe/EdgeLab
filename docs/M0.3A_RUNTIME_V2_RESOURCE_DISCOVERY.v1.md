# M0.3A runtime-v2 resource-bound discovery profile v1

## Status

This profile is a deterministic discovery census, not the reviewed semantic
resource manifest required for release generation. It expands the deny-only
readiness checker with fixed-input source and JSON-Schema bound-site
inventories so that this current syntactic candidate subset is finite,
reproducible, and sensitive to drift.
Every discovered site is deliberately `UNCLASSIFIED`, and coverage is
explicitly `INCOMPLETE`.

The profile cannot remove `RESOURCE_INVENTORY_INCOMPLETE`, emit a dependency
closure or carrier, connect the public verifier, clear a STOP, or authorize
execution. Its current fixed-root result contains 394 source-bound candidates
and 296 schema-bound candidates across 15 schemas. Counts are observations of
the current frozen input candidates, not contractual promises that future
source versions retain the same counts.

## Source discovery

The checker parses the ten prospective runtime-v2 source artifacts from the
same stable byte snapshots used by the release-readiness inventory. It records
the following syntactic classes:

- module-level assignments whose value contains an integer or uppercase bound
  name;
- comparisons containing an integer, uppercase bound name, or `len()` call;
- calls to the fixed helper set `_array`, `_integer`, `_string`, `_strict_int`,
  `_TableSpec`, `bounded`, and `range` when a numeric/bound signal is present;
- numeric function defaults and slices; and
- `re.compile` patterns with explicit numeric quantifiers.

Each record binds the repository-relative path, enclosing qualified name,
node kind, normalized `ast.dump(..., include_attributes=False)` SHA-256,
same-shape occurrence ordinal, diagnostic line, unparsed expression, and a
domain-separated site ID. The line number is never identity. Adding, removing,
or changing a discovered expression changes the census digest.
Function-default records additionally bind the owning parameter name.

This is intentionally a syntactic over-approximation. Arbitrary Python makes
open-ended semantic completeness undecidable. A successor reviewed manifest
must classify each site and separately prove that its discovery rules cover
all contract-relevant enforcement mechanisms; source hashing alone is not a
completeness proof.

## Schema discovery

The checker uses the already audited bytes of the five bootstrap and nine
retained schemas and adds the dependency-closure schema as a fifteenth fixed
input. It recursively inventories every integer-valued occurrence of:

`minimum`, `maximum`, `exclusiveMinimum`, `exclusiveMaximum`, `minLength`,
`maxLength`, `minItems`, `maxItems`, `minProperties`, `maxProperties`,
`minContains`, and `maxContains`.

Each record binds schema ID, raw schema path, escaped JSON pointer, keyword,
integer value, and `UNCLASSIFIED`. The complete canonical record list and the
15 raw schema identities receive domain-separated digests. Numeric `const`
values, regex grammar, enums, and nonnumeric schema semantics are not silently
called resource limits; a successor classification manifest must retain them
as separately reviewed protocol/representation constraints where relevant.
The two content assets are not treated as JSON Schemas; numeric descriptor
semantics such as storage `integer_max` remain explicitly outside this
discovery scope and must be reconciled by the successor coverage proof.

## Required successor classification

The reviewed successor must partition every discovered site exactly once as a
resource maximum, diagnostic ceiling, representation/domain constraint,
protocol exact/minimum/relational constraint, calendar/encoding rule, or
explicit non-resource site. Every resource/diagnostic limit must bind all of
its definitions and enforcement coordinates, agree across source and schema
copies, carry a closure-compatible nonnegative maximum and unit, and cite its
contract equation.

Relations such as import affected/events/group counts, selector count versus
checkpoint copies, exact schema/table cardinality, total accounted input, and
cumulative root work require explicit equations and boundary evidence rather
than scalar relabeling. `INT64_MIN`, minima, exact grammar cardinalities, and
other values unrepresentable by the closure v1 nonnegative `maximum` field
must remain separately classified.

This census is only a candidate lower bound. The semantic completeness gap is
not known to be finite until a reviewed successor proves coverage of every
enforcement mechanism and descriptor/contract constraint.

Any unclassified, stale, duplicate, aliased, inconsistent, or unrepresentable
site keeps the readiness result `BLOCKED / DENY`. No closure or carrier may be
generated until the partition, equations, independent adversarial review, and
the other release blockers are complete.

## First semantic classification slice

`M0.3A_RUNTIME_V2_RESOURCE_CLASSIFICATION.v1.json` is the first deliberately
small classification slice. It classifies only the inclusive
`MAX_DEPENDENCY_CLOSURE_BYTES` maximum: one definition site and the one
`len(raw) > MAX_DEPENDENCY_CLOSURE_BYTES` rejection guard. Boundary evidence
distinguishes maximum-minus-one, maximum, and maximum-plus-one behavior.

The closed manifest self-digests canonically and binds the raw identities of
all ten runtime source inputs, both complete discovery-census digests, and the
fifteen-schema input digest. It also binds the exact classification schema,
the enclosing validator-function AST, its complete module AST semantic
dependency closure, and the contract/test evidence bytes.
Any drift makes the inspected tree invalid until the classification is
reviewed and republished. The two classified source
sites remain syntactically labeled `UNCLASSIFIED` in the discovery census;
the separate semantic manifest is the sole classification record.

This slice leaves 688 census sites semantically unclassified. Coverage remains
`INCOMPLETE`, generation remains `DENY`, and
`RESOURCE_INVENTORY_INCOMPLETE` remains unconditional. In particular, no
minimum, negative bound, exact cardinality, diagnostic ceiling,
representation limit, or relational equation is broadened into a resource
maximum by this manifest.

## Second semantic classification slice

`M0.3A_RUNTIME_V2_RESOURCE_CLASSIFICATION.v2.json` preserves and byte-binds
the complete v1 manifest/schema, then adds only `MAX_BLOB_BYTES`. The new
classification is the inclusive 16,777,216-byte ceiling over the exact
captured `BlobRecord.canonical_json` bytes supplied to the host image
preflight. It does not claim that those bytes have already been parsed or
proven canonical at this layer.

The v2 manifest binds the exact definition and enforcement sites, the whole
`runtime_v2_image.py` source-module AST, the `inspect_runtime_image_host`
function AST, both governing contracts, and max-minus-one/max/max-plus-one
boundary evidence. The source-module pin covers the local field capture,
exact-type guard, cumulative charge, bounded finding sink, deny-only result,
and sanitized-image withholding implementation on which the scalar comparison
depends. It does not establish the behavior of an unpinned interpreter or
externally monkeypatched runtime objects.

The cumulative classification now covers two resource maxima and four unique
source sites. All 690 discovery records remain syntactically `UNCLASSIFIED`;
686 sites remain semantically unclassified. Coverage remains `INCOMPLETE`,
generation remains `DENY`, and `RESOURCE_INVENTORY_INCOMPLETE` remains
unconditional. Aggregate accounting, diagnostic, representation, minimum,
exact-cardinality, and relational constraints remain out of scope.

## Third semantic classification slice

`M0.3A_RUNTIME_V2_RESOURCE_CLASSIFICATION.v3.json` preserves and byte-binds
the complete v2 manifest/schema, re-audits the v1 ancestor bytes, and adds only
`MAX_SCHEMA_DOCUMENT_BYTES`. The classification is the inclusive
262,144-byte ceiling over the exact field bytes supplied in each exact
schema-document record admitted to either private host-image preflight or the
deny-only verifier bundle inspection. The field name `canonical_json` does not
establish parsing, canonicality, digest correctness, bundle acceptance, or
schema validity at this gate.

Both constant copies and both enforcement sites are one semantic constraint.
The v3 manifest binds the whole image and verifier source-module ASTs, their
two enclosing function ASTs, the governing contracts, and independent
max-minus-one/max/max-plus-one evidence at both stages. It covers field
observation, exact-type ordering, item-limit findings, image withholding, verifier
INVALID/DENY closure, and non-boolean results. It does not attest an unpinned
interpreter or externally monkeypatched runtime objects.

The cumulative classification now covers three resource maxima and eight
unique source sites. All 690 discovery records remain syntactically
`UNCLASSIFIED`; 682 sites remain semantically unclassified. Coverage remains
`INCOMPLETE`, generation remains `DENY`, and `RESOURCE_INVENTORY_INCOMPLETE`
remains unconditional. Shared generic, aggregate, diagnostic, representation,
minimum, exact-cardinality, and relational constraints remain out of scope.

## Fourth semantic classification slice

`M0.3A_RUNTIME_V2_RESOURCE_CLASSIFICATION.v4.json` preserves and byte-binds
the complete v3 manifest/schema, re-audits its v2/v1 ancestor chain, and adds
only `MAX_SCHEMA_REF_NODES`. The classification is the inclusive 4,096-key
ceiling over the valid root `$defs` owner keys materialized in the verifier's
`edges` map when graph-cardinality evaluation is reached before diagnostic
budget exhaustion.

This is a cycle-traversal admission bound, not a general schema-complexity
claim. Invalid definition names, dangling targets, reference occurrences,
adjacency edges, schema objects, and preliminary walking are not counted by
this maximum. Earlier diagnostic saturation may return before the guard. The
v4 manifest binds the complete verifier source-module AST, the enclosing
schema-safety function AST, an additive exact contract, and direct plus public
max-minus-one/max/max-plus-one evidence. Oversized graphs add
`SCHEMA_REF_GRAPH_TOO_LARGE` and return before cycle traversal; the public
result remains `INVALID / DENY` and non-Boolean.

The cumulative classification now covers four resource maxima and ten unique
source sites. All 690 discovery records remain syntactically `UNCLASSIFIED`;
680 sites remain semantically unclassified. Coverage remains `INCOMPLETE`,
generation remains `DENY`, and `RESOURCE_INVENTORY_INCOMPLETE` remains
unconditional. Shared generic, aggregate, diagnostic, representation,
minimum, exact-cardinality, and relational constraints remain out of scope.
