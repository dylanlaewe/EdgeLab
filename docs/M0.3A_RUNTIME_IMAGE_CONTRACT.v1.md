# M0.3A runtime-v2 bootstrap and image contract v1

## 1. Status, precedence, and authority boundary

This document is the normative successor contract for the pure, no-I/O
runtime-format-2 bootstrap and whole-image boundary. It supplements
`M0.3A_SUCCESSOR_RUNTIME_FORMAT.v1.md` and
`M0.3A_CONTENT_REDUCER_CONTRACT.v1.md` and supersedes either document only
where this document closes a previously unstated image-transport, bootstrap,
dependency-closure, selector, checkpoint-copy, resource, or `REVALIDATE`
coordinate.

This document is a specification, not implementation or acceptance evidence.
`STOP-M0-3A-002` remains **OPEN** until the dependency-closure artifact,
embedded bootstrap validators, complete pure reducer, adversarial fixtures,
and all acceptance cases in section 12 are implemented and independently
accepted. Publication of this document does not connect the private transition
kernel to the public verifier and does not authorize a writer, SQLite open,
initializer, migration, recovery, selector installation, currentness claim,
R-gate, executor, paper/live action, strategy promotion, or capital use.

The reducer is pure. It reads only the supplied immutable `RuntimeImage`; it
does not read the filesystem, database, Git checkout, clock, network,
environment, package metadata, or callbacks. Mutable ambient files never
define retained evidence.

## 2. Exact host transport types

The implementation-facing transport types are exactly:

```python
from dataclasses import dataclass
from typing import TypeAlias

JsonCell: TypeAlias = type(None) | str | int

@dataclass(frozen=True, slots=True)
class SchemaDocumentRecord:
    schema_id: str
    document_sha256: str
    canonical_json: bytes

@dataclass(frozen=True, slots=True)
class BlobRecord:
    sha256: str
    schema_id: str
    canonical_json: bytes

@dataclass(frozen=True, slots=True)
class TableSnapshot:
    table: str
    rows: tuple[tuple[JsonCell, ...], ...]

@dataclass(frozen=True, slots=True)
class RuntimeImage:
    storage_descriptor: bytes
    verifier_dependency_closure: bytes
    manifest: bytes
    attachment: bytes
    schema_registry: bytes
    schema_documents: tuple[SchemaDocumentRecord, ...]
    blobs: tuple[BlobRecord, ...]
    events: tuple[bytes, ...]
    table_snapshots: tuple[TableSnapshot, ...]
    checkpoint_copies: tuple[bytes, ...]
    selector_history: tuple[bytes, ...]
    legacy_evidence: None
```

No field has a default. The concrete runtime image and every record must be an
instance of the exact supported host type; subclasses, lists in place of
tuples, mutable record variants, extra record fields, and duck-typed objects
deny before parsing. `JsonCell` means exactly `None`, `str`, or a signed-64-bit
`int`; because `bool` is an `int` subclass in Python, it is explicitly invalid.
Floats, bytes, arrays, objects, and arbitrary numeric classes are invalid
table cells.

`legacy_evidence` is exactly `None`. A mapping, empty tuple, empty mapping, or
any other value is invalid. Legacy material is transported only as registered,
typed content-addressed blobs reached from a `LEGACY_V1_BRIDGE` payload.

## 3. Dependency closure and acyclic pin elision

The image supplies one canonical dependency-closure record in
`verifier_dependency_closure`. The supported verifier compiles one exact copy
of those bytes and its expected digest. Supplied bytes must be byte-identical
to the compiled record; merely presenting a record with a self-consistent
digest is insufficient.

The closure digest is:

```text
closure = SHA256(
  "EDGELAB\0VERIFIER_DEPENDENCY_CLOSURE\0V2\0" ||
  EDGELAB_CANONICAL_JSON_V1(record without verifier_dependency_closure_sha256)
)
```

The record's `verifier_dependency_closure_sha256` must equal `closure`.
Genesis or bridge payload
`data.verifier_dependency_closure_sha256` must equal it. A missing, extra,
reordered, duplicated, differently versioned, or differently hashed closure
member denies.

The closure inventory closes every executable pure-reduction module, embedded
or compiled schema/validator, canonicalization and digest implementation, and
external distribution/version used by whole-image reduction. It contains no
Git commit, branch, tag, dirty-state value, current-checkout path, build time,
or environment-selected value. Those values either create a publication
cycle or let the ambient checkout redefine historical meaning.

The public entrypoint is fixed to
`src/edgelab/runtime_v2_verifier.py:verify_runtime_image`. The only pin carrier
is fixed to `src/edgelab/_runtime_v2_release.py`; it is the sole local artifact
with role `PIN_CARRIER` and `pin_elision_applied=true`. The entrypoint is the
sole `ENTRYPOINT` artifact and has `pin_elision_applied=false`. Local artifact
paths, bootstrap paths and schema IDs, retained paths and schema IDs, digest
domain names, resource-limit names, standard-library module names, and
external-distribution names are each unique and in canonical ascending order.
Aliases, cross-role reuse, case collisions, dot segments, symlinks, hardlinks,
or multiple logical names for one resolved input deny closure generation.

Closure production is acyclic:

1. Freeze all semantic sources and dependency identities before generating the
   closure artifact or pin carrier.
2. Hash every ordinary member's exact bytes.
3. For the single generated source carrier that stores the compiled closure
   bytes/digest, hash its semantic source with the generated pin block replaced
   by the literal ASCII marker `PIN_BLOCK_ELIDED_V1`. Exactly one complete
   generated block must be replaced; zero, partial, nested, or multiple matches
   deny generation.
4. Canonicalize and digest the closure record with its own digest member
   omitted using the equation above.
5. Generate the carrier from that frozen record. Regeneration must reproduce
   the exact carrier and closure bytes.

Only the generated carrier receives this elision. The marker is a deterministic
cycle breaker, not a wildcard: all carrier bytes outside the one generated
block remain closure members, and the runtime still compares the complete
supplied closure record with the compiled complete record. Semantic source may
not be modified after closure generation without publishing a new supported
closure.

The generator independently derives every recorded byte length, raw SHA-256,
domain-separated digest, schema `$id`, import edge, package identity, and
resource-limit value from the frozen inputs. A candidate record cannot select
or merely assert those values. Swapping raw and domain-separated digests,
duplicating a keyed inventory member with a different value, or supplying a
self-consistent candidate that differs from the generated compiled record is
invalid. Because the whole-image reducer is not yet source-frozen, this
contract intentionally does not publish a provisional closure artifact; doing
so would make the very next reducer change obsolete. Its absence keeps
`STOP-M0-3A-002` open.

## 4. Bootstrap schema authority

The no-I/O verifier embeds or mechanically generates exact validators for the
attachment, manifest, active selector, schema-registry record, and storage
descriptor. Runtime loading from `schemas/`, `$ref` resolution outside the
closed compiled bundle, network resolution, and caller-provided validators are
prohibited.

The following are SHA-256 digests of the exact raw schema-file bytes and are
compiled pins:

| Bootstrap schema | Raw SHA-256 |
| --- | --- |
| `m0-3a-runtime-attachment.v2.schema.json` | `0623e1706d3a18a2b06043c72f444bd8bad9d798248ff62c83a901a36c1dbb9c` |
| `m0-3a-runtime-manifest.v2.schema.json` | `dcec875b3bb65178fc58e19d84c7fed5d85df97f44f501b3e4aa3c1c44b791de` |
| `m0-3a-active-runtime-selector.v2.schema.json` | `5398ccf55ce90159d9da34f9a29863a856f1e6e38fdb9ab498b8bd71bb5badf9` |
| `m0-3a-schema-registry.v2.schema.json` | `b31a025add8419bfc1db2bee579d2511a3e93c59dcea47cd832655affc03d630` |
| `m0-3a-runtime-storage-descriptor.v2.schema.json` | `cb54877057a81440fa8510111a984ba2cbd528b48842066fb49a3a92cd7a6193` |

Raw-byte pins do not replace semantic validation. Each document must be exact
canonical JSON, satisfy its exact embedded validator, satisfy the semantic
equations in this contract, and match the compiled supported document or
descriptor pins where the older contracts require an exact supported value.
The retained nine-document registry remains exactly the registry defined by
the content-reducer contract; bootstrap schemas are verifier dependencies and
are not silently added as retained registry documents.

The bootstrap validator semantics are a versioned conservative refinement of
the raw schemas, not an appeal to a host JSON Schema library's defaults.
Every published `pattern` must match the whole string with no trailing-newline
alias, exact JSON types apply (`bool` is not integer), and `date-time` is an
asserted Gregorian UTC-second in the form `YYYY-MM-DDTHH:MM:SSZ` with year
`0001..9999`, a real calendar day, hour `00..23`, minute `00..59`, and second
`00..59`. These stricter rules are part of the generated validator and closure
identity. A host library treating `format` as annotation or `pattern` as a
substring search cannot redefine them.

## 5. Resource and root-work limits

Limits are checked using host types and bounded byte scans before semantic
reduction. Exceeding a limit invalidates the whole image; truncation, sampling,
partial verification, and early positive acceptance are prohibited.

### 5.1 Cardinality and individual-byte limits

| Item | Limit |
| --- | ---: |
| events | 100,000 |
| derived tasks | 100,000 |
| blobs | 300,000 |
| each event | 1,048,576 bytes |
| manifest | 1,048,576 bytes |
| attachment | 1,048,576 bytes |
| verifier dependency closure | 1,048,576 bytes |
| each checkpoint copy | 1,048,576 bytes |
| each selector document | 1,048,576 bytes |
| each blob body | 16,777,216 bytes |
| table snapshots | exactly 15 |
| checkpoint copies | at most 49,999 and no more than the number of checkpoint command groups |
| selector documents | 2 through 50,001 inclusive, and exactly `2 + checkpoint_group_count` |
| total accounted input | 1,073,741,824 bytes |

The retained schema-document, registry, finding, event-group, task-ID, and
signed-64-bit limits from the content-reducer contract remain in force.

The total accounted-input equation from the content-reducer contract is
extended by adding the exact byte length of
`verifier_dependency_closure`. It otherwise counts each field occurrence once:
raw byte lengths of the storage descriptor, manifest, attachment, registry,
closure, schema-document bodies, blob bodies, events, checkpoint copies, and
selector documents; UTF-8 byte lengths of every schema-document/blob ID and
digest; and the canonical JSON byte length of each snapshot as
`{"table":<name>,"rows":<array-of-row-arrays>}`. Container overhead is not
counted. An invalid cell or non-canonicalizable snapshot denies rather than
being assigned an estimated size.

### 5.2 Per-table row caps

| Table | Maximum rows |
| --- | ---: |
| `blobs` | 300,000 |
| `events`, `tasks`, `attempts`, `claims`, `reviews`, `remediation_links`, `idempotency`, `snapshots` | 100,000 each |
| `schema_documents` | 9 |
| `schema_registry`, `metadata`, `seals`, `legacy_archive` | 1 each |
| `migrations` | 0 |

These are maxima, not expected cardinalities. The derivation may require a
smaller exact count, including zero `legacy_archive` rows for a new runtime.

### 5.3 Root-work budget

Let `P = b"EDGELAB\0TABLE\0V2\0"`. For every checkpoint
pre-registration cut, every export pre-registration cut, and the final
supplied-image cut, and for every one of the 15 descriptor tables, charge:

```text
root_work(cut, table) =
    len(P)
  + len(table_name encoded as UTF-8)
  + 1
  + len(EDGELAB_CANONICAL_JSON_V1(ordered_rows_at_that_cut))

total_root_work =
  sum(root_work(cut, table)
      for cut in checkpoint_cuts + export_cuts + [final_supplied_cut]
      for table in descriptor_table_order)
```

`total_root_work` must be at most 1,073,741,824 bytes. Each logical cut is
charged separately even if two cuts have byte-identical rows. Cached root
computation may optimize execution but may not reduce the charged work. The
budget therefore bounds repeated flat-table root reconstruction rather than
only transport size.

## 6. Genesis kinds and identity closure

Exactly one global-sequence-zero system event exists. Its event group contains
no `COMMAND_COMMITTED` event and is one of two kinds:

| Manifest `source_kind` | Request / event | Reserved operation key | Legacy result |
| --- | --- | --- | --- |
| `NEW` | `SYSTEM_GENESIS` / `RUNTIME_GENESIS` | `system:v2:genesis` | no legacy refs; empty `legacy_archive` table |
| `V1_MIGRATION` | `SYSTEM_LEGACY_BRIDGE` / `LEGACY_V1_BRIDGE` | `system:v2:legacy-bridge` | exact-role archive/projection refs; exactly one `legacy_archive` row |

Both payloads bind the same runtime/chain IDs, formats `(2,2)`, attachment
digest, exact storage descriptor, exact schema registry, supported verifier
dependency closure, repository generation zero, and initial repository bundle.
The event uses the fixed genesis predecessor and task-null coordinates required
by the content-reducer contract. Attachment `created_at`, manifest
`created_at`, metadata/seal creation time, system event timestamp, and selector
generation-1 `written_at` are byte-identical canonical UTC seconds.

The manifest is derived only after the genesis/bridge event ID and digest are
known. The system request and payload therefore do not bind the manifest
digest. The completed manifest binds that system event and its source kind;
metadata and the sole `RUNTIME_GENESIS_IDENTITY` seal bind the completed
manifest. This ordering is acyclic.

For `NEW`, no legacy archive or projection blob is reachable and the reducer
begins with no active task rows. For `V1_MIGRATION`, the bridge's archive and
projection blobs and all legacy source coordinates must cross-equal the
manifest, payload, blob schemas, and sole `legacy_archive` row. It still begins
with no active v2 tasks, attempts, claims, reviews, remediation links,
idempotency records, migrations, or imported scheduler authority.

## 7. Selector genesis, checkpoints, and metadata equations

Let canonical selector objects be `S[0] ... S[n]`, let `sd(S)` be the
domain-separated selector digest from the successor-format contract, and let:

```text
selector_history(S[0..g]) = SHA256(
  "EDGELAB\0SELECTOR_HISTORY\0V1\0" ||
  EDGELAB_CANONICAL_JSON_V1([S[0], ..., S[g]])
)
```

The supplied selector history is exact canonical bytes, contiguous by
`selector_generation`, contains no duplicates, and contains exactly
`2 + checkpoint_group_count` documents.

For every supplied index `i`,
`S[i].selector_generation = i`,
`S[i].selector_history_path = "selectors/{i:020d}.json"`, and
`S[i].selector_sha256 = sd(S[i] without selector_sha256)`. Generation zero has
null prior coordinates. Every `i > 0` has
`prior_selector_path = "selectors/{i-1:020d}.json"` and
`prior_selector_sha256 = S[i-1].selector_sha256`.

### 7.1 Generation zero

`S[0]` is a schema-valid format-1, generation-zero, `V1_ACTIVE` selector with
the fixed v1 paths, null manifest/checkpoint/prior coordinates,
`selectors/00000000000000000000.json`, `UNKNOWN`, and `DENY`. Its digest is
recomputed.

For `V1_MIGRATION`, `S[0].active_runtime_id` equals the bridge
`source_runtime_id`. For `NEW`, the generation-zero active runtime ID and
`written_at` are opaque schema-valid pre-cutover evidence. They have no
cross-identity requirement with the new runtime and convey no migration,
authenticity, currentness, or authority claim.

### 7.2 Deterministic generation one

`S[1]` is derived, never caller-selected, as the exact object:

```text
schema_version                    = 1
selector_format_version           = 1
selector_generation               = 1
active_runtime_format_version     = 2
active_runtime_id                 = manifest.runtime_id
active_database_path              = "runtime.v2.sqlite"
active_attachment_path            = "attachment.v2.json"
active_manifest_path              = "runtime.v2.manifest.json"
active_manifest_sha256            = manifest digest
latest_v2_checkpoint_sha256       = null
selector_history_path             = "selectors/00000000000000000001.json"
prior_selector_path               = "selectors/00000000000000000000.json"
prior_selector_sha256             = S[0].selector_sha256
cutover_state                     = "V2_ACTIVE"
currentness_status                = "UNKNOWN"
authorizing_use                   = "DENY"
written_at                        = genesis/bridge envelope occurred_at
selector_sha256                   = sd(the preceding fields)
```

The initial selector-history digest is
`selector_history([S[0],S[1]])`. Here and below, the manifest digest is the
domain-separated `manifest_digest(manifest)`, not raw SHA-256 or a caller
field. Initial metadata selector fields are exactly
`active_selector_generation=1`,
`active_selector_sha256=S[1].selector_sha256`, that history digest, and a null
latest checkpoint.

### 7.3 Generations two and later

Checkpoint command group number `k`, zero-based, produces exactly `S[k+2]`.
If current selector generation is `g=k+1`, then the candidate selector is the
exact v2 object required by the content-reducer contract with generation
`g+1`, the three fixed v2 paths, manifest/runtime identity unchanged,
`latest_v2_checkpoint_sha256` equal to the newly registered checkpoint,
history path for `g+1`, prior path/digest equal to `S[g]`,
`V2_ACTIVE/UNKNOWN/DENY`, and `written_at` equal to the checkpoint semantic
event envelope's `occurred_at`. Its digest and the history digest over
`S[0..g+1]` are recomputed
and must equal the request and payload.

Equivalently, every selector at index `i >= 2` corresponds to exactly one
checkpoint with `checkpoint_sequence = i - 2`; no other command can create it.

No export creates a selector. No selector may be skipped, inserted, or exist
without its one corresponding checkpoint after generation one. Final metadata
must equal the last selector's generation and digest, the digest of the whole
supplied selector history, and the last checkpoint digest (or null when the
history contains only generations zero and one).

## 8. Checkpoint-copy transport

`checkpoint_copies` are optional transport duplicates, not roots of
reachability and not additional retained records. Each supplied copy must:

- be exact canonical bytes satisfying the checkpoint-document schema;
- byte-equal exactly one reachable registered checkpoint document blob;
- cross-equal that blob's schema ID, blob digest, checkpoint domain digest,
  snapshot row, payload, sequence, cut head, roots, and prior checkpoint;
- appear in strictly increasing registered checkpoint-sequence order; and
- be unique by bytes, checkpoint digest, blob digest, and sequence.

The tuple may be empty even when checkpoints exist. It may contain any sorted
subset of registered checkpoint documents, subject to the caps in section 5.
An unregistered copy, duplicate, out-of-order copy, mismatched serialization,
or a copy treated as evidence that creates a blob/row is invalid. Absence of a
copy never removes the registered blob or snapshot row.

## 9. Table snapshots and all-table materialization

There is exactly one `TableSnapshot` for each descriptor table, with no missing
or duplicate name, in this exact descriptor order:

```text
attempts, blobs, claims, events, idempotency, legacy_archive, metadata,
migrations, remediation_links, reviews, schema_documents, schema_registry,
seals, snapshots, tasks
```

The exact logical source of each materialization is:

| Table | Derived rows |
| --- | --- |
| `attempts` | one row per observed task attempt; its sequence-1 task event is the origin and its greatest task sequence is the immutable attempt head |
| `blobs` | exactly the least-fixed-point reachable typed request, response, payload, state, checkpoint, export, legacy archive, and legacy projection blobs |
| `claims` | claim issuance plus its exact close, recovery, or governance-invalidation semantic event |
| `events` | every validated canonical event envelope in global-sequence order |
| `idempotency` | one row per committed non-system transaction group, with its transaction, request/response, commit event/sequence, and group time |
| `legacy_archive` | zero rows for `NEW`; one bridge-derived row for `V1_MIGRATION` |
| `metadata` | singleton genesis/bridge and manifest identity plus reduced repository, global head, checkpoint, final selector/history, and fixed deny-only coordinates |
| `migrations` | exactly zero rows |
| `remediation_links` | each atomically reduced reciprocal source/child event pair and domain-separated link digest |
| `reviews` | review assignment plus its exact approval, rejection, remediation, or governance-revocation semantic event |
| `schema_documents` | the exact pinned nine-document retained inventory |
| `schema_registry` | the one exact pinned registry row |
| `seals` | exactly one deterministic `RUNTIME_GENESIS_IDENTITY` row |
| `snapshots` | every validated checkpoint and export event/document in its independent contiguous sequence |
| `tasks` | one latest reduced state per active v2 task, including atomic retry and remediation effects |

Each row has exactly the descriptor's column count and descriptor column
order. Cells have the strict scalar types from section 2 and integers are
signed-64-bit. Rows are in the descriptor's exact total ascending-BINARY key
order, with no duplicate key. Canonical-JSON database columns contain their
exact canonical ASCII JSON strings as `str`; they are not nested transport
objects or bytes.

The reducer derives all 15 tables from the validated closure, schemas,
genesis/bridge, events, typed reachable blobs, checkpoints, selectors, and
transition equations. It takes no supplied table row as a transition input.
After every transaction is reduced, the final derived rows must equal every
supplied row and cell exactly. Missing or extra tables, rows, columns, blobs,
or values invalidate the entire image. The table roots use the descriptor
projections and the domain-separated table-root equation; snapshot roots at
checkpoint/export cuts and the final materialization are independently
recomputed under the root-work budget.

## 10. Legacy semantics and `REVALIDATE`

### 10.1 Legacy bridge is archive-only

Legacy archive and projection documents are reachable only through the two
typed bridge blob references. No free-form key, untyped digest, filename, task
ID, or value inside `legacy_evidence` is traversed. The bridge materializes the
single `legacy_archive` row and the two exact-role blobs; it materializes no
active v2 task or attempt.

Legacy receipt strings, idempotency rows, seals, migration rows, snapshots,
and metadata outside the frozen verified projection remain untrusted archive
content. They do not seed active v2 metadata or authority. Exact legacy event
strings remain in the raw archive; only the three typo mappings closed by the
successor-format contract may appear in the diagnostic projection. A legacy
task can become active only through a later separately specified v2 operation;
the reducer must not infer a task mapping, receipt, retry, claim, review, or
authority from archive/projection content.

### 10.2 Exact `REVALIDATE` equation

For a valid `REVALIDATE` group:

```text
source B0 -> target N0
source B1 -> target N3
after.scheduler_generation = before.scheduler_generation + 1
after.repository_generation = current metadata.repository_generation
after.decision_receipt_digest = request.arguments.evidence_sha256
after.active_claim_id = null
after.reviewer_assignment_id = null
after.reviewer = null
```

Every other field not named by the closed transition is byte-identical to the
before state. No former claim or review assignment is reopened or restored.
The request evidence digest, `GOVERNANCE_REVALIDATED` payload/state refs,
after-state blob, response affected state, event envelope, and materialized
task row must all cross-bind this same result. A second receipt source,
manifest-derived receipt, prior receipt reuse, or caller-selected after value
is invalid.

## 11. Result boundary while the STOP is open

The existing public result remains version 1 and has only `INVALID` and
`UNSUPPORTED`. Until `STOP-M0-3A-002` is formally resolved after complete
implementation and independent acceptance, no input may produce a positive
public result.

A future separately versioned result may use the exact status literal
`LOCALLY_CONSISTENT_DENY_ONLY` only after every equation in the governing
contracts and this document is implemented and accepted. That result must
still contain:

```text
anchor_status      = "UNANCHORED"
currentness_status = "UNKNOWN"
authorizing_use    = "DENY"
```

It is not truth about external history, current repository state, receipt
authenticity, permission, execution safety, or capital eligibility. It must
not be truth-tested as an authorization boolean. Complete coordinated rewrite
or rollback of all local evidence remains outside local detection.
