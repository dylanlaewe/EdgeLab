# M0.3A review decision and route replay slice v1

## Scope

This private slice extends runtime-v2 NEW-image replay through exact review
assignment, review decision, and director-routing transaction groups. It
derives review history and the private decision index from committed events;
candidate task and review rows remain comparison inputs only.

The slice adds no positive public-verifier result and no operational,
STOP-clearance, execution, live-approval, or capital authority. A review
`APPROVE` transition is scientific workflow evidence only. `ROUTE` reaches
`DIRECTOR_GATE_READY`; it does not authorize a director decision or execution.

## Assignment

`ASSIGN_REVIEW` accepts only N3. The request actor must differ from the task's
immutable owner and the request role must differ from its immutable owner role.
The `REVIEW_ASSIGNED` payload supplies the lowercase UUIDv4 assignment ID, and
the response repeats that identity as one `REVIEW_ASSIGNMENT` generated
reference with a null digest.

The transition sets N4, advances only scheduler generation, sets
`reviewer_assignment_id`, and creates the exact OPEN review row at the semantic
event. The persisted task `reviewer` field remains null. Task and review writes
commit in one revision-bound workspace delta.

## Decisions and routing

`APPROVE`, `REJECT`, and `REMEDIATE` accept only N4 and require the request
assignment ID to equal the active assignment. Their semantic payloads are
empty. Each transition advances only scheduler generation, clears the active
assignment, and atomically:

- closes the review at the semantic event as `APPROVED`, `REJECTED`, or
  `REMEDIATION_REQUIRED`;
- derives N7, N5, or N6 respectively; and
- records the exact operation, decision digest, and semantic event in the
  private cumulative decision index for the task attempt.

The physical runtime-v2 layout has no separate decision table. Decision
evidence is retained by the reachable command request and event group, while
the review row records its exact closing event and status. The private decision
index is reconstructed during replay so later remediation can bind the exact
prior decision digest without trusting candidate materialization.

`ROUTE` accepts only approved N7. It validates the routing-evidence digest,
sets N8, and advances only scheduler generation. It preserves the approved
review and decision history byte-for-byte.

All five operations are same-attempt two-event groups. They advance the exact
task-local head without opening an attempt or rewriting attempt origin or
predecessor history.

## Atomicity and projection

Task, review, and decision writes are staged without mutation and checked
against their workspace revision before commit. Review open/close event IDs are
retained once; a decision uses the same semantic ID as its review closure and
does not create a second event-identity claim. Stale, forged, duplicate, or
partially valid plans cannot close a review without the matching task and
decision transition.

Whole-image derivation projects exact task and review rows, attempt heads,
idempotency rows, events, and reachable request/response/payload/state blobs.
No generated reference is allowed for decision or route groups.

## Assurance and residual boundary

Focused tests cover independent assignment, all three decision outcomes,
approved routing, N4 governance revocation and revalidation, exact cumulative
review and attempt history, decision and assignment CAS, malformed evidence,
wrong-source routing, candidate review-row tampering, event reuse, and atomic
workspace parity with the immutable transition kernel. Optimized-Python runs
must preserve the same results.

Valid candidates remain opaque `UNSUPPORTED / CLOSURE_NOT_COMPILED / DENY`.
Remediation creation, repository import, checkpoint/export cuts, cumulative
root work, exact generated closure identity, the complete A-J acceptance
matrix, and genuinely independent acceptance remain outside this slice.
`STOP-M0-3A-002` remains OPEN.
