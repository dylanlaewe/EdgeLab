# M0.3A Legacy Bridge Amendment v1

## 1. Status, scope, and precedence

This document is a normative additive amendment for the runtime-format-2
`V1_MIGRATION` bridge only. It clarifies the legacy portions of:

- `M0.3A_SUCCESSOR_RUNTIME_FORMAT.v1.md`, especially canonical format-1
  archive/projection and migration steps;
- `M0.3A_CONTENT_REDUCER_CONTRACT.v1.md`, especially system-event and legacy
  derivation language; and
- `M0.3A_RUNTIME_IMAGE_CONTRACT.v1.md`, especially sections 6, 10, and 12F.

Where those passages conflict with this amendment, this amendment controls.
All existing retained schema, schema-registry, storage-descriptor, and raw-file
pins remain byte-identical. This amendment does not claim that the present
schemas carry evidence bytes they do not contain.

This amendment does not relax the successor-format requirement to run the
pinned frozen-v1 verifier against the source database, produce and verify a
consistent backup, or retain the exclusive lock through capture and cutover.
The capture profile below is an additional eligibility boundary, not a
substitute semantic replay or a reconstruction of missing evidence.

`V1_MIGRATION` remains unsupported under the current schemas and carrier.
Future support requires the versioned evidence treatment in section 5 as well
as a pure projector implementing this profile. Nothing here creates a
migration writer, cutover authority, currentness, or capital authority.

## 2. Attachment-byte equation

Let `B` be `archive.attachment_bytes_base64`. The successor projector MUST:

1. decode `B` using strict RFC 4648 standard-alphabet base64 with required
   padding and zero unused pad bits;
2. re-encode the decoded bytes and require byte-for-byte equality with `B`;
3. parse the decoded bytes as duplicate-free JSON;
4. require the decoded bytes to equal the format-1 canonical JSON encoding of
   the parsed attachment; and
5. calculate:

```text
A = strict_base64_decode(B)
source_attachment_sha256 = SHA256(A)
```

The parsed `meta` inventory MUST contain exactly one `attachment_digest` value.
After duplicate-free JSON parsing of that stored `meta.v`, it MUST equal
`source_attachment_sha256`. The projection `attachment_sha256`, manifest
legacy bridge, bridge payload, and the sole format-2 `legacy_archive` row MUST
all equal the same digest.

This raw SHA-256 equals the format-1 `digest(attachment)` only because canonical
byte equality is a bridge-eligibility requirement. Semantically equivalent but
noncanonical attachment bytes deny; the projector may not silently re-encode
them and claim the original bytes were verified.

## 3. Compiled successor-capture profile

The following profile MUST be compiled into any successor capture/projector;
no such projector exists yet. It describes checks performed during successor
capture and is not a claim that historical v16 performed them. `TEXT!` and
`INTEGER!` mean the exact SQLite storage class and non-null. A `?` suffix
permits `NULL` or the named storage class. `NULL!` means the exact SQL `NULL`
value and permits no other class. No `REAL`, `BLOB`, numeric alias, coerced
value, or other storage class is eligible in a logical table cell.

| Table | Ordered columns and storage profile | Total row order |
| --- | --- | --- |
| `meta` | `k:TEXT!, v:TEXT!` | `k` |
| `seals` | `runtime_id:TEXT!, attachment_id:TEXT!, attachment_digest:TEXT!, genesis_digest:TEXT!, created_at:TEXT!, seal_digest:TEXT!` | `runtime_id` |
| `tasks` | `task_id:TEXT!, attempt:INTEGER!, workflow:TEXT!, execution:TEXT!, review:TEXT!, scheduler_generation:INTEGER!, dispatch_generation:INTEGER!, task_fence:INTEGER!, claim_id:TEXT?, reviewer_id:TEXT?, continuations:INTEGER!, repository_generation:INTEGER!, receipt_digest:TEXT!, owner:TEXT!, reviewer:NULL!, predecessor_task:TEXT?, successor_task:TEXT?` | `task_id` |
| `attempts` | `task_id:TEXT!, attempt:INTEGER!, predecessor_attempt:INTEGER?` | `task_id,attempt` |
| `claims` | `claim_id:TEXT!, task_id:TEXT!, attempt:INTEGER!, fence:INTEGER!, status:TEXT!, actor:TEXT!` | `claim_id` |
| `reviews` | `assignment_id:TEXT!, task_id:TEXT!, actor:TEXT!, role:TEXT!, status:TEXT!` | `assignment_id` |
| `idempotency` | `operation_key:TEXT!, request_digest:TEXT!, response:TEXT!` | `operation_key` |
| `runtime_events` | `event_id:TEXT!, global_seq:INTEGER!, event_type:TEXT!, payload:TEXT!, event_digest:TEXT!, prev_id:TEXT!, prev_digest:TEXT!` | `global_seq,event_id` |
| `task_events` | `event_id:TEXT!, task_id:TEXT!, attempt:INTEGER!, task_seq:INTEGER!, global_seq:INTEGER!, event_type:TEXT!, before_json:TEXT!, after_json:TEXT!, payload:TEXT!, event_digest:TEXT!, prev_task_digest:TEXT!, prev_global_digest:TEXT!` | `global_seq,event_id` |

| `migration_ledger` | `migration_id:TEXT!, from_version:INTEGER!, to_version:INTEGER!, artifact_digest:TEXT!, backup_ref:TEXT!, backup_digest:TEXT!, result:TEXT!, created_at:TEXT!` | `migration_id` |
| `snapshots` | `snapshot_id:TEXT!, digest:TEXT!, generation:INTEGER!, global_head:TEXT!, created_at:TEXT!` | `snapshot_id` |

Rows MUST be strictly increasing in the stated total order under SQLite BINARY
text ordering and numeric integer ordering, with no duplicate key. The archive
retains exact tagged cells; the compiled profile rejects a correctly tagged but
wrong-class or wrongly nullable cell. This profile supplements rather than
rewrites the pinned generic tagged-cell archive schema.

Successor eligibility also requires exactly one `seals` row and zero
`snapshots` rows. The format-1 DDL is not `STRICT`, and frozen startup does not
validate every cell or cardinality that this profile closes. In particular, a
`NULL` or `BLOB` `idempotency.operation_key`, a `NULL` or `BLOB`
`migration_ledger.artifact_digest`, an extra seal, or any snapshot is
bridge-ineligible even if frozen-v1 startup happens to accept it. These are
deliberately stricter successor-capture rules, not claims about guarantees
historically enforced by v16.

## 4. Projection derivation

No projection-local value is caller-selected. The projector MUST derive:

- `source_runtime_id`, source global-head ID/digest, repository generation, and
  repository bundle from duplicate-free parsing of the exact `meta.v` cells;
- the exact sorted meta-key inventory fixed by the projection schema;
- each table's column digest, row count, and ordered-row digest from the archive
  plus the compiled profile in section 3;
- `storage_inventory_sha256` from the archive's exact single-file storage
  inventory using the `legacy_storage` domain;
- the fixed three-entry legacy event-name mapping;
- `row_archive_sha256` by the `legacy_archive` equation;
- `projection_sha256` by the `legacy_projection` equation with its self field
  omitted;
- `created_at` exactly equal to the bridge envelope `occurred_at`; and
- `currentness_status="UNKNOWN"` and `authorizing_use="DENY"`.

All shared coordinates MUST cross-equal the archive, projection, manifest,
bridge payload, exact-role blobs, and sole `legacy_archive` table row. A caller
default, current-clock value, inferred filename, repaired row, or silently
coerced storage value denies.

The legacy-domain and format-2 blob-domain digests are distinct and MUST NOT
be equated. The exact bindings are:

```text
source_row_archive_sha256
  = projection.row_archive_sha256
  = legacy_archive_digest(archive)

request.arguments.legacy_archive_ref.sha256
  = payload.data.legacy_archive_ref.sha256
  = legacy_archive.archive_blob_sha256
  = blob_digest(archive)

source_projection_sha256
  = projection.projection_sha256
  = legacy_projection_digest(projection_without_projection_sha256)

request.arguments.legacy_projection_ref.sha256
  = payload.data.legacy_projection_ref.sha256
  = legacy_archive.projection_blob_sha256
  = blob_digest(projection)
```

## 5. Unavailable preimages and assurance limit

The present `RuntimeImage` carries the exact archive and projection blob bytes.
The archive in turn carries attachment bytes and a physical storage-inventory
record. It does **not** carry the following preimages:

- the raw `runtime.sqlite` bytes named by the storage inventory's size and
  SHA-256 fields;
- the consistent SQLite backup named by `source_backup_sha256`;
- the migration plan named by `migration_plan_sha256`;
- the frozen format-1 verifier dependency closure named by
  `frozen_verifier_closure_sha256`;
- the commit/tree content named by `frozen_verifier_commit`; or
- the repository-bundle content named by
  `source_repository_bundle_sha256`.

Under the current pinned schemas those values are unverified archival reference
coordinates. A reducer can recompute `legacy_storage` over the supplied
inventory record, but cannot verify that record against the absent database
bytes or prove that the supplied row archive came from that database. It may
require syntax and exact cross-copy equality among projection, manifest,
payload, and table row, but MUST NOT state that absent bytes were recomputed,
traversed, or independently verified. They are not typed blob-reachability
edges.

Because the controlling successor contract requires frozen-v1 verification,
consistent backup verification, and lock-held source capture, `V1_MIGRATION`
MUST return `UNSUPPORTED` under the current schemas and `RuntimeImage` carrier.
Supporting it requires a new versioned legacy evidence carrier and
corresponding registry, request/payload, manifest, storage, and runtime-format
treatment; missing evidence may not be smuggled into the existing pinned
records or replaced by a self-consistent fabricated archive.

`V16_BOUNDED_REPLAY_ONLY` is only an archival scope and producer-claim label.
It does not prove that v16 produced or verified the archive encoding, compiled
column profile, backup, migration plan, frozen closure, successor projection,
authenticity, currentness, or authority. The successor projector independently
checks only the equations for which it possesses evidence.

## 6. Correct system-event binding language

For both system operations, the request top level binds runtime ID, chain ID,
repository generation, and repository bundle. Request arguments bind
attachment, storage descriptor, and schema registry; bridge arguments also
bind the archive and projection blob references.

The request has no format-version or verifier-dependency-closure field. Only
the payload binds runtime/event format versions and
`verifier_dependency_closure_sha256`. Only the bridge payload binds legacy
source coordinates. Cross-equality applies only to coordinates actually shared
by the relevant records.

These corrections preserve the acyclic pre-manifest order: archive and
projection blobs; request, response, and payload; bridge event; manifest; then
metadata, seal, and selectors. The event envelope binds the request, response,
and payload digests. No system request may acquire a manifest digest or a field
absent from its pinned schema.
