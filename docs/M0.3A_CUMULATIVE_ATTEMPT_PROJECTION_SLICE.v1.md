# M0.3A cumulative attempt projection slice v1

## Scope

This private slice replaces the runtime-v2 NEW-image reducer's final-row-only
attempt projection with a cumulative projection owned by the accepted replay
cursor. It does not compile `RETRY`, repeated `CLAIM`, or any new public
verifier result. Candidate table rows remain untrusted comparison inputs.

## Ownership and derivation

The replay cursor owns one head per `(task_id, attempt)`. Each head retains the
attempt predecessor, origin event, current task sequence, and current semantic
event identity. The final `attempts` table is derived in primary-key order from
all retained heads; no transaction-group patch supplies a candidate row.

Opening an attempt requires task sequence 1. Attempt 1 has no predecessor. A
later attempt must name exactly `n - 1`, and that predecessor attempt must
already exist for the same task. Advancing an existing attempt requires the
next sequence and the exact retained semantic-event predecessor. Advancing an
attempt changes only its head; origin and predecessor remain immutable.

## Atomicity

Group patches declare whether their already validated semantic event opens an
attempt and, if so, the predecessor attempt. Before the transition workspace
is mutated, the commit owner rechecks the exact event pair, cursor uniqueness,
and attempt-head mutation. Only then does it commit the staged task/claim delta
and perform a local no-fail cursor advance. A stale, skipped, duplicate, or
forged attempt mutation therefore cannot partially advance either owner.

## Assurance and residual boundary

Adversarial tests cover cumulative multi-attempt projection, preservation of a
closed prior head, exact origin/head separation, skipped-predecessor rejection,
and rejection before workspace or cursor mutation. A delegated read-only
review found no in-scope blocker; that review is engineering feedback, not
independent Skeptic acceptance.

Because `RETRY` is still outside the workspace and image dispatcher, the
multi-attempt positive test exercises the private cursor directly. The next
slice must compile exact `F0(n) -> N0(n+1)` retry semantics, repeated claims,
and end-to-end attacks against omitted, extra, reordered, or rewritten
historical attempt rows. `STOP-M0-3A-002` remains OPEN, and the public verifier
remains disconnected and deny-only.
