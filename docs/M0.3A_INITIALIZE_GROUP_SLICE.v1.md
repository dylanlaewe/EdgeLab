# M0.3A INITIALIZE transaction slice v1

## Status

This document records the first private ordinary transaction-group slice of
the runtime-format-2 reducer. It is an incremental engineering boundary, not a
whole-image verifier release.

The slice is pure, deny-only, and disconnected from the public verifier. A
candidate that passes every compiled check remains opaque as
`UNSUPPORTED / CLOSURE_NOT_COMPILED / DENY`.

## Compiled profile

The profile accepts exactly one of these NEW-runtime shapes:

1. The already-compiled sequence-zero `RUNTIME_GENESIS` image.
2. That genesis followed by one two-event `INITIALIZE` transaction:
   `TASK_INITIALIZED`, then `COMMAND_COMMITTED`.

For the second shape, the reducer independently checks:

- canonical, domain-digested supplied blobs indexed by digest and schema role;
- contiguous global sequences and predecessor links;
- unique event and transaction identities;
- one shared transaction ID, event count, operation key, request digest,
  response digest, repository coordinates, and UTC-second timestamp;
- exact semantic-then-commit ordering and event positions;
- the task-attempt predecessor root and task sequence;
- closed `INITIALIZE` request, response, payload, commit payload, envelope, and
  task-state shapes;
- runtime, chain, operation, operation-key, subject, repository, payload,
  request, response, state, and commit cross-bindings;
- immutable task-state derivation through `reduce_transition`, followed by an
  exact comparison to the supplied after-state document;
- typed reachability of the genesis and group request/response/payload/state
  blobs, with no extra supplied blob accepted;
- exact events, attempts, idempotency, tasks, metadata, bootstrap, schema, and
  seal rows across all 15 supplied table snapshots.

Candidate table snapshots remain comparison-only. They never drive replay.
The group patch is returned only after all group checks pass, so a late
failure cannot publish partial task or idempotency state.

## Explicit exclusions

This version does not support later ordinary task operations, remediation,
repository imports, checkpoints, exports, checkpoint copies, legacy bridge
reduction, historical root-work charging, exact release-closure generation, a
writer, a database, selector cutover, a positive consistency result, or any
authority or capital path.

The supplied-blob catalog is intentionally distinct from the incrementally
reachable set. Future checkpoint and export roots must be computed from the
pre-registration reduced cut, never from the final supplied blob inventory.

## Next implementation boundary

Extend the same atomic group planner and projection layer across the remaining
single-semantic ordinary operations. Then add the two-event remediation and
variable-cardinality import groups. Only after ordinary replay is complete may
export and checkpoint cuts consume descriptor-driven pre-registration table
roots. Exact closure generation remains deferred until every semantic source
is frozen and independently accepted.
