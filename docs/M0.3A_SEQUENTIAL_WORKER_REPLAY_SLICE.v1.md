# M0.3A sequential worker replay slice v1

## Status

This document records the seventh private ordinary replay increment of the
runtime-format-2 reducer. It replaces enumerated event depths and full-prefix
rescans with a locally derived sequential cursor for the already compiled
single-task, single-claim worker lifecycle. It is not a general lifecycle
dispatcher or a whole-image verifier release.

The slice remains pure, deny-only, and disconnected from the public verifier.
A candidate that passes every compiled check remains opaque as
`UNSUPPORTED / CLOSURE_NOT_COMPILED / DENY`.

## Compiled replay

After NEW genesis, `INITIALIZE`, and the first `CLAIM`, the reducer accepts any
structurally complete odd event count within the existing 100,000-event host
cap. Every later pair must be exactly one already compiled worker or synthetic
recovery group followed by its `COMMAND_COMMITTED` event:

- `START`;
- zero or more state-valid `CONTINUE` groups;
- `YIELD`, `FAIL`, or either `COMPLETE` outcome; or
- bounded `RECOVER` from `CLAIMED` only.

The immutable transition kernel still decides whether an operation is valid
from the derived current state. A valid prefix cannot make an invalid suffix
acceptable.

## Cursor boundary

The private cursor is constructed only from the already validated genesis and
fully accepted groups. It is not read from candidate content, serialized,
returned, or used as authority. It retains global and per-attempt heads plus
event-ID, event-digest, transaction-ID, and operation-key indexes. Each group
is fully validated before the cursor advances.

Typed reachable blobs and idempotency rows accumulate once during replay and
are compared/projected only after the complete trace. Final task and claim
rows come from the immutable reducer state. The implementation no longer
slices or scans the growing event prefix for each group.

## Explicit exclusions

This version has exactly one task, one attempt, and one claim. A later
`CLAIM_ISSUED` or `TASK_RETRIED` event is uncompiled and denied even after a
valid long prefix. Re-claim, `RETRY`, historical multi-attempt projection,
governance, review, remediation, import, checkpoint, and export replay remain
outside this slice.

The linear-work statement applies only to event indexing for this one-claim
scope. Repeated claim and attempt histories would make the current immutable
transition-state reconstruction quadratic; they must not be enabled until a
separately tested transition workspace/delta design removes that cost.

This slice adds no writer, database, selector cutover, currentness result,
execution, operational authority, STOP clearance, or capital path.

## Next boundary

Implement a private transition workspace with atomic deltas and cumulative
historical attempt projection. Then add closed dispatch for re-claim and
`RETRY` while retaining every prior attempt and claim exactly.
