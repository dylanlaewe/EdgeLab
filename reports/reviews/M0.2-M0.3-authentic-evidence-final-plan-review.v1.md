# Authentic M0.2 → M0.3A planning acceptance review

## 1. Verdict

`M0_2_M0_3_ADAPTER_PLAN_REQUIRES_REVISION`

The package contains genuine frozen executions and substantially improves the historical record, but Data still cannot implement the security boundary without inventing policy. The reference verifier accepts a self-consistent replacement of retained frozen source and its output; dependency captures omit repository and package integrity bindings; and the currentness contract is prose plus asserted result vectors rather than a closed, executable record and comparison contract.

## 2. Authority-set integrity

Every path named by `docs/M0.2_DECISION_EVIDENCE_AUTHORITATIVE_SET.v1.md` exists, and the declaration correctly demotes old V12 fixtures to structural evidence. The set is internally incompatible at its integration boundary: Envelope v13 designates directory captures as replay authority while its only root schema is the structurally different V12 envelope. Currentness model v1 requires authority dimensions the V12 `currentness_binding` cannot represent. H-M0-074 remains `CLAIMED`; its promised completion, envelope v13 schema and M0.3A v14 contract do not exist.

## 3. Stage 1 neutrality

`src/edgelab/orchestration.py`, `src/edgelab/validate.py`, `src/edgelab/data_integrity.py`, `tests/test_orchestration.py`, and `tests/test_orchestration_final.py` have no diff from `bc3a40924ca580ca6eddc4c24e32ff99ddd95330` through Director base `670b1df`. Retained `orchestration.py` and the checked orchestration/scheduler schemas are byte-identical to the freeze. No production adapter was implemented in this review.

## 4. Authentic DISPATCH

The original capture replays exactly as `DISPATCH`, `SYNTHETIC_ASSERT`, `D-0a6e8268c4309df969a5384c4ce33063`, reason `repository-resolved synthetic task passed preflight`. The retained tree contains the real frozen source and records. This is authentic execution evidence, subject to the verifier-authenticity failure in section 22.

## 5. Authentic DENY

The original DENY replays exactly with the frozen five-field mapping and `D-25150701cc9d3f301f686d420e407c2f`. It is frozen-generated rather than a hand-authored V12 substitute.

## 6. Dependency satisfied replay

## 7. Dependency denied replay

## 8. Replay self-containment

Replay does not import current EdgeLab source, current schemas, current `.git`, or network resources. It rebuilds temporary Git, uses `python -S`, and loads retained package trees. Its allowed boundary is nevertheless under-specified and weakly verified: it uses the host `sys.executable`, `git`, and `PATH`; the package tree includes a CPython 3.13 Darwin native module; no interpreter/Git identity is captured or checked by the capture format.

## 9. Frozen source retention

Decision-critical retained source is real and matches the frozen commit where checked. The verifier does not bind it to that commit: changing the source, recomputing the ordinary inventory, and replacing the expected output with the mutated engine's output passes official replay.

## 10. Schema retention

The full retained repository includes actual frozen schemas and frozen imports resolve without current-tree fallback. Authentic directory captures have no closed schema connecting them to the V12 artifact/blob/source model.

## 11. Runtime/package retention

The external trees are executable and support offline replay. Original captures declare package versions and file hashes, but replay checks neither. Dependency captures do not declare package identities or hashes at all. A harmless retained-package mutation passes replay.

## 12. Git evidence

Embedded `.git` is unnecessary; temporary reconstruction reproduces the frozen equality/ancestry predicates. The manifest's `freeze_commit`, `head`, and `origin_main` are ignored. Replacing all three with unrelated 40-hex values still passes. Replay also creates a new commit whose identity is not compared with the recorded historical observations.

## 13. Historical provenance

Provenance v1 identifies direct frozen reads and deterministic task-SHA derivation well. It overstates verification of retained source/package/Git observations because the reference verifier does not check the declared package hashes or historical Git labels and treats the repository inventory as mutable self-assertion rather than a trusted freeze anchor.

## 14. STOP evidence

The retained STOP record matches frozen consumption. Existing mutation tests show an un-rehashed STOP byte change fails the repository inventory check. That demonstrates consistency with the capture, not immutable historical authenticity: an attacker who changes the STOP and recomputes inventory plus output can use the same accepted self-consistent-forgery path. Today's STOP must remain a separate currentness input.

## 15. Capability evidence

The retained capability inventory matches frozen reads and includes the fields used by Stage 1. Existing mutations fail when they leave the capture inventory stale. They do not defeat a self-consistent historical replacement.

## 16. Assignment/handoff evidence

Retained assignment, binding and handoff histories cover the frozen selection and equality predicates. As with STOP/capability evidence, their protection is only a self-declared inventory digest. Current assignment/handoff source selection remains prose.

## 17. Dependency predicate

Direct code and empirical evidence cover scheduler dependency reference, authoritative versioned head, `COMPLETED`, exactly one completion, typed completion path, parsed task ID/attempt/task ref/status, and `content_sha256 == SHA256(exact task bytes)`.

## 18. Dependency mutation coverage

All material frozen dependency predicates have direct-code or empirical coverage. Twelve recorded variants produce the expected frozen families. No new frozen predicate gap was found.

## 19. Task-byte/completion-byte distinction

The evidence correctly establishes that dependency task bytes are authorization-relevant through SHA-256; completion bytes are provenance; parsed completion mapping is the authorization input; and serialization-only completion changes preserve the decision and receipt.

## 20. Source graph

The nine dependency authority paths exist once and the seven edges reflect frozen reads/derivations. The graph is descriptive JSON without a schema or verifier and does not bind the dependency capture to repository/package inventories.

## 21. Graph/reference integrity

The older V12 artifact/blob schemas plus semantic resolver define several uniqueness checks, but the authentic capture format bypasses that graph entirely. There is no authoritative mapping from an authentic directory capture into V12 persisted artifact/blob records, no authentic-capture schema, and no rule that decides the canonical record/digest Data must persist. Data would have to design this boundary.

## 22. Forged-output resistance

Critical property failed. A Skeptic probe changed both occurrences of the frozen success reason in retained `orchestration.py`, recomputed `repository_inventory_sha256`, executed the mutated retained engine, replaced `capture.result` with that output, and the official replay returned success with `self-consistent forged replay accepted`. Ordinary hashes detect accidental mutation only when an external trusted root pins them; this package supplies no verified root.

## 23. Historical mutation resistance

Uncoordinated result, STOP, capability, assignment and handoff mutations fail as published. Coordinated source/evidence, inventory and result replacement passes. Dependency source is weaker: its capture contains neither `repository_inventory_sha256` nor package manifest, so even a retained-source byte mutation passes without modifying capture metadata.

## 24. Currentness completeness

Currentness model v1 names repository, runtime, attachment, task/attempt, scheduler, assignment, handoff, claim, fence, project, STOPs, dependencies, capabilities, inventories, Git and eight generations. It does not provide a closed schema, canonical serialization/digest, exact captured binding representation, deterministic current-source resolver, equality rules, or executable verifier. The authoritative V12 root can encode only repository/runtime/attachment IDs, task/attempt, three generic state strings, generations, claim state and fence. Matrix v8 explicitly says a later implementation must add complete authoritative checks. This requires security-policy invention, not merely implementation.

## 25. Dependency currentness

The six committed cases express the correct separation: historical `VALID` remains unchanged while dependency drift becomes `STALE`/`DENY`; current-as-historical is `INVALID`. They are asserted JSON rows tested for their own values, not outputs of a currentness verifier.

## 26. Non-dependency currentness

The 24 listed dimensions have the correct expected outcome, `STALE`/`DENY`, with historical validity retained. Again, the test only checks a static expectation object and case count. It does not resolve or compare current authority.

## 27. Cross-contamination

The dependency result includes one declared contamination case. No executable resolver attempts substitution of current records into immutable history. The historical/current conceptual separation is correct, but enforcement is not specified sufficiently for Data.

## 28. Verification-result safety

Verification-result v3 is closed and structurally prevents unsafe `ALLOW`; `DENY` cannot use `NONE`. The vocabulary is usable once historical and currentness verifiers exist.

## 29. Paths/environment

Retained relative paths work in the reference package. The reference implementation inherits host `PATH`, uses current `git`, and identifies no supported interpreter/ABI rule in the authentic capture. The older engine v5 has a stricter model, but Envelope v13 does not define how an authentic capture is bound to that engine record. This integration is security-relevant.

## 30. ID/package uniqueness

V12's bounded duplicate artifact/blob handling remains available for structural envelopes. Authentic package directory names are enumerated without validating the declared package records, unique package names, versions, hashes, or exact closure. Dependency captures omit those declarations. The authoritative formats therefore do not share one enforceable uniqueness rule.

## 31. Structural fixture classification

The authority set, Envelope v13 and matrix correctly classify hand-authored V12 fixtures as schema-only. This review did not use them as authentic historical proof.

## 32. Acceptance matrix

Matrix v8 points to real replay packages and correctly says later implementation must add currentness. Claims that the repository inventory prevents substitution and that a rehashed forged result cannot pass are false under coordinated replacement. Static currentness rows do not support the claim that complete currentness coverage is established.

## 33. M0.3A adoption

M0.3A v13 preserves accepted scheduler semantics and adopts V12 structures. It does not adopt or map the structurally different Envelope v13 capture format, and it cannot cure the currentness mismatch by reference. A promised v14 was never published.

## 34. Evidence-only operations

`REPORT_BLOCKED`, `RECORD_EVIDENCE`, `REPORT_FAILURE`, and `SAFE_YIELD` remain B0-only, non-operational, and state/claim/fence/generation neutral under the accepted scheduler contract. No contrary evidence arose.

## 38. BLOCKER/HIGH

HIGH architecture/security findings requiring revision:

1. No trusted anchor binds retained frozen source/evidence/result; a self-consistent forged engine/output passes.
2. Dependency captures omit repository and package integrity bindings.
3. No closed currentness schema/source resolver/comparison algorithm exists for the declared dimensions; V12 cannot encode them.
4. Authentic directory captures have no authoritative persistence/verifier mapping to the V12 artifact/blob/engine model.
5. Runtime/package/interpreter/Git observations are declared across incompatible formats and are not verified as one closure.

Governance integrity is also incomplete: H-M0-074 remains `CLAIMED`, and three promised completion artifacts are absent.

## 39. MEDIUM/LOW

MEDIUM: source-graph and currentness-result artifacts have no schemas and their tests largely verify declarations; package name/version uniqueness is unenforced in authentic captures. LOW: the replay tool's terse error surface and reliance on host Git make diagnostics and portability weaker, but these do not independently drive the verdict.

## 40. Required revisions

Publish one closed authentic-capture schema or a deterministic mapping into the existing V12 graph; bind the frozen repository, exact output, package closure, interpreter boundary and historical Git observations to a trusted immutable root that replay verifies; apply equivalent repository/package bindings to dependency captures; define and schema the full currentness binding plus exact current authority sources and comparisons; implement conformance tests that calculate results rather than assert authored rows; reconcile or complete H-M0-074 and publish a consistent M0.3A adoption version.

## 41. Implementation readiness
