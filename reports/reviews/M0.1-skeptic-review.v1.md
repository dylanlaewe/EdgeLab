## HIGH findings

### H01 — Lifecycle state is an unchecked assertion below the live boundary

Evidence: `validate_record` strategy branch only denies live states and null hypotheses outside IDEA. `test_H01_paper_promotion_without_evidence_accepted` accepts REGISTERED, BACKTESTED, PAPER_ELIGIBLE and PAPER_TRADING with a nonexistent hypothesis and no experiments, reviews or transition events. `test_H01_rejected_version_resurrected_and_conflicting_versions_accepted` accepts a REJECTED v1 alongside PAPER_TRADING v2 with no lineage and allows rewriting v1 to PAPER_ELIGIBLE. Exact duplicate `(kind,id,version)` is rejected, but that does not resolve contradictory versions.

Impact/root cause: no accepted-event replay, typed reference resolution, authoritative current-version selection, or prerequisite enforcement. A Research/Director writer can assert paper eligibility without Skeptic or Risk. This does not bypass the explicit M0 denial of LIVE_CANDIDATE/LIVE_APPROVED/LIVE.

Smallest robust remediation: Director owns lifecycle integration, with Data reference resolution and Risk paper gates. Until implemented, explicitly deny operational paper eligibility and scientific approval consumption. Then derive state from version-bound accepted events; check legal edges, predecessor state, immutable evidence, required independent reviews, terminality, stale reviews and conflicts. Do not interpret an arbitrary version increment as permission to resurrect rejected work.

Acceptance: convert H01 probes to rejection tests; prove IDEA→PAPER_TRADING, BACKTESTED→PAPER_ELIGIBLE, terminal resurrection, missing/wrong-type evidence and concurrent conflicting transitions fail. Add a fully evidenced positive path and stale-review invalidation. Keep all live-skip denial tests.

### H02 — Role labels cannot establish independent approval

Evidence: `test_H02_single_actor_can_claim_all_approvals` persists Research, Skeptic and Risk APPROVED events by `same-author`, all with nonexistent subjects/evidence; repository validation succeeds. Audit actor, role and event type are unrestricted nonempty strings. No review schema or authenticated approval boundary exists.

Impact/root cause: one writer can manufacture the appearance of independent approval. Merely checking different strings would remain spoofable. This is correctly acknowledged in OPERATIONS, but not solved by the current contracts.

Smallest robust remediation: Director owns an accountable actor/trust model and review schema; Risk owns authorization semantics. Bind reviews to exact evidence hashes, author/conflict disclosures, reviewer identity, scope, expiry and policy. Verify reviewer authority through a trusted boundary outside the artifact author's writable assertions. Define what the local shared-workspace threat model can and cannot guarantee; do not claim strong authentication from Git attribution alone.

Acceptance: reject same actor under different roles, aliases mapped to the same actor, unauthorized/stale reviewers, mismatched evidence, fabricated Risk approval and self-review; accept independently authorized, correctly scoped review. No strategy approval may rely on the test audit labels.

### H03 — STOPs neither propagate nor require a real resolution event

Evidence: `test_H03_open_stop_does_not_block_affected_paper_state` validates PAPER_TRADING with an explicitly linked OPEN STOP affecting that strategy. `test_H03_stop_resolved_by_arbitrary_file` accepts RESOLVED with `evidence.txt`, which is not an audit event and contains no remediation or approvals. The implementation checks only null/status agreement and file existence.

Impact/root cause: no typed resolution contract, latest STOP state reduction, dependency graph, quarantine propagation or clearing-authority validation. A Director file edit can appear to resolve a STOP despite prose prohibiting that action. Free-text scope cannot reliably express transitive/global applicability.

Smallest robust remediation: Director owns typed scope/dependency and resolution integration, with Data quarantine propagation and Risk capital clearances. Preserve OPEN history; resolve through a validated event with issuer/independent substitute review, domain approval, tests and Risk approval when implicated. Missing/unreadable scope or safety state denies affected operations. Validation may store an OPEN STOP successfully; a separate eligibility decision must deny affected work.

Acceptance: reject arbitrary-file resolution, self-clearing, missing approvals and conflicts; deny affected strategy, descendants and global-scope operations while permitting unrelated remediation and exposure-neutral reconciliation. Revalidated descendants must remain quarantined until explicitly released.

### H04 — Confirmation can lack temporal provenance and reproduction inputs

Evidence: `test_H04_completed_confirmation_without_reproduction_inputs_accepted` validates a completed PROMISING_REQUIRES_REVIEW confirmatory experiment whose manifest, commit, environment, trial inventory, temporal review and result references are nonexistent strings. `test_H04_late_unknown_and_mutated_lineage_accepted` uses a manifest with unknown or post-decision availability and an incorrect hash; both pass repository validation because derived manifests are not validated at all.

Impact/root cause: dates on the hypothesis/experiment are checked, but inputs, content integrity and as-of semantics are not. No machine-readable manifest/observation/feature contract connects original publication, retrieval, correction, source version, parser/normalizer or decision time. Reproduction strings are neither resolved nor content-bound.

Smallest robust remediation: Data owns typed content-addressed manifests and observation lineage; Quant owns the immutable reproduction bundle. Implement the existing SPECIFICATIONS contract: snapshot/hash verification, source/version/URL, retrieval and evidenced availability, publication/event/correction semantics, parser/normalizer and transformation versions, parent hashes and feature availability. Unknown availability blocks confirmation. Separate evaluation-only closing prices/outcomes; require as-of joins and exact config/environment/code/input/output/trial references. Check paths/types/hashes without executing untrusted reproduction commands.

Acceptance: reject missing/wrong-type/altered inputs and outputs, later corrections masquerading as earlier facts, unknown availability, post-decision injury/closing/outcome inputs, future-derived features, cycles and missing parents; reconstruct an approved synthetic bundle deterministically from its recorded versions. No real dataset is presently eligible.

### H05 — Exploration contamination is not represented or detected

Evidence: `test_H05_explored_dataset_reused_as_confirmation` records a completed exploratory run on September 18 and a September 19 registered hypothesis/confirmatory run using the exact same `dataset_manifests`; both validate. Current ordering proves only consistency of self-reported registration/freeze/start dates.

Impact/root cause: no structured exposure/trial history, holdout identity, sample overlap or first-results-access evidence. An already profitable pattern can be registered and retested on examined outcomes. Free-text split definitions and multiple-testing plans do not identify reused information.

Smallest robust remediation: Research defines preregistration and prior-exposure disclosures; Quant owns sample/split/trial identifiers and Data supplies immutable membership. Connect new hypotheses to exploratory ancestors; record outcomes already accessed and freeze an unexamined confirmatory population before access. Deny reuse/overlap unless a prespecified, independently reviewed statistical protocol establishes valid confirmation. New IDs alone do not create fresh data.

Acceptance: reject identical and partially overlapping observed outcomes (including renamed manifests), retroactive registration and altered thresholds; accept a genuinely unexamined, frozen synthetic holdout. Preserve all failed trials and multiplicity accounting.

### H06 — Audit and scientific history can disappear without detection

Evidence: `test_H06_history_mutation_deletion_and_circular_supersession_accepted` accepts an audit event superseding itself, overwrites its reason under the same identity, then deletes it; all three repository snapshots validate. H01 also rewrites a rejected strategy version. The validator has no previous accepted inventory, immutable digest baseline or event chain.

Impact/root cause: current snapshots cannot detect lost rejections, STOPs, failed experiments or intermediate decisions. Git can reveal committed changes to a reviewer, but current validation neither consults it nor detects pre-commit rewrites. It is not an append-only guarantee.

Smallest robust remediation: Director owns audit acceptance and retention, with Data immutable evidence storage. Compare changes against a trusted accepted inventory (a protected accepted Git baseline is an initial option with explicit trust limits), forbid deletion/rewrite of published identities, enforce acyclic exact supersession, and bind accepted events to content hashes and causal predecessors. Preserve negative trials, rejection and STOP history. External durable/authenticated storage can follow the agreed threat model; do not invent a database solely for appearances.

Acceptance: reject mutation/deletion, cycles, orphan supersession, omitted failed trials and inconsistent event chains; permit a new correction version that preserves originals. A writer able to replace the trusted baseline must be outside the claimed enforcement boundary.
