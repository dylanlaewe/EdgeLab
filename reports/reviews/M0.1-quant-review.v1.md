## Q01 — prior train/validation contamination escapes

The production scan in `_deny_prior_holdout_use` examines only earlier trials' `test` and `holdout` manifests. It skips `train` and `validation`. Three valid-prerequisite probes establish the consequence:

| Prior use of today's holdout | Result |
|---|---|
| Exact membership in prior `train` | **Accepted** as `SCIENTIFIC_INTEGRITY_CONSISTENT` |
| Exact membership in prior `validation` | **Accepted** as `SCIENTIFIC_INTEGRITY_CONSISTENT` |
| Renamed/repackaged prior `train` manifest with partial canonical overlap | **Accepted** as `SCIENTIFIC_INTEGRITY_CONSISTENT` |
| Exact membership in prior `test` | Rejected by the existing prior/repeated-trial check |

Each prior experiment has a distinct preregistration, a genuinely disjoint holdout and confirmatory access record, internally disjoint splits, a successful typed trial, and inclusion in the verifier-accepted complete trial inventory. Research correctly sees no conflicting holdout exposure because the contaminating observations were used in the prior experiment's training or validation population. Quant is the layer that possesses the actual split inventory and must compare all prior consumed populations against a proposed holdout.

The smallest robust remediation is to compare the proposed holdout's canonical Data sample keys against **every split actually consumed by every earlier trial**, including train, validation, test and holdout. Exact, renamed, reordered, partially overlapping and membership-version-equivalent packaging must all deny. A null result-access reference cannot by itself prove that train/validation inputs were never consumed; where execution phase cannot establish that fact, the check should fail closed. The current complete-inventory and accepted-state checks should remain. Data's identity system should remain the sole identity primitive. Quant should add owner tests mirroring all four roles and keep a genuinely disjoint positive case.

## Authority adapter and Risk interface

Local code correctly passes both the expected current-state digest and the complete assessment to `commit_if_current`, rechecks state immediately before that call, and documents the required atomic compare-and-commit behavior. A compliant adapter therefore closes the demonstrated local race. Tests also show that an adapter can ignore the digest, commit different bytes, return the same token twice and still satisfy the Python return check. This is not evidence that Quant can authenticate a dishonest external authority; the code and specification disclaim that guarantee.

Q02 is narrower. The returned token has no schema, assessment digest, state digest, authority identity, generation or verification/resolution method. The in-process tuple associates token and assessment, but a downstream Risk consumer cannot independently detect token substitution or replay from this interface alone. Before operational integration, define a structured commitment or authority lookup/verification contract that binds token, authority, assessment digest and current-state digest. This does not reduce the adapter trust assumption and does not itself authorize Risk.

The assessment body otherwise provides a clear Risk boundary: evidence refs, experiment identity, assessment digest, current-state digest, Research status, completeness scope and limitations are bound, and every operational authorization field is false. Risk retains lifecycle replay, reviewer/authority authentication, STOP enforcement, bankroll/exposure/correlation limits, paper/live gates, kill switches and all capital decisions.
