# M0.2 → M0.3A decision-evidence adapter planning review v8

**Verdict: `M0_2_M0_3_ADAPTER_PLAN_REQUIRES_REVISION`.** V8 closes the formerly unrestricted canonical input and output objects, adds immutable local module/schema mappings, lists the previously omitted Stage 1 schemas, and V10 adopts V8 without changing scheduler semantics. The package still cannot be implemented literally: its raw-output schema rejects frozen Stage 1 DENYs, the accepted closure digest is wrong, replay authority omits records frozen Stage 1 actually consumes, and external distribution references cannot resolve to the engine package records.

## 1–4. Stage 1, project and dependency authority

Frozen Stage 1 remains byte-identical at `bc3a40924ca580ca6eddc4c24e32ff99ddd95330`. Its 37 accepted tests pass from a detached worktree. V8/V10 changes no Stage 1 source, decision, STOP/capability/dependency/assignment/handoff interpretation, repository observation or decision-ID algorithm.

V8 now carries project record identity/version/head/artifact plus `phase`, `status`, `live_status` and optional capital. Frozen Stage 1 consumes phase, status and live status but does not consume a project-state capital field. The prose requires those values to equal the retained artifact, which closes the previous field omission. The separate `project.artifact_id` and `project.record.artifact_id` still need an explicit equality rule or a single field.

Dependency entries now name task ID, task artifact, task version/head, completion artifact and completion version/head, disposition, and optional generation. They do not represent required head and current head separately or state their equality relationship. The schema therefore does not implement the review requirement that current/required task and completion heads be compared directly.

## 5–8. Canonical, raw and normalized records

The canonical-input object and its nested objects are closed and reject unknown fields, empty authority objects and missing required fields. It nevertheless omits direct bindings for the primary task artifact/version/head, scheduler-state artifact and handoff-binding artifact. Frozen Stage 1 reads all three and includes task, state and handoff-binding content in its DISPATCH decision-ID context. A source manifest cannot compute a unique required source set from an input that never names those authorities. This is a BLOCKER for historical replay and decision-ID equality.

The raw and normalized schemas reject `{}`, unknown fields, `LIVE`, caller verification/capability/authorization fields, DENY with an operation and DISPATCH without an operation. The same DENY schema is used for both records and requires `operation:null`. Frozen `orchestration.decision()` returns a raw DENY with no `operation` member. The actual output reproduced from the freeze is therefore schema-invalid, while adding `operation:null` makes it valid. Normalization may add null; raw evidence may not rewrite frozen output. This is a BLOCKER.

The prose gives a literal field mapping, but it does not give the envelope any raw-output blob/digest/length/base64 reference and does not explicitly require the verifier to recompute normalized output. Data cannot prove canonical raw bytes or distinguish stored normalized content from recomputation without adding security-critical linkage.

## 9–13. Manifests and dependency closure

Import manifest v2 binds each local module to module name, artifact ID, replay path and digest. Validation manifest v2 binds each logical schema to artifact ID, replay path, digest and referenced schema IDs. These close the prior local name-to-byte gap.

External linkage remains incomplete. Import records point to `distribution_id`, and the validation manifest points to `validator_distribution_id`, but engine `external_packages` records have no `distribution_id` field. No exact cross-record target exists. The fixture also lists only `jsonschema` as a third-party distribution rather than the complete installed transitive dependency set required for an offline import. Data would have to invent package identity and transitive closure policy.

Closure v2 lists the six schemas actually loaded by frozen decision paths: scheduler state, orchestration task, project state, STOP, capability registry and handoff. The accepted fixture claims `closure_sha256=2f3c…3f31`; recomputing `SHA256(CJ(record excluding closure_sha256))` yields `598171…02f3`. Mutation detection therefore fails at the accepted baseline. This is a BLOCKER.

The prose states a useful traversal procedure, but the accepted output contradicts its digest rule and does not define how external transitive imports map to sealed distributions. The generation algorithm is not yet objective end to end.

## 14–20. Replay safety and evidence variants

Replay paths are still unsafe. `working_directory` has a pattern but no JSON type, so numbers, objects, arrays and null validate. Both it and module search paths accept `replay/../../current-checkout`. The schema does not establish root containment. Environment keys, if supplied, are fixed literals and unknown keys reject; both keys are optional, so `{}` leaves locale/hash behavior dependent on host defaults without an explicit statement that this is valid.

External package records carry name, exact version, wheel/sdist blob identity/digest and platform, and Python version is bound. The missing distribution IDs and missing sealed transitive packages prevent deterministic third-party replay without network resolution.

The referenced evidence-artifact schema still permits `member_kind:"OTHER"`, directly contradicting V8’s acceptance matrix. ABSENT carries all intended fields, but V8 supersedes the earlier digest prose and supplies no implementable assertion formula; changing path, inventory, source class and absence context while retaining the same assertion digest remains schema-valid.

Git observation is closed and typed. The matrix says inconsistent operands/results reject, but V8 does not state which ancestry operands must equal HEAD/origin or the historical shim invocation. Data still must choose that relationship. Historical replay must use persisted Git evidence, not current Git.

## 21–26. Source, bytes, reasons and verification

Source manifest has unique artifact/inventory/absence sets and canonical/source-set digests. Project, STOP, assignment/handoff records, dependency records and capabilities have artifact IDs. Primary task, scheduler state and handoff binding do not, so complete authority-source closure cannot be derived without inference.

Blob records bind base64 content, byte length and SHA-256. FILE artifacts bind raw bytes. The envelope does not link raw output to a blob or byte record, so the requested canonical UTF-8/base64/length/digest/replay-equality chain is incomplete.

Reason/status consistency remains only a one-line acceptance instruction. Verification-result v2 safely rejects every ALLOW combination with INVALID, STALE/UNKNOWN, wrong runtime, verifier failure or generation mismatch. It still permits contradictory DENY/reason combinations unless the future verifier invents a mapping.

Because the raw DENY representation, authoritative input source set, closure digest and external distribution linkage are unresolved, the full historical chain cannot be walked using persisted evidence alone. Currentness is conceptually separate, but V8 does not fully specify comparison of the omitted primary authorities; historical validity/current authorization separation is therefore not implementation complete.

## 33–36. Findings and required revision

BLOCKER findings:

1. V8 raw DENY is incompatible with frozen Stage 1 raw DENY.
2. The accepted closure v2 self-digest does not recompute.
3. Canonical input/source closure omits the primary task, scheduler-state and handoff-binding authorities required to reproduce the frozen decision ID.
4. Raw-output byte evidence is not directly represented or linked.

HIGH findings requiring architecture/security semantics:

1. External import and validator distribution IDs have no resolvable engine-package identity, and offline transitive package closure is incomplete.
2. Dependency required/current head relationships are not represented.
3. Working-directory and module-path containment are not enforced; fixed environment behavior is optional.
4. ABSENT assertion construction and exact Git ancestry operand relationships are unspecified after V8 superseded prior plans.
5. Normalized-output recomputation and complete historical/currentness source comparison are not explicit.

MEDIUM findings are the structurally valid DIRECTORY OTHER member, project record/artifact duplicate-ID equality, and incomplete reason/status mapping. No separate LOW finding was found.

Required revision: model frozen raw DENY separately from normalized DENY; link exact raw bytes; correct the accepted closure digest; bind primary task/scheduler-state/handoff-binding sources; give external distributions stable referenced identities and seal transitives; represent required/current dependency heads; enforce safe replay-relative paths and deterministic environment behavior; forbid OTHER; define ABSENT and Git operand formulas; and require verifier recomputation plus reason consistency.

Data cannot implement V8/V10 without inventing security-critical semantics. H-M0-041.v16 remains blocked and Data is not released.
