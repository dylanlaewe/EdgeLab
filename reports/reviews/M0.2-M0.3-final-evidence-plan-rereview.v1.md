# Final M0.2 historical-evidence / M0.3A currentness planning re-review

## 1. Verdict

`M0_2_M0_3_ADAPTER_PLAN_REQUIRES_REVISION`

The package adds a graph generator, composed-history entry point and source-reading currentness entry point, but the five prior HIGH findings are not closed. The composed verifier does not replay frozen Stage 1 and still accepts capture-local package rehashing, forged output and an unpinned required schema. The generated graph cannot independently persist or replay bytes. Currentness reads caller-selected JSON fixtures rather than locked repository/SQLite authority, misses repository races and permits inconsistent generations when the supplied binding matches.

## 2. HIGH 1 disposition — self-consistent historical forgery

**OPEN.** Decision-module and freeze-ID forgeries fail because their identities are pinned. Three required attacks still succeed:

- changing the sidecar result to a forged DISPATCH plus a false repository inventory returns `HISTORICALLY_VALID`;
- changing retained package bytes and recomputing the capture-local package hash returns `HISTORICALLY_VALID`;
- changing `orchestration-task.schema.json`, required by dependency closure v4 but omitted from the trust root's schema list, returns `HISTORICALLY_VALID`.

`verify_authentic_history()` never invokes frozen replay. Its raw-result check compares `cap['result']` with canonical JSON generated from the same `cap['result']`, so it is tautological.

## 3. HIGH 2 disposition — authentic/persisted representation

**OPEN.** The generator deterministically enumerates retained files, but its “blobs” contain only IDs and hashes, not bytes or immutable byte references. The graph contains no ABSENT records and only one Git field, `freeze_commit`. Its schema types all graph collections as unconstrained arrays/objects. There is no verifier that accepts a persisted graph and reconstructs retained bytes; `verify_authentic_history()` regenerates a new graph from the original directory. Round-trip persisted graph → verification → replay is therefore impossible without Data inventing blob storage and reconstruction rules.

## 4. HIGH 3 disposition — authoritative currentness

**OPEN.** The new entry point reads `repository.json` and `runtime.json` beneath a caller-selected directory, not the actual repository and SQLite scheduler/attachment authorities. It imports no SQLite or locking facility. Runtime generation is reread, but repository authority is never reread. A probe changed `repository.json` from A to B immediately after its read; the resolver returned `ALLOW` for stale A while B was current. There is no source-conflict model; the published “source conflict” is an attachment repository-ID mismatch. No historical/current source provenance check exists.

## 5. HIGH 4 disposition — v3 composition

**PARTIALLY REMEDIATED / HIGH remains.** Normal current, stale, incompatible and race outputs use the exact v3 field set, and `resolve_with_trace()` keeps diagnostics outside the closed result. However, historical `INVALID` produces currentness status `INVALID`, which is outside v3 and fails schema validation. The historical verifier itself emits a different ad hoc structure (`schema_version`, `verification_kind`, `status`, `authorization`, `reason_codes`) and is not v3-compatible despite the authority declaration. No composed R-gate consumes trusted history plus currentness v3.

## 6. HIGH 5 disposition — runtime/Git/package closure

**OPEN.** Exact package name/version set is checked, and reduced/duplicate/conflicting identities deny. Package byte hashes remain capture-local rather than trust-root pinned, so a byte change plus rehash passes. Host checking covers only Python implementation and major/minor. Platform, architecture, ABI, Git executable/model, PATH and environment allowlist are ignored. A trust record requiring `ImpossibleOS`, architecture `none` and `impossible-git` still validates. Historical Git evidence is not captured beyond freeze commit.

## 8. Dependency semantics

Frozen code and committed mutation evidence correctly cover scheduler head, `COMPLETED`, exactly one completion, typed path, task ID, attempt, task ref, completion status and content SHA equal to SHA-256 of exact task bytes. Task bytes are SHA-sensitive; completion bytes are provenance; parsed completion mapping is authorization input.

## 9. Provenance/source integrity

The existing source graph accurately describes frozen reads and deterministic task-SHA derivation. The persisted generator does not retain source roles/edges or distinguish scheduler/task/assignment/handoff/project/STOP/capability/dependency/module/schema records. It treats every repository file generically and supplies no evidence-type mapping beyond path prefixes.

## 10. Currentness authority

Positive fixture authority returns `CURRENT/ALLOW`, and declared drift dimensions deny. The source formats are test-created JSON snapshots with no schemas or mapping from `transactional_scheduler.py` tables, attachment record, repository bundle and generation fields. The binding remains a caller argument rather than a binding extracted from verified historical evidence; matching attacker-controlled binding/source objects can authorize.

## 11. Currentness race/conflict safety

Runtime generation A→B through `race-runtime.json` is detected, but the resolver itself writes the replacement file as a test hook. It holds no lock and does no repository final recheck. A real repository A→B race passes. Cross-field generation consistency is absent: `repository.generation = 99` with `generations.repository = 1` returns `ALLOW` when both supplied binding and source share the inconsistency. Missing files fail closed. Actual duplicate/conflicting sources are not modeled.

## 12. V3 result safety

Normal authoritative-currentness outputs validate against v3 and unsafe combinations remain structurally denied. Historical-invalid output fails the v3 schema. Historical verification output is not v3. `resolve_with_trace()` returns the same authority result as the closed resolver for the positive case and keeps its sorted trace separate, which is correct.

## 13. Runtime/Git/package closure

Package identity/version closure and removal checks improved. Required module/freeze pinning works. Byte authenticity, full schema closure, platform/architecture/ABI, Git executable identity, PATH/environment and historical Git observation enforcement remain absent from the composed path.

## 14. Persistence mapping

The persisted schema does not reuse or constrain V12 FILE/blob/source/DIRECTORY/ABSENT schemas. Data would have to choose storage and reconstruction semantics.
