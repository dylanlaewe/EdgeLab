## R01 — supplied prior registration disclosures are not compared with the new holdout (HIGH)

Reproduction: `test_v3_prior_registration_ancestry_not_carried_to_new_holdout` starts with a valid fresh-holdout fixture. REG.v1 has a disjoint fresh population and explicitly discloses OLD, an examined exploratory population. REG.v2 retains the exact valid `supersedes` reference to REG.v1, changes custody/holdout to OLD's population, and sets current `exploratory_ancestors=[]`. A post-freeze confirmatory-access record names the exact new holdout. With a new version-specific pin (the normal prerequisite for any new registration version), both repository validation and `check_confirmation_contract` accept; the latter returns `CONSISTENT_SUPPLIED_EVIDENCE`. Passing OLD again via `disclosure_refs` immediately rejects overlap.

The positive result remains `operational_authorization=false`. This is a false consistency/freshness assessment within supplied evidence, not an execution or capital bypass. The test assumes the verifier supplies the new pin; it does not claim to forge a historical pin. Pinning new bytes cannot make an already declared exposure disappear. The attack leaves v1 and its disclosed OLD bytes intact and reachable through the explicit predecessor. This is distinct from discovering hidden trials, scanning the repository or proving off-system completeness.

Root cause: `validate_research` validates a preregistration predecessor independently against that predecessor's own holdout. For the current holdout it traverses only current custody and current `exploratory_ancestors`. `check_confirmation_contract` likewise builds its comparison set from current registration disclosures, caller disclosures and access ancestry; it does not collect exposures from prior preregistration versions. Recursive *validation* of a prior record is not cumulative *exposure propagation* against the newly selected holdout.

Scope interpretation: SPECIFICATIONS explicitly preserves prior **exposure** versions and defers cross-hypothesis/experiment completeness to Quant. It does not explicitly promise prior **preregistration** closure. R01 identifies the missing Research prior-version semantic contract, not a claim that the documented Quant completeness scanner already exists. Because the contradiction is in the exact registration graph already supplied to Research, carrying that evidence forward is the smallest robust fix at this layer. This distinction should be documented, not solved by requiring callers to rediscover an already supplied ancestor.

Smallest remediation, owner **03 Research**: define and collect the cumulative exposure disclosures reachable through preregistration predecessors (including predecessor custody/ancestry and exposure predecessors). Compare every examined/unknown population against the current holdout using existing canonical Data keys. Preserve valid prior records; keep cycle, type, timestamp and pin checks. Do not conflate a legitimate new registration pin with a fresh population. Quant still must provide access/exposure records not reachable through this supplied chain, including previous confirmatory accesses and cross-hypothesis trials.

Acceptance: add separate rejection regressions for this compatible fixture, multiple predecessor hops, renamed and partially overlapping prior disclosed populations, and prior UNKNOWN evidence. A v2 with truly disjoint new holdout must pass and remain non-authorizing; changing a version still requires its own pin. Run all retained suites and preserve both historical Skeptic files and this new characterization. Do not invert or delete published tests to make the suite green. H-M0-011 v1 assigns this bounded remediation and requires Director scheduling.

No known previously enforced production behavior regressed. R01 is a newly demonstrated omission in the new protocol; the legacy schema error itself is not the defect. Existing STOP scope already covers this scientific-consistency risk; no STOP clearance or parallel research is warranted.
