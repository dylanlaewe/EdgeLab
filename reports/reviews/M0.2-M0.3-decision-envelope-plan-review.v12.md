# M0.2 → M0.3A decision-evidence adapter planning review v12

**Verdict: `M0_2_M0_3_ADAPTER_PLAN_REQUIRES_REVISION`.** V12/V13 improves root binding, digest formulas, engine ownership, raw DENY shape, verification-result safety and historical/currentness separation in concept. The completed package is not replayable evidence. Its golden authority records, engine modules, schemas and package archives are placeholder strings; its DISPATCH is impossible under frozen Stage 1; its STOP directory contains the task instead of a STOP; and the historical graph omits scheduler state, handoff binding and the complete DENY context that frozen code actually consumes. V12 also regresses the complete currentness surface promised by V11.

## 1–5. Stage 1, golden fixtures and graph traversal

Frozen Stage 1 production modules and core tests are byte-identical from `bc3a40924ca580ca6eddc4c24e32ff99ddd95330` through the Director base. The 37-test frozen suite passes at that commit. V12 is planning-only and cannot alter decision, operation, STOP/capability/dependency interpretation, assignment/handoff behavior, repository observations or receipt content.

Both golden envelopes validate the closed schema, every root node is present, structural IDs are unique and the Director resolver can walk every declared edge. That structural result is insufficient. The dependency closure is only an ID/version/digest stub; the resolver selects the full record from today’s repository by hardcoded filename. The seven historical authority FILE blobs decode to strings such as `retained:task`, not JSON records. Local engine blobs are `retained:orchestration` rather than frozen module bytes; validation blobs are not schemas; package blobs are not wheel archives and use version `fixture-1`.

The DISPATCH raw mapping is not a frozen Stage 1 result: operation `SAFE_YIELD` is outside frozen `STATE_READ`, `SCHEMA_WRITE`, and `SYNTHETIC_ASSERT`, reason is `fixture decision`, and decision ID is `decision-1` rather than `D-<32 hex>`. DENY correctly has five raw fields and normalized `operation:null`, but it has the same synthetic reason/ID and was not produced by replay.

Frozen `_load_scheduler_state` and `_validate_task` consume `orchestration/scheduler-state.json`, its claim, and `orchestration/handoff-bindings/<task>.v1.json`. V12 retains no scheduler-state record and no handoff-binding record. `claim_fixture_id` has no retained source or deterministic derivation. A future adapter cannot reconstruct the accepted positive fixture without inventing these records.

Frozen `_denial_context` scans scheduler state plus all JSON in docs, handoffs, STOPs, assignments, handoff bindings, tasks, completions and capabilities. V12 DENY retains none of those complete inventories. Exact DENY receipt replay is therefore impossible even if its selected direct records were replaced with real bytes.

## 6–16. Digests, blobs, historical authority and source closure

All published logical digests independently recompute: source manifest, Git observation, import manifest, validation manifest, engine distribution, closure v4, DIRECTORY inventory, ABSENT assertion and both envelope self-digests. Raw base64/length/SHA and normalized mappings are internally consistent. Blob IDs, byte lengths and digests are also internally consistent with the placeholder bytes.

Uniqueness is enforced by the Director semantic resolver rather than the schemas: conflicting artifact/blob IDs remain schema-valid but resolve as failure. Missing blobs, digest/length mismatch and malformed base64 have deterministic denial rules. This is implementable once real retained bytes exist.

Historical provenance remains incomplete. Generic task/assignment records require derived `id`, `version`, and head fields that do not directly exist in every frozen record, but V12 gives no derivation rule. More materially, scheduler state, claim content and handoff binding are absent despite direct consumption by frozen code.

STOP closure is invalid in both fixtures. The `historical/stops` DIRECTORY has one member, `task.json`, pointing to the task artifact; no STOP record is retained or parsed. Omission, addition, disposition and record mutations are therefore not tested against the literal frozen STOP predicate.

Capability and dependency records could be enforced by replay if their real task/capability/completion bytes and scheduler mappings were retained. The placeholders prove none of the consumed capability trust/approval/revocation/effect fields or literal dependency completion equality.

ABSENT digest computation is now defined, but coverage is not sound. `optional-receipt-absent` names `historical/receipt.json` while its inventory root is `historical/stops`. The conformance resolver accepts a rehashed DIRECTORY that contains the allegedly absent path, and accepts a dangling `absence_artifact_ids` entry.

DIRECTORY members are FILE-only and duplicate paths are rejected semantically. Root containment, canonical ordering, artifact-path correspondence and absence contradiction are not enforced. A rehashed artifact path `../escape/task.json` remains schema-valid and passes the resolver.

Source-manifest direct membership is checked as an exact set for the limited historical record list. That list omits scheduler state and handoff binding. Absence references are not resolved, and STOP inventory membership is not checked for STOP records.

## 17–29. Engine, replay, currentness and negative mutations

Engine v5 binds one interpreter identity, launcher, clock/Git shims, manifest IDs, closure ID/digest, local artifact IDs, packages, environment and working directory. The interpreter boundary is explicit: exact compatible CPython identity or DENY, with no host fallback. That bounded identity model is implementable.

Import, validation and package relationships are structurally traversable. They are not executable offline closure because the local/schema/package blobs are placeholders. The package set has the five closure names, but each archive is plain text and each version is `fixture-1`, rather than an installable retained distribution.

Closure v4 recomputes to `766c19c23841c8605068fffb7c9fd85e69a3b03457358cb200a6a060546406c4`; engine v5 binds its digest. The full closure record is neither an artifact nor a blob, so the resolver loads `docs/M0.2_STAGE1_DEPENDENCY_CLOSURE.v4.json` from the ambient checkout. A duplicate package name under a second distribution ID also passes. This is not self-contained historical closure and does not authenticate the placeholder package bytes as usable members.

The engine working-directory schema and exact four-key environment are strict. Import/validation schemas still accept dot segments and doubled separators, while artifact paths are only non-empty strings. V12 prose supplies the safe rule, so this is a bounded schema/test correction, but current schemas are inconsistent with the stated contract.

Raw mapping→canonical bytes→base64/length/SHA and deterministic DENY normalization work internally. The conformance resolver does not execute frozen replay: changing the receipt ID/reason, rebuilding raw bytes/normalized output and rehashing the envelope passes. This is expected of a shape-only helper but contradicts the completion claim that golden raw Stage 1 evidence was verified.

Git observation digesting and typed IDs work. V12 does not restate left=HEAD/right=origin/main equality, and the resolver accepts rehashed unrelated ancestry operands. Historical replay therefore needs the superseded V11 rule or an implementation choice.

Verification-result v3 correctly rejects INVALID/STALE/UNKNOWN/INCOMPATIBLE/wrong-runtime/verifier-failure/generation-mismatch ALLOW and DENY+NONE. No reason code grants authority.

Currentness is a HIGH regression. Its closed record contains repository/runtime/attachment, task/attempt, three state strings, eight generations, claim state and fence. It cannot represent assignment/handoff/claim identities or heads, project, STOP state, dependency/completion state, capabilities, inventories, Git state or the authoritative records from which current values are read. Rehashing arbitrary claim state/generations still passes the graph resolver; no currentness verifier can be implemented from the root record alone.

The consolidated Director mutation suite covers selected wrong closure/manifest/Git/source/artifact/blob/raw/normalized edges. Skeptic probes add placeholder-byte, impossible-DISPATCH, missing-scheduler/binding, DENY-closure, STOP substitution, root escape, ABSENT contradiction, dangling absence, wrong Git operands, self-consistent forged raw output, currentness mutation, closure-stub, duplicate-package-name, path grammar and duplicate-ID characterization. A real replay fixture and current-authority resolver remain absent.

## 30–39. V13, findings and readiness

V13 explicitly adopts V12/engine v5/result v3 and makes no scheduler semantic change. The accepted state machine, synthetic actor boundary, B0 guards, closed claim/fence, generations and idempotency remain unchanged. REPORT_BLOCKED, RECORD_EVIDENCE, REPORT_FAILURE and SAFE_YIELD remain evidence-only, state/claim/fence/generation neutral, non-completing and non-operational.

Matrix v7 references current V12/V13 artifacts, but its claims of a complete historical graph, retained local/package closure, exact provenance and currentness-only mutation coverage are contradicted by the fixtures and resolver. No stale V9/V10 artifact is named as authority.

Historical Skeptic probes were not modified. The v10 suite now has one expected historical failure because it asserted that result v3 and matrix v5 did not exist; V12 supplies result v3 and later matrices. Its other 18 tests pass. This superseded expectation is separate from the current V12 gate.

Existing M0.3A scheduler code remains reusable and its 12-test suite passes. No scheduler redesign is required. Data implementation must remain blocked until the evidence contract is corrected and separately released.

BLOCKER findings:

1. The golden envelopes retain placeholder strings instead of parseable authority records, frozen modules, schemas and installable packages; their raw outputs are not replayed Stage 1 results.
2. Historical DISPATCH closure omits the scheduler-state/claim record and handoff-binding record directly consumed by frozen Stage 1.
3. Historical DENY closure omits the complete record inventories consumed by `_denial_context`, preventing exact receipt replay.
4. The claimed historical STOP closure contains a task artifact and no STOP evidence.
5. The root retains only a closure digest stub; the full dependency record is selected from the ambient repository by filename.

HIGH findings requiring architecture/security correction:

1. Closed currentness cannot represent most V13 authorization dimensions or identify their current authoritative sources.
2. ABSENT/DIRECTORY/source semantics permit root escape, present-path contradiction and dangling absence references; V12 is not self-contained for these checks.
3. Git ancestry operand equality is absent from V12 and unenforced.
4. Historical generic-record derivations and claim identity are not specified, while required scheduler/handoff sources are excluded from exact source membership.

MEDIUM bounded issues: import, validation and artifact path schemas are weaker than the explicit V12 safe-path rule; duplicate artifact/blob IDs are only semantically rejected; and duplicate package names with distinct distribution IDs pass the resolver. No independent LOW finding was found.

Required revision is to publish real replayable DISPATCH/DENY fixtures derived from accepted frozen Stage 1 evidence; retain scheduler state, handoff binding, exact STOPs, full denial-context inventories and the full dependency-closure record; expand currentness to every declared authority dimension with deterministic current-source resolution; correct ABSENT/DIRECTORY/source/Git rules; retain actual frozen modules/schemas/installable packages; and extend mutation tests to exercise real replay rather than self-consistent placeholder graphs.

Data cannot implement V12/V13 without inventing historical evidence and currentness policy. `STOP-M0-3A-001` remains OPEN and planning disposition cannot clear it.
