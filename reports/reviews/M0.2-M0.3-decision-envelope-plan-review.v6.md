# M0.2 → M0.3A decision-evidence adapter planning review v6

**Verdict: `M0_2_M0_3_ADAPTER_PLAN_REQUIRES_REVISION`.** V6 materially improves canonical subject/generation typing, artifact discrimination, raw/normalized field closure, Git identity discrimination, result authorization and the acceptance matrix. V9 restores the actor, closed-claim/fence, generation and idempotency prerequisites. The authoritative envelope nevertheless omits four input categories promised by v6, carries only a dangling Git-observation ID, contains no engine-distribution record/reference, and leaves `blobs` as arbitrary objects despite FILE artifacts depending on immutable blob resolution. These are implementation BLOCKERs, not missing polish.

## 1–7. Stage 1, canonical input, operations, generations and identity

Frozen Stage 1 remains byte-identical at `bc3a40924ca580ca6eddc4c24e32ff99ddd95330`; current frozen implementation/test paths match it. V6 remains observational and requires exact replay, so it cannot legitimately alter decision, operation, STOP/capability/dependency/assignment/handoff/repository behavior or decision ID.

The v6 canonical schema closes task, attempt, intent, expected operation, assignment and handoff IDs/heads/versions, claim fixture/state, an eight-field generation vector, repository/runtime/attachment IDs, inventory IDs, Git-observation ID and evaluation time. Extra fields and empty required IDs reject. The generation vector has distinct repository, runtime, scheduler, dispatch, fence, assignment, handoff and claim counters and covers v9’s stated exact-generation guard.

The bundle does **not** contain the typed project, STOP, dependency/completion or capability artifact identities promised in the v6 prose. It also has no writer/role identity beyond `claim_fixture_id`. `expected_operation` may be empty and the schema does not condition it on raw DISPATCH/DENY; the semantic prose gives the deterministic rule, so that structural issue is bounded, but the absent evidence references cannot be recovered without inventing a source-class convention.

Identity typing is improved: logical IDs, record versions, SHA-256 content heads and Git IDs have separate fields. Repository ID is now one nonempty string across the canonical bundle. However, only a `git_observation_id` exists; no schema-valid Git-observation record or envelope collection resolves it. Blob and artifact identities are intended to differ, but the blob collection is not typed.

## 8–13. Artifact union, FILE/ABSENT/DIRECTORY, blobs and source manifest

The artifact companion schema is a strict discriminated FILE/ABSENT/DIRECTORY union. Empty, unknown-kind and extra operational records reject. FILE has source/provenance, historical path, content-addressed blob ID, raw length/digest and optional canonical digest. ABSENT has expected path, inventory, class, context and assertion digest. DIRECTORY has root, selection rule, typed ordered members and inventory digest. Semantic rules explicitly require unique IDs/paths, root containment, ordering, digest equality, valid references and absence contradiction checks.

The envelope defeats FILE replay by defining `blobs.items` only as `{type:"object"}`. The artifact schema contains a suitable closed `$defs.blob`, but v6 does not reference it. `{}` and operational caller fields are schema-valid blobs. Data therefore has no authoritative blob shape enforcing blob ID equals digest, immutable bytes, length, base64 encoding or content. This is a direct BLOCKER for historical replay.

DIRECTORY permits member kind OTHER while requiring an `artifact_id`, but the artifact union has no OTHER variant. Because v6 also requires every ID resolve exactly once, a non-file member cannot be represented without dangling or mis-typed reference. This matters for malformed directory entries encountered before frozen parsing fails and is HIGH.

The source manifest closes lists of source artifacts, inventories and absences and binds canonical input/source-set digests. It does not define the canonical source-set digest formula. More seriously, the missing project/STOP/dependency/capability fields and missing Git-observation record mean completeness cannot be verified by comparing the manifest with the canonical bundle. Data would have to define implicit source-class rules.

## 14. Complete handoff and inventory closure

The intended inventory rule covers frozen `_current_handoff` enumeration, including unrelated, malformed, newer and conflicting handoffs, and the denial-context scans of docs, handoffs, STOPs, assignments, bindings, tasks, completions and capabilities. Version-head directory enumeration for tasks/assignments and recursive dependency/completion/capability reads must also be retained. V6’s directory/source structures can encode these once the missing canonical references, blob records and OTHER representation are fixed.

## 15–19. Raw/normalized output, normalization, timestamp and base64

Raw and normalized objects now reject unknown fields and require exactly the frozen field names. V6 specifies `normalize(raw)` literally: copy the frozen six fields for DISPATCH; copy the five frozen DENY fields and set operation null. Exact decoded raw replay and recomputed normalization reject task, reason, decision ID, decision and operation mutations.

The schemas do not structurally condition DENY operation null or DISPATCH operation/task non-null, so those impossible pairs validate structurally. This is bounded because `semantic_verify_v3` explicitly rejects them and the acceptance matrix names both cases. The same applies to invalid base64 and length/digest mismatch: the matrix requires rejection and the content verifier has one deterministic strict-decoding implementation.

The timestamp regex permits impossible dates such as `2026-99-99T99:99:99Z`. V6 requires UTC evaluation time; strict RFC3339 calendar parsing should be made explicit in acceptance tests. This is MEDIUM and implementation-bounded, not an architecture choice.

## 20–25. Engine distribution, replay environment and dependency manifests

V6 says replay distribution is immutable, but `m0-2-decision-evidence-envelope.v6.schema.json` has no `engine_distribution` field or reference. The “current” engine schema is still v1 from the rejected v5 package: it accepts empty Python/package versions and artifact IDs, absolute mutable working/module paths and arbitrary environment strings. External distributions contain only name/version, with no retained package artifact/digest or immutable environment snapshot. Data cannot attach or reconstruct the distribution v6 requires.

The import and validation schemas are closed lists, but local module/external distribution/schema IDs are not mapped to artifact IDs. Manifest digests, inventory digests, absence assertions and source-set digests have no normative canonical calculation formula. `import_manifest_id`/`validation_manifest_id` in engine v1 are disconnected because the engine record is absent from the envelope. The validation manifest identifies validator/canonicalizer, but recursive schema IDs likewise have no immutable artifact mapping.

The prose names a dependency-closure traversal from `edgelab.orchestration.decision` through static imports and `validate_record` schema reads. That is the right boundary, but without module→artifact, schema→artifact and distribution→immutable-package mappings Data cannot prove closure or materialize it. An undeclared dependency is said to invalidate replay, yet the accepted manifest cannot establish the declared byte closure.

## 26–31. Clock/Git replay, historical/currentness, results and reasons

The clock target and pre-invocation installation are exact and preserve repeated UTC reads without changing frozen source. The Git shim boundary remains the actual `_remote` and `_is_ancestor_of_remote_main` subprocess calls. The missing Git-observation record prevents supplying either call from v6 evidence.

Historical verification therefore cannot currently run from persisted evidence: source blobs, Git observations and the engine distribution are absent or untyped. Currentness categories and generation comparisons are otherwise complete in prose and remain separate from historical validity.

Verification-result v2 rejects every tested unsafe ALLOW combination: INVALID, STALE, wrong runtime, verifier FAIL, generation mismatch and UNKNOWN. Wrong-runtime history remains historically valid while authorization denies. Contradictory DENY reason/status pairs remain structurally accepted, but the v6 acceptance matrix explicitly requires contradictory reasons to reject, making this a bounded semantic-verifier MEDIUM.

V6 no longer defines the envelope self-digest algorithm after superseding v5 and all earlier plans. The schema requires `envelope_sha256`, but no authoritative text states the canonical bytes or exclusion rule. Data must not infer the former v5 rule from superseded evidence. This is a BLOCKER for envelope identity and event binding.

## 32–35. Scheduler prerequisites, evidence operations, idempotency and matrix

V9 explicitly restores the original actor fixture, immutable B0 block, matching already-closed claim ID/fence, exact generation vector and idempotency key. All four operations are B0-only event acknowledgements with no tuple, claim, fence, scheduler, dispatch, retry, completion, success or operational effect. SAFE_YIELD acknowledges a claim already closed by governance; REPORT_FAILURE never creates F0.

The idempotency rule binds block, operation, actor, payload and optional envelope digest. Same key/payload returns the committed event; conflicting reuse denies. Once/block and once/block/evidence-digest rules preserve deterministic uniqueness. These rules are implementation-ready.

The acceptance matrix now consolidates artifact/blob, source, identity/generation, Git, output/base64, engine/environment, result/reason, scheduler prerequisite, idempotency, B0 immutability, Stage 1 equivalence and historical-versus-current Git attacks. Each case is objective after the missing evidence/distribution/digest contracts are supplied.

## 39–42. Findings, revisions and readiness

Four BLOCKERs remain:

1. **Required authority inputs are absent.** Project/STOP/dependency/capability evidence promised by v6 is missing, and `git_observation_id` has no resolvable typed record.
2. **The retained blob model is not applied.** `blobs` accepts arbitrary objects, so FILE bytes cannot be objectively resolved or verified.
3. **The engine distribution is absent and the referenced current schema remains non-immutable.** No exact third-party/local/environment replay closure can be stored.
4. **Envelope identity is undefined.** V6 supersedes the v5 self-digest rule but provides no `envelope_sha256` calculation.

Three HIGH ambiguities remain:

1. OTHER directory members require artifact IDs but have no corresponding artifact variant.
2. Source/import/validation manifests do not map decision-critical names to immutable artifacts, and their digest/canonicalization formulas are unspecified.
3. Canonical source completeness cannot be checked without explicit project/STOP/dependency/capability/Git bindings rather than inferred source classes.

MEDIUM findings are semantic-only DENY/DISPATCH conditionals, strict timestamp/calendar parsing, strict base64/content checks and result reason/status consistency. All have explicit outcomes or matrix cases and do not independently require architecture. No LOW finding was separated.

Required revision is narrow and mechanical: add the missing canonical artifact references and a closed Git-observation record; point `blobs` to the existing closed blob definition; add a corrected immutable engine-distribution record to the envelope; map module/schema/distribution names to artifact/package IDs; define every manifest/inventory/assertion/self-digest formula; and give OTHER members a resolvable representation or remove their artifact reference. Preserve v9, result safety, the generation model and acceptance matrix.

Data cannot implement v6/v9 without security-critical evidence/replay invention. H-M0-041.v14 remains blocked and Data is not released.
