# M0.2 → M0.3A decision-evidence adapter planning review v5

**Verdict: `M0_2_M0_3_ADAPTER_PLAN_REQUIRES_REVISION`.** V5 closes the Git discriminator, self-digest, safe-ALLOW conjunction, and conceptual historical/currentness separation. V8 keeps evidence-only operations non-operational. The package is still not implementation-ready because its schema does not encode the closed evidence model described by the prose: canonical decision inputs contain arbitrary objects and omit declared fields, artifacts are unrestricted objects, and raw/normalized outputs are open. The engine schema also lacks immutable third-party distribution evidence and a defined dependency-manifest format. Data would have to design security-critical record shapes and replay closure.

## 3. Canonical-input closure

The prose names the right categories, but the schema does not mechanically contain them. `intent`, `writer_claim`, and `repository_identity` are unrestricted objects. Assignment and handoff heads are untyped strings. Project, STOP, dependency, and capability evidence are only arbitrary artifact IDs whose target artifact has no defined schema. `expected_operation`, named by the contract, is absent. Runtime, attachment, repository, runtime, scheduler, dispatch, and fence generations are declared part of `canonical_input_bundle` but exist only in the separate top-level `runtime_binding`; therefore `canonical_input_sha256` does not bind them as stated. There is no typed dependency graph/head/completion or capability requirement/resolution structure. A schema-valid bundle with empty intent, claim, identities, heads, references, inventories, runtime IDs, and timestamp `"Z"` exists.

## 4–5. Git observations and runtime/repository bindings

Historical Git observations are improved and closed: HEAD and origin/main use correctly discriminated Git object IDs, plus origin URL, reachability and repository identity. A 40-hex Stage 1 SHA-1 accepts; cross-labeled 40/64-hex identities reject. Historical replay is directed to use only this record.

Top-level runtime binding includes runtime ID, attachment ID, repository/runtime/scheduler/dispatch generations and task fence. Task/attempt are in the input. Claim generation is only inside unrestricted `writer_claim`; assignment/handoff generations are not typed. The canonical bundle’s `repository_identity` is an object while Git observations’ field is a string, leaving the required duplicated-identity equality undefined. These defects prevent mechanical currentness binding.

## 6–7. Verification-result safety and reason codes

The v2 result schema correctly makes ALLOW require the full conjunction: historical VALID, CURRENT, compatible target runtime, verifier PASS, exact generations and reason NONE. INVALID, STALE, wrong-runtime, verifier FAIL, generation mismatch, and unknown-currentness ALLOW attacks all reject. Wrong runtime can remain historically valid while authorizing use denies.

Reason values are closed and explanations are bounded/non-authoritative. Denial consistency is incomplete: INVALID/FAIL may carry reason NONE, and STALE/generation mismatch may carry WRONG_RUNTIME. These are fail-safe but weaken audit accuracy and are MEDIUM.

## 8–9. Self-digest and digest typing

The self-digest rule is exact: `SHA256(CJ(envelope excluding only envelope_sha256))`, lowercase 64-hex, recomputed by semantic verification. Mutation of any included field changes it.

Git object identity is cleanly separated from SHA-256 evidence digests. Other authority identities are not: assignment/handoff heads are generic strings, blob IDs have no published shape, and repository identity has conflicting object/string representations. The successor must type each as a logical ID, Git object, content digest, or versioned record reference.

## 10–11. Artifact schemas and cross-reference verification

The prose defines useful FILE, ABSENT and DIRECTORY forms and an exhaustive cross-reference checklist. The schema implements none of those forms: `artifacts.items` is merely `{type:"object"}`. It accepts `{}`, caller verification flags, capital operations, or any arbitrary record. No field is required for kind, ID, retained blob, source, path, length, digest, absence inventory/context, directory root, selection rule, member type, ordering, or inventory digest. Consequently no objective cross-object verifier can be implemented from the authoritative schema without Data inventing all artifact and blob-store representations.

The prose’s semantic checks cannot repair absent data definitions. Exact reference resolution, uniqueness, containment, lexical ordering, raw/canonical digest comparison, absence contradiction and retained bytes need closed versioned schemas and explicit canonicalization rules.

## 12–13. Engine distribution and dependency closure

The engine schema identifies Python, distributions, local artifact IDs, launcher, clock/Git shims, import/validation manifests, working directory, module path and environment allowlist. It remains open in security-critical substance. Python and dependency name/version may be empty; artifact IDs may be empty; environment entries are arbitrary strings, including a mutable current-checkout `PYTHONPATH`; and the clock target is absent despite the prose claiming the schema binds it. External dependencies have only name/version, with no immutable package artifact or digest, so restored replay is not self-contained.

The “accepted static import allowlist plus traced validation schema reads” is not published as an algorithm or typed manifest. `import_manifest_id` and `validation_manifest_id` point into the arbitrary artifact array. Data cannot objectively prove that every frozen local import/schema is present or decide what an undeclared dependency means without designing the manifest format and closure procedure.

## 14–16. Raw output, normalized output, and subject reconciliation

The raw-output prose is correct: exact unnormalized mapping, canonical UTF-8 JSON, strict base64, byte length, SHA-256, bool/int distinction, float rejection and null preservation. Its schema leaves `mapping` unrestricted and permits empty/non-base64 transport. Normalized output is wholly unrestricted. A schema-valid record can claim raw DENY with LIVE capital operation and normalized DISPATCH with caller `verified:true`. Exact replay should reject these, but no closed raw/normalized schemas or precise deterministic normalization contract exists in v5. This is a regression from v4’s structural decision forms.

Subject reconciliation is sound in prose: output supplies only task where present, while attempt and heads come from input/source evidence. It becomes mechanical only after the canonical input and referenced assignment/handoff records are closed and typed.

## 17–20. Clock, Git, historical verification, and currentness

The clock patch target, pre-invocation installation, isolated module and historical/current-time separation are clear in prose and preserve frozen source. The Git shim is limited to the two actual frozen observations and current Git is excluded from historical replay.

The intended historical algorithm is correct, but it cannot execute entirely from authoritative preserved evidence while artifacts, blobs, canonical subrecords, dependency manifests, distribution packages, raw outputs and normalization remain undefined/open. Currentness correctly follows historical verification and names task/attempt, assignment/handoff/claim, project, STOPs, dependencies, capabilities, inventories, Git and generations. The open input identities and untyped current references prevent a direct implementation. Wrong-runtime semantics themselves are correct and fail closed.

## 28–31. Findings, revisions, and readiness

Three BLOCKERs remain:

1. **The authority schema is not closed.** Canonical input subrecords, artifacts, raw mapping and normalized output accept arbitrary structures, while required expected-operation and generation/input evidence is absent or outside the declared bundle.
2. **Artifact/blob and cross-reference representations are undefined.** No schema-valid FILE, ABSENT, DIRECTORY, retained blob or manifest structure exists from which Data can implement the required verifier.
3. **Frozen engine/replay closure is not immutable or mechanically derivable.** External distributions lack retained artifacts; import/validation manifests and closure algorithms are undefined; environment values permit mutable fallback.

Three HIGH ambiguities remain:

1. Runtime/repository/assignment/handoff/claim identities and generations are incompletely typed and canonical repository identity has incompatible object/string forms.
2. V8 drops v7’s actor, closed-claim/fence and idempotency prerequisites after superseding it.
3. The raw/normalized decision shapes and full implementation acceptance matrix are no longer structurally or procedurally specified.

MEDIUM findings are denial reason/status inconsistency, weak UTC syntax (`"Z"` validates), and missing uniqueness/non-empty constraints on identifiers and lists. No separate LOW finding was found.

Required revision: publish closed schemas for canonical intent/claim/repository/assignment/handoff/dependency/capability evidence; put every declared generation into the canonical bundle or explicitly redefine its binding; define FILE/ABSENT/DIRECTORY/blob/manifests; close raw and normalized decision forms; retain immutable third-party distribution artifacts and exact environment key/value bindings; publish the dependency-closure algorithm; restore evidence-only actor/claim/fence/idempotency rules; and enumerate the implementation acceptance matrix.
