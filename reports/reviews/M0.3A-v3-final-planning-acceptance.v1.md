## Acyclic sealing and checkout attachment

The three-phase construction is acyclic and implementation-grade. Phase A hashes immutable attachment-core bytes with no runtime/genesis digest. Phase B binds that digest in immutable genesis and hashes genesis. Phase C stores a separate immutable seal over both prior digests. Startup recomputes in that order and denies missing/mismatched attachment, database, repository, checkout, freeze or seal. A copied DB cannot silently attach to another ordinary checkout because the owner-only attachment binds real path, common-dir identity, remote, repository marker and nonce. Coordinated hostile copying of DB, attachment, checkout and every local anchor remains explicitly outside local proof.

## SQLite, serialization, backup and export

V3 is self-contained: runtime directory `0700`; database/WAL/SHM/attachment/lock/backup/export files `0600`; per-connection `foreign_keys=ON`, `busy_timeout=5000`, verified WAL and `synchronous=FULL`; short `BEGIN IMMEDIATE` writers; exclusive migrations; coherent read snapshots; startup/export integrity, foreign-key, replay, permission and effective-PRAGMA checks; and fail-closed corruption with no destructive repair. No older planning document is needed to determine these requirements.

All operations use the same lock order: cooperative OS advisory lock, then SQLite, then SQLite release before advisory-lock release. Normal transitions, initialization, migration, backup and export state their transaction/read-snapshot boundaries. Process death releases the OS lock; elapsed time or stale text grants nothing. A new holder must own the correct runtime/attachment lock, verify liveness evidence and record `LOCK_RECOVERED`. A noncooperative malicious process remains outside the local threat model.

Backups use the SQLite backup API into an owner-only temporary target, verify integrity, foreign keys and digest, then rename atomically. Raw main-file copies in WAL mode are forbidden. The backup event binds the starting logical generation/heads and verified artifact. Export retains the common lock, verifies replay, opens one read snapshot, binds the exact Git bundle/repository generation/runtime/global and task heads/materialized state, canonicalizes non-secret output and hashes it before release. Attachment nonce, credentials, WAL/SHM and database bytes are excluded.

Migration evidence is stable and sufficient: from/to versions, artifact digest, backup reference/digest, timestamps, result, pre/post runtime/global heads and migration digest. Successful schema, ledger and runtime event changes commit together. Failure cannot emit success; it either proves the prior schema usable or leaves the runtime unavailable. Downgrades and unknown newer versions deny.

The complete tuple domains, valid aliases and closed matrix are coherent. N7→N8 changes workflow while leaving review `APPROVED`; terminal attempts/tasks do not resurrect. Every unlisted tuple/operation denies. Retry creates a new attempt, remediation a linked task and continuation remains the same attempt.

## Events, repository generation and replay

Task and runtime events have distinct shapes with one contiguous global chain. Runtime events need no fake task identity. Task chains have independent sequences and predecessors. Logical sequences are transactionally allocated and independent of row IDs.

Cross-task remediation now commits two deterministic task events with consecutive global sequences, separate per-task sequence advances, one relationship ID, reciprocal links, child N0 state, source successor state and one idempotency result. Both task heads and all materializations commit or roll back together and replay verifies both sides.

Repository generation is runtime-global, canonical and advances exactly once per authoritative scheduling-bundle change. Irrelevant ignored/untracked noise and byte-identical changes do not advance it. Runtime events bind old/new generation, full bundle digest and affected tasks; affected tuples update atomically. READY imports invalidate old receipts; CLAIMED/IN_PROGRESS fence to B0; review states move to B1 and revoke assignment. Stale generation, receipt or assignment denies.

Replay derives and compares every mutable fact required by the contract: tuples, attempts, claims/fences, assignments, generations/counters, receipt/bindings, lineage, evidence, idempotency responses, seals, migrations, snapshots and all heads. Any extra, missing, malformed, reordered, substituted or irreconcilable data fails closed.
