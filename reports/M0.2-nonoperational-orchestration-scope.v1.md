# M0.2 non-operational orchestration sandbox scope

**Disposition: LIMITED_ENGINEERING_ALLOWED.** `STOP-M0-001` remains OPEN and M0 remains blocked. The STOP affects M0 exit/control approval, scientific confirmation eligibility, strategy promotion/paper authorization, STOP clearance/dependent evidence reuse, and independent approval/audit acceptance. It does not explicitly prohibit unrelated repository engineering. The remediation plan permits coordination and synthetic tests. This scope therefore permits only test-only orchestration safety infrastructure; it does not begin M1 operations.

## Allowed scope

Only offline, synthetic implementations for repository identity preflight, handoff parsing, task/queue schemas, dependency and claim coordination, completion/review/release routing, stale-assignment detection, STOP/M0-blocked dispatch checks, audit logging, model/usage metadata routing, and a Skill/Plugin Registry schema/review model. Public documentation research about tools may occur only as non-executing infrastructure due diligence: no installation, activation, credentials, external repository clone, or sports/source discovery.

## Required dispatch invariant

Every task must have a typed action classification. With phase `M0`, status `BLOCKED_FOR_APPROVAL_REMEDIATION_ALLOWED`, an OPEN STOP, locked capital or engaged kill switch, the scheduler must deny by default and allow only this exact allowlist: `ORCHESTRATION_SCHEMA`, `HANDOFF_PARSING`, `REPOSITORY_PREFLIGHT`, `CLAIM_COORDINATION`, `COMPLETION_ROUTING`, `RELEASE_ROUTING`, `STOP_SCHEDULER_CHECK`, `AUDIT_LOGGING`, `SYNTHETIC_TEST`, `PLUGIN_REGISTRY_SCHEMA`, and `PLUGIN_REVIEW_METADATA`.

It must reject unknown classifications and `SCOUT_DISCOVERY`, `EXTERNAL_INGESTION`, `RESEARCH_CAMPAIGN`, `QUANT_REAL_EXPERIMENT`, `PAPER_PORTFOLIO`, `LIVE_EXECUTION`, `CAPITAL_MUTATION`, `NETWORK_EXECUTION_ADAPTER`, and `PLUGIN_INSTALL`. Synthetic tasks must use only repository fixtures or generated static inputs. The scheduler must have no network execution adapters or capability to mutate bankroll, risk policy, STOP state, venue/account state, or execute plugins. It must re-read the authoritative STOP and project-state records before each dispatch and fail closed if absent, unreadable, stale, or inconsistent.

## Boundaries

Current handoffs and the Git protocol provide a non-clearance scheduling mechanism for coordination; they do not yet provide a machine-enforced task classifier or dispatcher. Creating that enforcement is the bounded M0.2 work. The external authority provisioning plan continues independently and remains required for STOP resolution. M0 approval, M1 operational release, Scout activation, real Data ingestion, real Research/Quant work, paper activity, live/capital activity, and third-party capability activation remain prohibited.
